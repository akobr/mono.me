# Review of PR #135: [Machine credentials and conditional reads in the OpenAPI document, one STORYTELLER_* contract](https://github.com/akobr/mono.me/pull/135)

Reviewer: Harry · Review date: 2026-10-26

**Verdict: needs discussion.** The code is solid and well tested; nothing blocking was found in it.

**CI:** "Build and Deploy Job" failed, but not because of this PR — Azure Static Web Apps refused the deploy because the app already has the maximum number of staging environments, so an old preview environment needs deleting. "Lint, type-check, test, build" was still running at review time.

**Merge order is the one gate.** #131 and #132 both touch `open.api.v0.9.54.json`, so whichever merges second has to regenerate the SDKs and classify its new operations in `OperationAccess`.

## Important

1. NSwag added a required positional `string if_None_Match` to `GetConfigurationAsync`, `GetResolvedConfigurationAsync` and `GetConfigurationCompositionAsync`, which breaks every generated C# caller. Turn on optional parameters or keep the header out of the generated signature, and at least note the break in the 0.10 release notes.
2. Each bound credential creates a `TokenEndpointClient` that is never disposed. `CachedTokenCredential` makes a new one on every `Bind` and `WithPrimaryHandler`, and `MachineAuthenticationService.Bind` replaces `_bound` without cleanup. Short-lived CLIs don't care, but a long-running host that binds per tenant will leak handlers. Share one client per handler config, or make the credential `IAsyncDisposable`.
3. An invalid `STORYTELLER_KEY` now breaks every sform machine command, even when `-p` or `STORYTELLER_PROJECT` sets the target. `MachineSignInSettings.GetKind` should throw only when the key actually picks the target.
4. `STORYTELLER_TOKEN_FILE` now means a federated platform token when `STORYTELLER_CLIENT_ID` is set, where it used to be an error. A leftover client id would quietly turn a bearer token file into a token exchange. Put that in the migration notes, along with the exit code change from 3 to 44 and the new retries.

## Nits

- Copy `_target` into a local in `RenewAccessTokenAsync` and `GetAccessToken`, which each read it twice.
- `Load()` returns `new LoadedCredential(null!, null!, null!, exception)` on failure, which is awkward to dispose.
- `CredentialFailures.Guard` treats every `ArgumentException` as a config error, which can hide real bugs.
- `MtlsSecuritySchemeDocumentFilter` hardcodes `"X-ARR-ClientCert"` again.
- `ReadFederated` falls back to `SUBJECT_TOKEN_FILE` even for the GitHub Actions source.
- The GUID client id rule for GitHub Actions federation (about line 118) is safe only because other client ids need `TOKEN_URL`. Comment it and pin it with a test.
- `StorytellerVariableReader` is now public and allocates a wrapper on every `SetNames` read. Consider keeping it internal.

## Good

About 700 lines of duplicated token and GitHub code left sform for the SDK, secrets stay internal, the audience matches the server's comparison byte for byte, and `OperationAccess_MatchesTheTablesOfTheTests` will fail if a new operation isn't classified.
