## Why the fix is right

`ConfigurationReads.WriteFile` (`src/Platform/Cli/src/Commands/Configuration/ConfigurationReads.cs:170-190`) writes a resolved export on Unix through `OwnerOnlyFile.WriteAllText` (`src/Platform/Cli/src/Output/OwnerOnlyFile.cs:18-43`): a new 0600 temp file next to the target, then `File.Move(temp, target, overwrite: true)`. The real file system refuses to move a file over a folder, but `MockFileSystem` replaces the folder, so the old "folder at the path" setup never failed on Unix. A missing parent folder makes `FileStream.New` of the temp file throw `DirectoryNotFoundException` in the mock on both platforms, before the move, so the test now exercises the `catch` in `WriteFile` everywhere. That matches the technique in the GITHUB_ENV test right above it (`ConfigExportCommandTests.cs:383-404`). The real-filesystem behaviour for a folder at the path stays covered by `OwnerOnlyFileTests`.
