# Review of PR #162: [📝 docs(platform): register the admin UI's Sign-out URI in WorkOS and name it when a sign-out fails (424-165)](https://github.com/akobr/mono.me/pull/162)

Reviewer: Harry · Review date: 2026-11-03

**Verdict: approve-ready.** This is mostly docs plus a small test-side helper; the real fix is a WorkOS Staging setting that the PR correctly leaves to the owner. The diagnosis is right: `session.signOut()` passes an absolute `<origin>/login` as `returnTo`, authkit-js navigates to the WorkOS logout, and WorkOS only honours `return_to` for a registered Sign-out URI, falling back to the default one and then to `app-homepage-url-not-found`. Keeping the navigating logout instead of `navigate: false` + `location.assign` is the right call (an opaque `no-cors` logout would hide whether the session was really revoked). The new code is small, defensive and well commented.

**CI at review time:** "Lint, type-check, test, build" and CodeRabbit were still in progress on `5dc6f240`, with no review comments yet. I read the change in context (`App.cs` helpers, `SignInTests`, `MyInvitationTests`, `app/boot/auth.ts`, the vitest config) but did not run the tests myself; the PR reports `npm test` (1482), lint, typecheck, `dotnet build` and the mock-profile runs as passing.

## Nits

- `src/Platform/UI.Admin.AutomationTests/src/Pages/App.cs` (`ClickSignOutAsync`, ~L305-319): case 12 used to wait with `ExpectAtAsync(Routes.Login())`, which also accepts `/login/`; `LoginPath()` does not. Harmless today (the app routes to `/login`), but worth knowing the expectation got slightly stricter, not "unchanged" as the PR says.
- Same method: the catch fires whenever the page is off the app's origin when the timeout hits, including a slow redirect still sitting on `api.workos.com`. The message then asserts a missing Sign-out URI. Since it includes the actual URL that is fine, but "…ended on `<url>`; this usually means…" would be more honest than stating the cause outright.
- Same method: the origin regex is built from `Regex.Escape(origin)` and sent to Playwright as a JavaScript regex. I checked the characters an origin can contain (`.`, `:`, `/`, digits, `[`/`]` for IPv6) and the escaped form is valid and equivalent in JS, so no issue; a one-line comment saying so would save the next reader the check.
- `src/Platform/ui.admin/src/test/unit/boot/auth.test.ts` (L31-35): the test seeds the private cache key `2s-admin:auth-configuration:<apiBaseUrl>` by hand, so a rename in `auth.ts` silently turns it into a network call. Export the key builder (or a test seam) from `auth.ts`, and clear `sessionStorage` in `beforeEach` so the cases don't depend on order.
- Same file (L50-56): the devMode case relies on happy-dom's default URL being `localhost`. Assert `location.hostname` first or pin `environmentOptions.happyDOM.url`, so a config change fails with a clear reason. A companion case for a non-localhost host (`devMode: false`, `apiHostname` set) would round out the coverage, but that is beyond this PR.
- `src/Platform/ui.admin/README.md` checklist: "Initiate login URI" lists only `https://<admin-host>/login`; say whether Staging needs `http://localhost:5173/login` there too, like the other bullets now do.
- `docs/Platform/UI.Admin.AutomationTests/automation-tests.md` L115: the checklist bullet now packs four facts into one line; splitting the "without it…" part into its own sentence or sub-bullet would read better.
- PR title type: the change includes test code (`App.cs`, `SignInTests.cs`, `auth.test.ts`), so `test(platform)` or `fix(platform)` would describe it a bit better than `docs`. Purely cosmetic.

## Good

- The investigation is excellent: the WorkOS settings were read (read-only) to confirm the cause, and the spec records why each in-app workaround was rejected.
- The unit test was mutation-checked (switching to `navigate: false` makes it fail), and the forced off-origin sign-outs (`about:blank`, another origin's `/login`) show the new message actually fires.
- `ClickSignOutAsync` keeps Playwright's assertion as the inner exception and only replaces the message when the browser really left the app's origin; a failure on the app's own origin keeps Playwright's message.
- Docs are consistent across the four places that mention WorkOS setup, the relative links resolve, and the troubleshooting rows match the new error text.
