# Review of PR #173: [✨ feat(platform): add sform story edit to edit an annotation in your editor (424-217)](https://github.com/akobr/mono.me/pull/173)

Reviewer: Harry · Review date: 2026-11-08

**Verdict: approve-ready.** The PR changes 20 files (+3,164/−34) in 3 commits and is not a draft. It adds `sform story edit <key>` (`StorytellerEditCommand`), an edit document model (`AnnotationEditDocument`) with client-side validation and normalization, a `check` hook on the shared `IEditorService.EditJsonAsync`, and a stricter JSON reader for every editor command. The command flow is careful: it reads, optionally restores deleted keys, re-reads right before the write to catch concurrent changes, and keeps the user's edit in a file on every failure after the editor closes. Tests are extensive (about 1,900 lines across command, body, model and editor tests, with a scripted editor). I found nothing blocking. The points below are refinements.

## Important

1. **The shared editor now rejects duplicate properties case-sensitively, but configurations are case-insensitive.** `EditorService.ParseDocument` (`src/Platform/Cli/src/Services/EditorService.cs:265-276`) uses `DuplicatePropertyNameHandling.Error`, which only catches an exact repeat. In `config edit` / `config patch`, a document with both `"Logging"` and `"logging"` still passes and reaches the API, while the PR description presents duplicate properties as now handled for every edit command. The annotation document is fine, because `AnnotationEditDocument.Read` matches members with `OrdinalIgnoreCase` and reports the twin. Suggested fix: give configuration callers a `check` that walks the objects with `StringComparer.OrdinalIgnoreCase` and returns "The member 'x' is in the document twice." That is the same message and re-open loop you already have. Alternatively, narrow the description to exact duplicates. This is the same casing gap I raised on [#172](https://github.com/akobr/mono.me/pull/172).

2. **The behavior change for `config edit`, `config patch`, `template edit` and `schema … edit` needs its own regression test per caller.** Switching to `DateParseHandling.None` is correct and matches `ApiSdk.partial.cs`. Still, it only compares equal if every caller's `original` was also read without date parsing. `TemplateEditCommand` and `ConfigEditCommand` pass the SDK's content, and `SchemaOperations.ToJObject` converts `current.Content`. If any of those paths goes through `JToken.FromObject` on a value the SDK typed as `DateTime`, an untouched document would now show a spurious diff. Suggested fix: add one "open and save without edits gives WARNING_NO_WORK_NEEDED" test for each of the four commands, with a date-like string in the content.

## Nits

- **`original` is not normalized, but `edited` is** (`AnnotationEditDocument.Create`, line 66, versus `Normalize`, line 321). Labels are de-duplicated only on the edited side, so an annotation stored with a repeated label shows a diff and asks to save even when nothing was touched. Normalizing in `Create`, or comparing `Normalize(original)`, makes "No changes detected" exact. `HasChangedAsync` is unaffected, because it compares `Create` with `Create`.
- **`TryReadDate` accepts a `JTokenType.Date` without an offset** (line 284). A `DateTime` of kind `Unspecified` or `Local` gets this machine's offset, which is the case the string branch refuses on purpose. The editor never produces that token type, but `Validate` and `Normalize` are public. Refuse a `DateTime` whose `Kind` is not `Utc`, or document the exception.
- **Date parsing allocates a `JsonDocument` per date** (serialize the string, then parse). It is harmless at this scale, but `Utf8JsonReader` over the UTF-8 bytes of the quoted string, or a small cached helper, avoids it.
- **`AnnotationKeyCasing.WithLowerCaseTypeCode` duplicates the private copy in `StorytellerSetCommand`** (line 265). Pointing `set` at the extension now is a one-line change and avoids two copies drifting until 424-210.
- **Production methods made `virtual` for tests** (`OpenFileInEditorAsync`, line 93, and `ShowChanges`, line 301). This works with `ScriptedEditor`, but a small injected process-launcher seam would keep test hooks out of the public surface of `EditorService`.
- **`KeepEdit` leaves the edit in the shared temp folder** (`StorytellerEditCommand.cs:322`). That is intentional and the path is printed. Annotation `Values` may hold internal data, though, so consider mentioning in the docs that the file is not cleaned up.
- **`TimeZone` is not checked client-side.** The server still validates it, so a bad zone only shows up as a 400 after the editor has closed (the edit is kept). If `AnnotationRules` checks it against IANA or Windows ids, the same check in `CheckRules` would let the editor re-open instead.

## Good

- The concurrency guard (`HasChangedAsync`, line 244) compares documents in the same normalized shape, covers "appeared" and "went away", and runs before the restore, so a lost race changes nothing. The remaining check-then-write window is acknowledged and tracked as 424-210.
- Restore happens only on save, with `Descendants = false`, and partial restores are reported with an accurate message about what kept its old content.
- Every exit after the editor goes through `KeepEdit` (including 401 and network errors, which are rethrown after the file is written) and prints a working `sform story set … --replace` command.
- `CreateTempFilePath` now keeps only ASCII letters, digits, `.`, `-` and `_`, which closes the `%…%` expansion and quoting problem on `cmd.exe`.
- Rejecting `undefined`, constructors, `NaN` and `Infinity`, and reading with `MetadataPropertyHandling.Ignore` so `$ref` and `$id` stay data, are good defensive choices that match how the API reads bodies.
- The interactive-console check fails fast with exit 43 and names the non-interactive alternative.
