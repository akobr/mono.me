## Blocking

1. **The PR doesn't merge: `StorytellerSetCommand.cs` conflicts with `main`.** GitHub reports the PR as `dirty`, and a trial merge conflicts in `src/Platform/Cli/src/Commands/Storyteller/StorytellerSetCommand.cs`. Since this branch was cut, `main` gained three commits to that file: `fb1c70e9` (merge `story set` into an existing annotation, with `--replace`), `e30d11a0` (an error line when the client can't write the body) and `0e270c62` (send `AnnotationKey` and the type-specific members). This PR rewrites the same error handling (it folds the 400/409/403 branches into `Console.WriteApiError`, see the hunk around the old lines 200-218) and the deleted-annotation prompt. Suggested fix: rebase onto `main`, keep `main`'s merge/`--replace` behaviour and its error line, and re-apply this PR's single `WriteApiError` mapping on top. Then re-check `StorytellerSetCommandTests` and the `story set` automation cases (and their `[Covers]` lists, so `CommandCoverageTests` knows about `--replace`) against the merged semantics. As it stands, the coverage test will probably fail after the rebase, because `--replace` is a new option with no case.

## Important

1. **`SFORM_<section>__<key>` now overrides any configuration value, including where tokens are sent.** `Startup.AddEnvironmentVariables` (`src/Platform/Cli/src/Startup.cs:117`) adds every `SFORM_`-prefixed variable last, in release builds too. So `SFORM_general__baseUrl`, and any auth setting under the same prefix, silently redirects an installed `sform`, and with it the user's bearer token, to another host. That's a reasonable feature for tests and CI, but it's a new trust boundary for the shipped tool: anything that can set the environment of a developer's shell or a CI step can now change where credentials go, with nothing shown to the user. Suggested fix: either allow-list the keys that may come from the environment (for example `general:baseUrl` only), or print a one-line notice on standard error when an environment variable overrides `general:baseUrl` or an authentication setting, the way `TokenStoreNotice` already does for `SFORM_TOKEN_STORE`. Either way, list the behaviour in the security notes of `docs/42for.net/cli/sform.md`.

2. **`run.log` is uploaded as an artifact, and GitHub doesn't mask secrets in files.** The Run step pipes the whole test output into `$results/run.log` with `tee` (`.github/workflows/cli-automation.yml:261`), and on failure the whole results folder is uploaded. GitHub's secret masking applies to the console log only, not to files written on the runner. The per-run `sform-<n>.txt` attachments go through `SecretScanner` and `AddSecret`, but `run.log` is whatever TUnit and the reporters print, for example an assertion message that quotes sform's stdout before a secret was registered, or a Playwright error. Suggested fix: run `run.log` through the same redaction before upload (or don't upload it, since the TRX and `results.jsonl` already hold the outcomes), and add a step that greps the results folder for the known secret values (they're in the environment of that step) and fails or deletes the file on a match.

3. **Disposable projects are never deleted, so every run leaves projects behind in the target organization.** `CliTest.CreateDisposableProjectAsync` (`src/Platform/Cli.AutomationTests/src/CliTest.Projects.cs:25`) creates `<org>.<generated name>` and, as the comments say, "the project stays in the organization", because sform has no project delete. Machines get a cleanup (`MachineCreation.DeleteAtCleanup`), projects don't. With [DisposableProject] cases in a routine CI run, the target org grows without bound, and it will eventually hit a project limit or make the pickers in the tests slower and the Sharprompt filter in `points create` ambiguous. Suggested fix: give the generated names a recognisable prefix with the run id and date, and add a cleanup (an API call or an admin script run at the start of the workflow) that removes projects with that prefix older than a day. At minimum, document the manual cleanup in `automation-tests.md` next to the CI setup.

4. **A network failure anywhere is reported as "the 2S platform could not be reached", pointing at the API address.** `Program.RunAsync` now catches every `HttpRequestException` and timeout (`src/Platform/Cli/src/Program.cs:234-242`) and prints the API base URL with advice to check it. The same exception type also comes from the other HTTP calls sform makes outside the SDK: the AuthKit and machine sign-in services and the auth discovery (`AuthKitAuthenticationService`, `MachineAuthenticationService`, `AuthenticationConfigurationResolver`) whenever they don't wrap the failure in `AuthenticationException`, and the extra request in `ConfigGetCommand`. Exit code 3 is right for all of them, but the message sends the user to the wrong place. Suggested fix: print the host of the failed request when it's known (`HttpRequestException` doesn't carry it, but the SDK's handler or a small `DelegatingHandler` can tag it in `exception.Data`), and only mention `general.baseUrl` when that host is the API's.

5. **The 229 case tests are unverified, and the workflow has no PR trigger, so nothing guards them yet.** This is stated honestly in the description, and the follow-ups (provision the AuthKit pool, create the `cli-automation` environment, three manual Testiny edits) are listed. I'd still recommend not treating `test-cases.md` or the Testiny `2SC` project as authoritative until one full run against `cli-tests/automation` passes, and adding the self, coverage and catalogue tests (84 of them, which need no target) to the regular PR build now. They're the part that protects the CLI's command surface from drifting, and right now no workflow runs them.

## Nits

1. `MachineRenewCommand.ReadCertificatePassword` uses `Console.Console.In.ReadLine()` (`src/Platform/Cli/src/Commands/MachineAccess/MachineRenewCommand.cs:158`), while everywhere else the code treats `Console.Console` as nullable (`Console.Console?.IsInputRedirected`). Use `Console.Console?.In ?? System.Console.In` or assert it once, to avoid an NRE in a host without a console.
2. `TokenStorage.HomeKey` hashes the directory string as given (`src/Platform/Cli/src/Authentication/TokenStorage.cs:24`). On Windows and default macOS, `C:\Work\Home` and `c:\work\home` are the same folder but get different Keychain and libsecret entries, so a session seems to disappear. Normalise the case on case-insensitive file systems before hashing.
3. `BrowserLauncher` supports `%s` in `BROWSER` entries but not the conventional `%%` escape for a literal percent sign (`src/Platform/Cli/src/Services/BrowserLauncher.cs:84`). It's rare, but worth a line in the comment if it's left out on purpose.
4. Removing `config set -c|-l` is a breaking change for scripts that passed them (they now fail as unknown options rather than doing nothing). It's documented in `sform.md`, which is good. Since the CLI version is `0.8-alpha` that's acceptable, but please mention it in the release notes of the next published `sform`.
5. The `ERROR_SERVICE_FAILURE` comment in `ExitCodes.cs` and `KeyValueConsoleExtensions.ExitCodeOf` describe the same mapping in two places, slightly differently worded. Keep the full rule in one place (the `ExitCodeOf` comment) and reference it from `ExitCodes`.
6. `SecretScanner` drops values shorter than 4 characters (`src/Platform/Cli.AutomationTests/src/Running/SecretScanner.cs:54`). That's sensible to avoid masking noise, but a short generated certificate password would then go out unmasked. Generated passwords are long today, so just note the assumption in the comment.

## Good to see

- The renewal fix is done properly on both sides: the API now returns the declared `CertificateRenewalResult` with error codes on refusals (`CertificatesHttp.cs`), the OpenAPI filter describes `byte[]` as base64 so Orval and Zod stop rejecting it, and the CLI still reads the old anonymous shape from an older deployment.
- One exit-code mapping (`ExitCodeOf`) used by both `WriteApiError` and `Program.Main` removes a whole class of "everything is exit 1" inconsistencies, and the generic `ApiException` handler logs only the status code, never the arguments.
- `InteractiveInputExtensions` is a clean, consistent answer to "never block on a prompt with redirected input", and every prompt names the option that answers it.
- `CliPaths` and `SFORM_HOME` remove the old reads of `Assembly.Location` and the user profile from several places, and an invalid `SFORM_HOME` fails before anything is read or written.
- The harness is careful: a from-scratch, allow-listed environment for each run, killing the whole process tree on timeout, awaiting the output pumps before disposing, and redacted per-run attachments.
- The workflow's secret handling is thoughtful: inputs only through `env:`, secrets only in the Run step, `--no-build` so no build target sees them, the `CI_*` copies unset before the tests start, and the trace zips deleted before upload. `queue: max` with `cancel-in-progress: false` is valid for a shared target.
- `CommandConstructionTests`, which builds every command through the real host, is exactly the test that would have caught the `TimeProvider` crash.
