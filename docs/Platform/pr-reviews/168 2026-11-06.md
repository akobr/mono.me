# Review of PR #168: [feat(platform): add a playground for Storyteller (424-205)](https://github.com/akobr/mono.me/pull/168)

Reviewer: Harry · Review date: 2026-11-06

**Verdict: approve-ready, with a few items worth fixing or tracking.** 43 files, +2167/-4: three small playground projects (`DotNet.SimpleConfiguration`, `DotNet.SimpleExecutor`, `DotNet.AspireHost`) under `src/Platform/Storyteller/Playground/`, two unit-test projects (8 and 27 tests), seed data for `sform story import`, a `playground.md` doc, one-line link fixes in four existing docs, a `CLAUDE.md` entry and the `42.mono.slnx` folder. ## Blocking

## Important

1. **Nothing in CI builds or tests the playground.** The PR touches no workflow, and the playground references `Hosting`, `Configuration`, `ConfigurationFormats` and `Aspire.Hosting` directly. A later change of a public API there (the types the renderer uses: `IExecutionContext`, `ISubscriptionCatalog`, `StorytellerConfigurationProvider.TryGet/GetChildKeys`, `StorytellerExecutionChange.Removal`) breaks the playground silently until somebody opens the solution. `DocumentKeys.cs` is the most exposed: it casts `IConfiguration` to `IConfigurationRoot` and walks `StorytellerConfigurationProvider` internals-by-convention. Suggested fix: add the two test projects (and a `dotnet build` of the AppHost) to `storyteller-conformance.yml` with a `src/Platform/Storyteller/Playground/**` path filter, or at least a build step; the tests use fakes, so they need no platform.

2. **`sform story set` fails for every key, and it is only mentioned in the PR text.** Found by the author while building the data: `ToSdkAnnotation` does not set `AnnotationKey`, which the SDK requires, so serialization throws. That is a shipped CLI command that cannot work. It deserves its own Linear issue (and a regression test) before the playground doc, which silently routes around it with `story import`, becomes the only place it is known. The same goes for the second finding, that Hosting cannot list a responsibility's units (`Responsibility.UnitNames`): the issue's "render units" is only partly met, so the acceptance criterion should be tracked as open.

3. **`--watch` never re-renders a unit document after the first time.** `ExecutorCommand.cs`, `WriteUnitAsync` guards with `_renderedUnits.Add(unit)` for the whole run. In a one-shot run this is right (several subjects share a unit), but the playground's stated purpose is to watch how a change on the platform reaches a process: an edit of `unt.playground.nightly-export.conf.json` while `simple-executor` runs is never shown, and neither is a unit that later gains a document. Suggested fix: when `Watch` is on, clear `_renderedUnits` at the start of each poll (the informer's `WatchExecutionsAsync` only yields changed executions, so also render the unit again when the execution that holds it changes), or compare the document version and render when it moved.

4. **Shutdown swallows real errors as success.** `ExecutorCommand.OnExecuteAsync`: `catch (Exception) when (stopping.IsCancellationRequested) { return Succeeded; }`. If a genuine failure (for example the platform answering 500, or a `NullReferenceException` in the renderer) coincides with Ctrl+C or a dashboard stop, it exits 0. Narrow it to `OperationCanceledException` (and `TaskCanceledException` is a subclass), and let everything else reach the host.

## Nits

1. **Print failures roll the document back.** `OptionsRenderer.cs`, `Render`: the comment correctly says it must not throw, because the provider counts a throwing change callback as a document that does not bind and rolls it back. `_output.WriteLine` can throw `IOException` when a redirected stdout is closed (the AppHost dashboard restarting the process, a pipe to `head`), and that would be reported as a bad document. A `try`/`catch (IOException)` around the body keeps the promise of the comment.

2. **`StopAsync` does not take `_lock`.** `OptionsRenderer.cs`: `_subscription?.Dispose()` can race with a `Render` in flight. `OnChange` registrations dispose safely, but taking the lock (or nulling `_subscription` inside it) makes the intent obvious and costs nothing.

3. **Only C0 controls are escaped.** `JsonConvert.ToString` escapes characters below U+0020 (and U+0085, U+2028, U+2029), but not the C1 range such as U+009B (CSI), which a few terminals still honour. The comment promises that "a C0 control character ... neither breaks the line nor reaches the terminal", which is accurate; if the playground is meant to be safe for hostile documents, also escape U+0080-U+009F. A low-priority hardening, since the doc already asks for a machine without `Secrets.Read`.

4. **`AppHost.cs` null-forgiving reads.** `playground["Responsibility"]!`, `Subject` and `Context` turn a missing key into a `NullReferenceException`-like failure deep inside the builder. `GetRequiredSection` already throws for the section; reading each key through `GetValue<string>` with an `ArgumentException` (or `playground.GetRequiredValue`-style helper) names the missing setting.

5. **`simple-executor` ends when who-am-I fails and nothing restarts it.** The doc says so ("Restart it from the dashboard"), which is honest; `WithExplicitStart` plus a `WaitFor` on the platform, or an Aspire `WithHttpHealthCheck` on the endpoint, would let the playground start in one step. Only worth it if first-run friction turns out to be real.

6. **The Aspire SDK version is repeated in the csproj.** `<Sdk Name="Aspire.AppHost.Sdk" Version="13.6.4" />` appears in three AppHosts now and again in `Directory.Packages.props`. Unavoidable today (SDK versions cannot come from central package management), but a comment pointing at the other two keeps them in step on the next bump.

7. **`ExecutionRenderer.Escape(object?)` boxes for strings.** Takes `object?` only to call `ToString()`; two overloads or a `string` parameter with the callers doing `.ToString()` is clearer. Cosmetic.

8. **Data file naming.** `uxe.*.json` seed files that contain `{}` (empty body) are valid but easy to mistake for an error; a one-line note in `playground.md` saying they only create the unit of execution would save a question.

## Good

- A very honest PR description: it says what was not run (`sform story import`, the machine creation, Linux, the full solution test) and what was found on the way, rather than hiding it.
- Escaping and rendering stay in a plain `TextWriter` renderer, so the output is testable without the toolkit console and the fake API; the 35 tests cover the renderer, the diff and the executor against fakes instead of a platform.
- `DocumentKeys` deliberately reads values from the provider, not from `IConfiguration`, so an environment variable cannot be printed through a document key; the comment explains why.
- Thought-through exit codes (`Succeeded`, `Failed`, `WrongInput`), a documented key-and-context validation, and logging sent to stderr so stdout holds only what the command renders.
- `playground.md` is clear about the secret risk (machine without `Secrets.Read`) and the port separation from the platform's own AppHost; `CLAUDE.md` and the existing Storyteller docs are kept in step as the repo guidelines require.
