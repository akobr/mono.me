# Review of PR #175: [424-220 sform: move the GitHub and masking export out of story config into story config export](https://github.com/akobr/mono.me/pull/175)

Reviewer: Harry · Review date: 2026-11-08

**Verdict: approve-ready.** The PR is not a draft. It changes 18 files (+2,124/−1,001) in 6 commits: a spec and its review, the split of the CI export out of `sform story config` into `sform story config export`, the GitHub Action and docs that call it, and two tests that pin the order of `GITHUB_ENV` and the file. The split matches the description. `story config` keeps the read job (`--resolved`, `--version`, `--format`, `--content-only`, `--export`, `--env-prefix`). The new command always reads the resolved configuration and always masks, with `--github-env`, `--mask`, `--prefix` (the renamed `--env-prefix`), `--allow-unprefixed`, `--allow-unresolved`, and `-e|--export` whose default format is `env`. Shared reads, formatting, file writes and failure messages live in `ConfigurationReads`. The guarantees of the old path are preserved and tested: every check runs before the first write; `::add-mask::` comes first; withheld secrets and reserved names are refused; a failed or skewed effective read masks every string and number; the summary goes to stderr and never holds a value. The removed options have no aliases and fail as unrecognized (exit `-1`). Nothing is blocking; the points below are a migration note and small docs nits.

None.

## Important

1. **An old `--mask -e <file>` without `--format` wrote JSON content; the new command writes `env`.** Under `story config`, `--mask` with `-e` and no `--format` used the JSON content (`--content-only` style). `ConfigExportCommand.Validate` now starts from `ConfigurationFormat.Env` (`ConfigExportCommand.cs:111`), and the docs say `env` is the default, which matches the action's `format` input. That is the right default for CI, but a caller who mechanically rewrites `sform story config <key> -r --mask bound -e outfile` to `sform story config export <key> --mask bound -e outfile` will get a `.env` file instead of JSON and may not notice until a later step fails. Suggested fix: one sentence in the export section of `docs/42for.net/cli/sform.md` (the `-f|--format` row, around line 202) that an `--export` file with no `--format` is now `env`, and that the JSON content the old `story config --mask -e` wrote needs `-f json`.

## Nits

- `docs/Platform/Storyteller/configuration-formats.md` (around line 67) describes `sform story config export <key> --github-env` without `--prefix` or `--allow-unprefixed`. That command line fails validation with exit 2. The examples in `sform.md` and `authentication.md` already pass `--prefix APP_`; this sentence should too.
- In `docs/42for.net/cli/github-action.md`, the paragraph after the first example says the workflow packed sform "in an earlier step `sform`". It reads as if `sform` were the step name. Something like "in an earlier step (`cli-version` and `cli-source`)" would match [Until sform is published](https://42for.net/cli/github-action#until-sform-is-published).
- When the resolved read succeeds and the effective read returns 404, the export stops with "The configuration for '{key}' has not been found." (`ConfigExportCommand.cs:255-258`). That is safe — nothing is written — but the wording is the same as a missing resolved configuration, which we just read. A line that the *effective* configuration was gone, so unresolved bindings could not be checked, would be clearer. The 401/403 path that lets `Program` report the refusal is consistent and tested.
- `docs/Platform/Cli.AutomationTests/test-cases.md` is not in the repository, as the PR says. The in-repo spec review already lists what `CFG-GHA-01` to `CFG-GHA-05` and `GEN-CLI-05` need (`config export`, `--prefix`, no `-r`). Worth applying when that file is committed; not a gap in this PR.

## Good

- The extraction is clean. `ConfigGetCommand` dropped from 643 lines to 241 and no longer depends on `GitHubActionsSettings`. What both commands share is in `ConfigurationReads` with the same messages and the same `OwnerOnlyFile` behaviour for resolved content on Unix.
- Write order is pinned, not only described: masks first (`FirstWriteProbe`), a `GITHUB_ENV` that cannot be written leaves no file, and a file that cannot be written is reported after `GITHUB_ENV` was appended. Refusals (withheld secrets, unresolved bindings, reserved names, U+0000, size limits, a document the format cannot write) all happen before any mask or file write.
- Security details survived the move: reserved runner/tool names, the open-last-line fix on `GITHUB_ENV`, no value on stderr (including workflow-command escaping of `#` in paths), multi-line masks, and an extra mask for the `properties`/`env`/`yaml` spelling of a value.
- The GitHub Action maps the old options onto the new ones (`--prefix` for `--env-prefix`, `--mask=` in the `--option=value` form, no `--resolved` or `--content-only`) and adds `allow-unresolved` defaulting to `false`. The PR's 360-combination check against a stub `sform` is the right way to prove the wrapper did not drift.
- Breaking changes fail closed: `RemovedExportOptions_DoNotParse` and `ProgramTests` cover `--github-env`, `--mask`, `--allow-unprefixed`, `--allow-unresolved` and `--prefix` on `story config`, and `--resolved`, `--content-only` and `--env-prefix` on `story config export`. `export` is matched as a subcommand before the key, which a test through `StorytellerListCommand` pins for both `config` and `configuration`.
- Docs were updated in the places people will copy from (`sform.md`, the action page and README, `authentication.md`, `CLAUDE.md`), including the caveat that `Program` still prints parse errors, sign-in failures, `401`/`403` and crashes to stdout. The internal review that caught the dropped caveat and the missing order tests earned its keep.
