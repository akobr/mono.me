# Review of PR #182: [refactor(platform): store all organizations in one shared Cosmos DB container (424-230)](https://github.com/akobr/mono.me/pull/182)

Reviewer: Harry · Review date: 2026-11-09

**Verdict: needs changes (small).** The refactor itself is careful and consistent: every point read, batch, ReadMany and single-partition query now goes through the full hierarchical key, and every organization-wide query I found carries both the `c.Organization = @organization` predicate and the prefix. Nothing I found leaks across organizations today. What's missing is a guard that keeps it that way, because the new isolation tests can't catch a forgotten predicate on the emulator, plus the new Cosmos workflow isn't wired into anything yet.

Scope I read: the full diff of `Backend.CosmosDb/src`, `DbCreator`, `Access.ApiKeys`, `Aspire.Host`, the new workflow and test helpers, the spec and the four phase reviews, and the surrounding code of every query that passes `QueryOptions()` / `Prefix`. CI: no checks had reported when I looked; CodeRabbit was still processing.

## Blocking

1. **Isolation rests on a hand-written predicate, and the tests can't detect when it's missing.**
   `OrganizationContainer.QueryOptions()` with no partition (`OrganizationContainer.cs:41`) and `Prefix` (`:32`) are used by about ten organization-wide queries, and each one writes `c.Organization = @organization` by hand (decision D3 in the spec). The spec itself notes that on all three emulators the prefix alone already keeps the other organization out. So the new `*IsolationTests` (two orgs with identical names) would stay green if someone drops the predicate from a future query, and the first place the leak shows up is Azure, where the prefix is routing only.
   *Fix:* make the safe path the only path. Options, cheapest first:
   - In `OrganizationContainer`, add a method for organization-wide queries (e.g. `OrganizationQuery(string text)` / `QueryAcrossPartitions(...)`) that throws if the text lacks `OrganizationParameter` in a `c.Organization =` predicate, and make `QueryOptions()` without a partition internal to it. LINQ call sites (`ConfigurationCacheInvalidator.CollectAsync`, `CosmosConfigurationSchemaService.QueryAffectedConfigurations`, `CosmosAnnotationService` around line 841) could go through a helper that applies `.Where(e => e.Organization == organization)` itself.
   - Or, at minimum, a test using `InterceptedRepositoryProvider` (or a recording `Container` decorator) that runs the organization-wide operations and asserts every query sent with the prefix key has the predicate and the parameter. An alternative is to run the isolation suites once with the queries routed without any partition key (full fan-out), which is exactly the case the prefix hides.

## Important

2. **`storyteller-cosmos.yml` gates nothing.** It only has `workflow_dispatch` and `workflow_call` (`.github/workflows/storyteller-cosmos.yml:9-11`), and no other workflow calls it. Since this PR moves the whole Cosmos suite to the vNext emulator and adds classic-only traits, merging with no automated run means the split is never exercised on PRs. Add a `pull_request` trigger with `paths:` for `src/Platform/Storyteller/**` (at least the vNext job), or call it from the existing platform workflow. The note in the description that it "needs to be on main first" applies to dispatch only; a `pull_request` trigger runs from the PR branch.

3. **Floating emulator tags.** `CosmosTestEmulator.cs:37-38` use `vnext-latest` and `latest`. The vNext emulator is still changing quickly, and the PR already found 3 emulator-specific failures; a silent image update will turn into unexplained red builds. Pin a version (or a digest) and bump it deliberately. The same applies to the Aspire `RunAsEmulator` image if Aspire allows a tag override.

4. **The "an organization exists" check that came for free is gone.** Before, a request for an organization without a container failed (404 from Cosmos, or `VerifyAccessForMachineAsync` returned false after `ReadContainerStreamAsync`). Now any organization name gives empty reads and successful writes into a new logical partition. Authorization in front of the backend makes this safe today, since a caller needs an access point. But it's a change in the trust model worth stating in `access.md`/the spec: the backend no longer refuses an unknown organization, and nothing ever cleans up items written under one. With D6 (no org deletion yet), orphaned data under a deleted or mistyped org stays forever and isn't visible to the usage snapshot, which lists organizations from `core`.

5. **`CosmosOrganizationCatalog` duplicates the `core` access constants.** `CosmosOrganizationCatalog.cs:13-14` redefines `"access"` and `"apt."`, which already live in `CosmosAccessService.MAIN_PARTITION_KEY` (`:18`) and `AccessPointEntity.Id` (`$"apt.{Key}"`). If either changes, the snapshot silently finds zero organizations and the usage meters go flat with no error. Expose them as public constants (e.g. `AccessPointEntity.IdPrefix`, `AccessPointEntity.Partition`) and reuse them. The "no dot means organization" rule is also implicit; a small `AccessPointEntity.IsOrganization` or a comment pointing at the name rules (`NameRules.Pattern`, which forbids dots) would make it explicit.

## Nits

6. **DbCreator message for a mis-keyed container.** `InitDbCommand.cs:51` and `DatabaseLayoutException.cs:12` always say the database "has the layout before the shared container", but `FindLayoutProblemsAsync` also reports an `organizations` container with the wrong partition key paths (`ContainerFactory.cs:120`), which isn't a legacy layout. Use something neutral like "can't take the shared layout".
7. **`FindLayoutProblemsAsync` doesn't check `core`.** A `core` with a partition key other than `/PartitionKey` would pass. Cheap to add while you're there.
8. **`CosmosTestEmulator.cs` is duplicated** byte for byte (apart from the namespace) in `Backend.CosmosDb/test` and `Access.Certificates/testint` (122 lines each). Link one file (`<Compile Include="..." Link="..." />`) or move it to a shared test-utilities project so fixes land in both.
9. **`ContainerFactory.CreateContainerIfNotExistsAsync`** special-cases the organizations name and otherwise always uses `/PartitionKey`. Now that only two containers exist, consider replacing it with `EnsureCoreContainerAsync()` and `EnsureOrganizationsContainerAsync()` so no caller can create a stray container by name.
10. **Throughput fairness** (discussion, not code): all organizations now share one container under the database's shared throughput. That was already true across containers, but a single noisy organization's organization-wide queries (the usage snapshot, re-wrap, cache invalidation) now compete inside one container. Worth a line in the spec about per-organization RU budgeting or throttling once public sign-up opens.

## Good

- `OrganizationKeys` / `OrganizationContainer` is a clean, narrow seam. The call sites barely changed shape, which kept a 126-file change reviewable.
- Making `Organization` a `required` property on every entity means the compiler finds every construction site, and Cosmos rejects a document whose body doesn't match the key. That gives two independent checks against writing into the wrong organization.
- `StructuredApiKey` now uses `IsNullOrWhiteSpace`, which closes the blank-organization 500 that `OrganizationContainer`'s guard would have surfaced.
- DbCreator refuses the legacy layout before writing anything, with a dedicated exit code and clear re-seed instructions. The new Aspire volume name avoids the classic/vNext data-format clash.
- The spec, the probe and its cookbook, and the phase reviews document the decisions (D3, D6) and the deviations honestly.
