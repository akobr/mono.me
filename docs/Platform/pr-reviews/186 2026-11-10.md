# Review of PR #186: [fix(platform): refuse unknown values of sform story --tree-root and accept subject (424-219)](https://github.com/akobr/mono.me/pull/186)

Reviewer: Harry · Review date: 2026-11-10

**Verdict: approve-ready, with one behavior change worth a conscious decision.** A small, well-scoped CLI fix: `sform story --tree-root` now accepts `subject`/`sbt` and `responsibility`/`rst` in any case, refuses anything else with exit 2 before any API call, and implies `--tree`. The parsing is correct, the tests are thorough, and the catalogue, `coverage-values.json` and the automation test all follow.

Scope I read: the PR description, the spec and review docs, the full diff, `StorytellerListCommand` in full (including the `ExecuteAsync` dispatch order and both tree renderers), `BaseContextCommand.OnExecuteAsync`, `AnnotationTypeCodes`, the new unit tests, `AnnotationListTests.Story_Tree_Rendered`, and `launchSettings.json`. CI at review time: "CLI unit tests, self tests and coverage" and CodeRabbit were still in progress, so I couldn't confirm a green run.

## Blocking

None.

## Important

1. **`-b` now takes precedence over every other query, including `-d`.** In `StorytellerListCommand.ExecuteAsync` (L122–127) the tree branch runs first, so with "`-b` implies `-t`" a command like `story -d <key> -b rst` or `story -u -b sbt` now silently renders a tree and drops `-d`/`-u`/`-e`. Before, `-b` without `-t` was ignored and those commands did what their other options asked. With `-t` this precedence already existed, and the spec puts the general "ignored option combinations" out of scope, so it's not a regression for documented usage. But "implies" now extends that silent-ignore to more invocations. Options: refuse `-d` together with a tree (exit 2, like the unknown root), or at least write a one-line warning to stderr when `-d`, `-u` or `-e` are dropped by the tree. Worth a follow-up ticket if not done here.
2. **Wait for CI before merging.** Both checks were still running when I reviewed. The PR's own verification (1943 unit tests, 87 self/coverage tests) is convincing, but `CommandCoverageTests`/`CatalogueTests` are exactly what this change touches, so let the workflow confirm it.

## Nits

- `StoryTreeRoot` (`Commands/Storyteller/StoryTreeRoot.cs`) is `public`, while its only consumers (`TryParseTreeRoot`, `RenderTreeAsync`) are `internal`/`private` and the option itself stays a `string`. `internal` would keep it out of the CLI assembly's surface; tests already see internals via `TryParseTreeRoot`.
- `TryParseTreeRoot` (L92–109) puts `case null:` next to the real values. It's correct, but the meaning "option absent" is different from "named subject". A separate `if (value is null)` early return would read more clearly and keep the switch about values only.
- The error message echoes the raw value (L118), so `-b ' context '` prints `' context '` while matching is on the trimmed value. Harmless, but echoing `value.Trim()` would match what was actually compared.
- `TreeRoot_WithoutTree_RendersTheTree` covers `rst` and `subject`; adding `sbt` without `-t` would close the matrix cheaply.
- Testiny case 255 still has the old steps (the review doc calls this out as open). Make sure someone owns that update so the external case doesn't drift from the catalogue.

## Good

- Validation runs before any API call and before sign-in matters, proven by the strict mock plus `VerifyNoOtherCalls()` in `TreeRoot_Unknown_IsRefusedWithTheAcceptedValues`, including empty and blank values.
- Choosing not to use McMaster's `[AllowedValues]` because its handler exits with 1 (reserved for crashes) is the right call and keeps exit codes consistent with `story config`.
- `RenderTreeAsync` switching on an enum instead of string comparisons is cleaner; returning the `Task` directly is fine here since the method only selects.
- `launchSettings.json` (`story --tree --tree-root responsibility`) stays valid, and the help texts now name the values.
