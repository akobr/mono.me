## Important

1. **The release now publishes Hosting, but its gate never runs Hosting's tests.** `.github/workflows/storyteller-sdk-release.yml:86` adds Hosting to the pack loop, while the gate it `needs`, `.github/workflows/storyteller-conformance.yml:98-102`, only runs the ConfigurationFormats and Configuration test projects, and its `paths` filters (`:11-37`) do not list Hosting at all. That matters more for Hosting than for the others, because Hosting compiles against internals of Configuration (`Configuration.csproj:21` grants `InternalsVisibleTo` to `42.Platform.Storyteller.Hosting`). A Configuration change that renames or reshapes an internal passes the gate, triggers no Hosting run, and ships a broken Hosting package. The PR lists this under "worth checking"; I'd fix it here since this PR is what turns Hosting on for release. Add a step `dotnet test --project src/Libraries/Platform/Storyteller/Hosting/test/Hosting.UnitTests.csproj` to the `dotnet` job, and add `src/Libraries/Platform/Storyteller/Hosting/**` to both `paths` lists (or collapse them to `src/Libraries/Platform/Storyteller/**`, which also picks up KeyVault, as noted on #165).

2. **The NuGet dependency from Hosting to Configuration is a floor, but Hosting relies on Configuration internals.** `src/Libraries/Platform/Storyteller/Hosting/src/Hosting.csproj:28-29`. The comment says "Hosting uses internals of it, so both ship one version", but a `ProjectReference` packs as `>= <version>`, so a consumer can take a newer Configuration with an older Hosting and hit `MissingMethodException` or `TypeLoadException` at runtime, with no compile-time warning. Moving Hosting into the same workstead (`src/Libraries/Platform/Storyteller/version.json`) is a step toward the "one version" promise #165 raised, and releasing them in one loop helps, but neither stops NuGet from resolving them apart. Options, in order of effort: pin the dependency to an exact version at pack time (for example a `PrivateAssets="all"` project reference plus an explicit `PackageReference Include="42.Platform.Storyteller.Configuration" Version="[$(PackageVersion)]"` in a pack-only item group, or a `nuspec` token); or move the shared internals into a small public "infrastructure" namespace marked `[EditorBrowsable(Never)]`. At minimum, make the comment honest ("released together; keep the versions in step") so nobody relies on a guarantee that isn't there.

## Nits

1. **Version drop is fine, but say so where the next person will look.** Hosting falls from `0.10.8-alpha` to about `0.10.3-alpha`. Since nothing is on nuget.org this is harmless, and `--skip-duplicate` in the publish step (`storyteller-sdk-release.yml:154`) cannot collide with an earlier upload. Any local or dev feed holding `0.10.8-alpha` will keep preferring it, though; a one-line note in `docs/Libraries/Platform/Storyteller/Hosting/package-readme.md` or `hosting.md`, or a `versionHeightOffset` in the workstead `version.json`, would avoid confusion for anyone who tried the earlier builds.

2. **`Aspire.Hosting` is still the odd one out.** It sits in the same workstead but is neither packed (`storyteller-sdk-release.yml:86`) nor listed in `docs/Platform/Storyteller/conformance.md`. If it is intentionally not released yet, a short comment above the pack loop saying so saves the question on the next PR.

3. **Workflow header comment wraps past the line length of the rest of the file.** `storyteller-sdk-release.yml:5` is now 126 characters, longer than its neighbours (about 116-119) after inserting "Hosting and the packages they depend on"; rewrap the comment block for consistency.

4. **`CLAUDE.md` describes Libraries as "suppressed as top-level mrepo item".** With Hosting now there too, the `mrepo.json` "2S platform" `test` script no longer covers the Hosting tests (the same gap #165 noted for the other four). Worth a line under the Libraries heading on how to run them.
