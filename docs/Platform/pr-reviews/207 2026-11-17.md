## Important

1. **`points revoke -r` help is wrong, and the PR now adds a detail right next to it.** `AccessPointRevokeCommand.cs` L46 says "If not specified all roles will be revoked." But L85 falls back to `PermissionRole.Reader`, and `CosmosAccessService.RevokePermissionAsync` (around L353) throws `ConflictException` (`ElevatedRole`) when the account's role is higher than the one requested. So `sform account points revoke <id> -p x` on a Contributor or above **fails with 409**. It doesn't revoke everything. The PR description and the spec review already flag this ("found on the way, not fixed"). Since this PR is about trustworthy help for exactly this command, I'd fix the option text here at least, e.g. "The role to revoke: … The account's current role; Reader when not given." Or open the follow-up Linear issue now so it doesn't get lost. The same goes for `-r` of `grant`/`revoke` not listing `ContributorWithSecrets`.

## Nits

- **`machine-auth -d` / `-l`** (`MachineAuthSetCommand.cs` L45, L48): on their own they fail with "At least one --credential-kind is required" (L80–83), and with `-k` they also need Administrator. The detail explains it, but the option texts don't. Consider "… Only with -k." Also, a set without `-l` resets the lifetime to the deployment default (L99). That's in the detail, but a short "not kept when omitted" in the `-l` option would match what you did for `-k`.
- **Terse parent-list texts.** "Re-protect keys" and "Re-encrypt hyok data" lose meaning in the `sform story kv` list. That's a fair price for one line, but "Move keys to another level" could still fit in the 53 columns.
- **`machine create`** has a note but no detail paragraph, while `reset/delete/rules` spell out the scope→role rule. The rule lives in `--scope`, which the docs paragraph allows. A one-line detail would still make the four `machine` commands consistent.
- **`docs/42for.net/cli/sform.md`**: the edited paragraph is now one very long sentence chain. A short bullet list would read better: when a note appears, groups, value-dependent roles, machines.
- **Test style:** `Detail_EndsWithTheRoles_InFullSentences` and `Detail_KeepsWhatTheDescriptionSaid` pin texts word for word, so every wording tweak needs two edits. That matches the 424-222 convention, so it's fine. Just noting the maintenance cost.

## Good

- The notes come from a traced CLI → SDK → Function → service check, and they hold up. I found no claim the server contradicts.
- The `-k` rewording ("The kinds given replace the enabled ones") prevents a real foot-gun: leaving a kind out stops its machines.
- `GroupNote_IsTheNoteOfEveryCommandBelowIt` turns the group rule into a test, so a future command under `shared-cert` with a lower role will break the build instead of making the help lie.
- The "an machine" typo fixes in the `reset`/`delete` arguments are a nice touch.
