# Review of PR #141: [Local-only schema references and bounded schema validation (424-98)](https://github.com/akobr/mono.me/pull/141)

Reviewer: Harry · Review date: 2026-10-31

**Verdict: needs changes.** The SSRF fix is solid, and so are the cycle, stack and nullability guards. But the "bounded" promise holds only per document, not per request.

## Blocking

1. **The compliance check is bounded per configuration, not per request.** `CollectComplianceErrorsAsync` (`CosmosConfigurationSchemaService.cs:713` and `:738`) calls `ValidateAgainstSchemaAsync` once per affected configuration. Each call gets a fresh parse budget (`ConfigurationSchemaChecker.cs:54`) and a fresh check budget (`:91`/`:161`). A project member controls both the schema and the stored configurations, so with 1,000 configurations each tuned to finish just under 10 s, one `PUT` holds a worker for close to 3 hours. The run also sits inside the ETag retry loop (`MaxRetries = 3`, `:464`), which multiplies that by up to 4, and a forced schema import hits the same thing. Pass one request-scoped deadline through every parse and validate, fail with `SchemaValidationTimeout` on timeout, and parse the merged schema once per distinct `MergedContent` instead of per configuration.

## Important

2. **Parse and check have separate budgets**, so one configuration write costs about 2× the documented limit, and `ValidateContentAsync` runs inside the write's retry loop (`CosmosConfigurationService.cs:412/473/517`). Share one deadline, or document it as "parse + check" in `definitions.md`.
3. **Stored schemas with external `$ref`s will break existing writes on deploy.** Each becomes a 400 `ExternalSchemaReference`. That's the right call, but there's no inventory step. Run a one-off Cosmos query for any `$ref` that isn't `#` or `#/…` before rollout.
4. **The options aren't validated at startup.** `EntryPoint.cs` uses `.Validate(...)` without `.ValidateOnStart()`, so a bad `ConfigurationSchemas` value only fails during a request. `AnnotationOptions` has the same gap.
5. **The format validators are unbounded outside the API host.** NJsonSchema's 13 format validators rely on `REGEX_DEFAULT_MATCH_TIMEOUT`, which only `Api.Functions/Program.cs` sets, while `DbCreator` and the integration-test hosts also call `AddCosmosDbAnnotations`. Low risk today, but move the default or document it.
6. **The `IsNullable` port is tied to NJsonSchema 11.5.2.** If a bump changes the library's walk, the guard silently stops matching. Add a version-pinning test or a comment in `Directory.Packages.props`.

## Nits

- `ConfigurationSchemaChecker.cs:226` runs `MatchPattern` on every string step, even when the type excludes string.
- `:175` re-walks `IsNullable` on every step. Memoize per `JsonSchema`.
- `:76` has a catch-all `catch (Exception)` that turns `OutOfMemoryException` and bugs into `InvalidSchema`.
- `ProcessDefaultsTests` sets process-wide `AppContext` data. Add a comment.
- The OpenAPI `force` text still names only `SchemaViolation`. Open a follow-up ticket.

## Good

`LocalReferenceResolver` refuses before any host path is built, and the tests prove it with a live `TcpListener` that never gets a connection. The cycle detection is correct and cheap, and stack checks turn a fatal `StackOverflowException` into a 400. Every schema failure is now a coded `InvalidInputException`, so config PUT/PATCH no longer returns a 500 with a stack trace.

## CI

`.NET reference (ubuntu-latest)` and `TypeScript SDK` passed. Windows and CodeRabbit were still running at review time. `Build and Deploy Job` failed, which looks like the Static Web Apps deploy and is probably unrelated, but check whether it also fails on main.
