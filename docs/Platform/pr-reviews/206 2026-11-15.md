# Review of PR #206: [feat(platform): project settings on the server for every client (424-266)](https://github.com/akobr/mono.me/pull/206)

Reviewer: Harry · Review date: 2026-11-15

**Verdict: needs changes (small ones).** The server side is well designed. It has one shared rule set with conformance vectors, ETag/`If-Match` on a monotonic `Version`, a real RFC 7396 merge that refuses case collisions, and an ETag-guarded replace with one retry. It also fixes the existing lost-update risk in the machine policy store. I found no logic bug in the API or the Cosmos service. Before merge: get the CLI workflow green, and close two hardening gaps. Labels accept control characters, which reach other members' terminals raw. And a PATCH revalidates the stored values it doesn't touch, which gets fragile when the catalog changes. The PR is large: 599 files, +47,655/−1,248, 31 commits. About 26k lines are the regenerated TypeScript SDK. I read the hand-written C# in full: the API handler and conditions, the Cosmos service and entity, the rules/JSON/catalog, the NSwag twins, the DbCreator seeding and the sform settings provider. I skimmed the admin UI, the docs/specs and the tests.

## Important

1. **Labels and plurals accept control characters, and sform prints them raw.** `ProjectSettingsRules.NormalizeAppearance` (`Abstractions.Annotations/.../ProjectSettingsRules.cs` L161–220) only trims and checks length. `ProjectDisplay.Text` (`Cli/src/Services/Projects/ProjectDisplay.cs`) passes the value straight into tables, tree tags and headers. So an Administrator, or a stolen admin token, can store `ESC` sequences that every member's terminal runs: OSC 8 links, title changes, screen clearing, faked output. The same strings reach assistants through `list_projects` (MCP), which is a small prompt-injection surface. Vue escapes them in the admin UI. **Fix:** add a rule (for example `label-characters`) that refuses C0/C1 controls (`char.IsControl`), U+2028/2029 and the bidi override/isolate characters (U+202A–202E, U+2066–2069). Add it to the vectors and to `validateProjectSettings`. As defence in depth, have `ProjectDisplay` replace controls the way `PlainOutputExtensions` already does (L119).

2. **A PATCH revalidates the stored values it doesn't touch, so it breaks when the catalog changes.** `CosmosProjectSettingsService.PatchAsync` (L92–98) runs `ProjectSettingsJson.ReadMergePatch(stored, patch)`. That turns *all* stored settings back into JSON and reads them back through the full rules (`ProjectSettingsJson.cs` L155–172). The same applies to a type code the catalog doesn't know, which `ProjectSettingsEntity.Ordered` deliberately keeps. Today the catalog only grows. Once an icon, colour, date format or type code is removed or renamed, every PATCH to an affected project fails with `400 InvalidSettings`, on a member the caller never sent. sform `set` and the UI's PUT-from-read hit the same wall. **Fix:** either (a) make catalog removals a versioned migration (spell this out in `conformance.md`), or (b) have the PATCH path report problems only for paths the patch touches. With (b), stored values the catalog no longer has are dropped with a warning or kept as they are. Add one vector for "stored value not in catalog + unrelated patch".

3. **Old binaries drop `Settings` during a rolling deploy.** Every writer of `apt.{org}.{project}` does a full typed replace or upsert of `AccessPointEntity`: `CosmosAccessService` (description, membership batch), `CosmosKeyValuePolicyStore`, `CosmosMachineAuthenticationPolicyStore`, and DbCreator's `Data.MergeAsync`. In the new code that's correct, because `AccessPointEntity` now has `Settings`. But an instance or tool still running the *old* entity type (a Function instance mid-slot-swap, an older DbCreator/sform-adjacent tool on a dev machine) silently removes the settings on its next write. The ETag only guards against concurrent writes, not against unknown members. **Fix:** at least note the deploy order in the PR and `access.md`: API and DbCreator together, no old writers after settings are first stored. Better, for the new store, use `PatchItemAsync` with `PatchOperation.Set("/Settings", …)` under `IfMatchEtag`. Then this writer never round-trips members it doesn't own. That also makes the "one retry" argument stronger.

4. **The new enum value `KeyValueAuditOperation.ProjectSettingsChange` breaks older clients.** NSwag-generated clients (older sform, any .NET SDK consumer) deserialise enums strictly. Once one settings change sits in the audit trail, an older client's `get audit` throws on the unknown value. Settings events also land in what the API and MCP describe as the *secrets* audit trail (Administrator only). **Fix:** call this out as a breaking change in the SDK changelog/version (0.10.40). Consider making the SDK's enum converters tolerate unknown values, or give project events an operation name space or trail of their own in a later step. Either is fine, but say which.

5. **sform: a failed fetch ignores the stale cache, and every offline run pays the timeout again.** In `ProjectSettingsProvider.LoadAsync` (L119–140), any exception from `FetchAsync` returns `ProjectDisplay.BuiltIn`, even when a cache entry older than 10 minutes exists. A failure is also never recorded, so on a flaky or blackholed network *every* command waits up to `ReadTimeout` (5 s, L33/L145–147) and then flips to built-in names. **Fix:** on failure, return `Display(entry.Settings)` when there is a stale entry, and stamp a short negative TTL (for example `RetryAfter` of 1–2 minutes) in the cache file. Consider a smaller timeout (about 1.5 s) for a call that's only decoration.

## Nits

1. `ProjectSettingsHttp.SetProjectSettings` (L91–132) never checks `Content-Type`. A client that sends a partial `application/merge-patch+json` body to **PUT** by mistake gets a valid full replace, and every type it left out silently goes back to built-in. Answer `415` for `merge-patch+json` on PUT, the mirror of the PATCH check at L166–176.
2. `AccessMappings.ToEntity(AccessPoint)` (L40–46) doesn't map `Settings`. Nothing calls it on a write path today, but it's a trap for the next caller. Map it, or add a comment that it's create-only.
3. `CosmosMachineAuthenticationPolicyStore.SetAsync` can now throw `ConflictException`, which the old upsert never did. The HTTP mapping and docs are updated. Check that DbCreator and any other non-HTTP caller handle it, or let it surface on purpose.
4. `CosmosProjectSettingsService.AuditAsync` (L239) also swallows `OperationCanceledException`. That's harmless because the audit write takes no token, but the comment could say the append is meant to be non-cancellable.
5. Time zone aliases (`Europe/Kiev`, `Asia/Calcutta`, `US/Eastern` …) are valid and stored as given, so two projects can hold the same zone under different ids. Consider storing the canonical id, or say in the catalog docs that ids are compared as given.
6. Admin UI `queries/project-settings.ts` L69–72: once a project has server settings (`Version > 0`), every browser drops its legacy local settings, including Readers'/Contributors', who could never migrate them. That's probably intended (the server wins), but the banner text or release note should say so. Alternatively, move a non-admin's legacy types into their personal Preferences, which still override.
7. sform's cache is keyed by base URL and project, not by account. After switching identities on one `SFORM_HOME`, the previous account's view is shown for up to 10 minutes. It's harmless because all members may read the settings. A one-line comment would do.

## Good

- One rule set (`ProjectSettingsRules`/`ProjectSettingsJson`) with an embedded catalog and **72 shared vectors**. .NET, the TypeScript SDK and the admin UI all run them. Trimming is deliberately aligned with .NET's `char.IsWhiteSpace` in TS (`\p{White_Space}`, not `String.prototype.trim`), and that's commented.
- Conditional writes are done properly. The strong ETag is the quoted `Version`, with canonical-number parsing (`"07"` never matches), `*` support, `If-None-Match` refused on writes, a `412` with `Details.Version`, and no-op writes that keep the version and emit no audit event.
- The merge patch refuses unknown and case-colliding names *before* merging, so a patch can never silently override itself. `AllowDuplicateProperties = false` on body parsing closes the duplicate-key ambiguity.
- The machine policy store moves from upsert to an ETag replace, which fixes a real lost-update race with membership and settings writes. It has its own emulator tests.
- DbCreator never overwrites settings: it writes conditionally on `Version(0)` and decides again after a 412. Settings are validated before any write.
- Thorough tests: HTTP (545 lines), Cosmos service on the emulator (concurrency, conflicts, audit failure, keeping the other access-point members), NSwag twins, sform provider and commands, UI unit and e2e.
