# Review of PR #202: [feat(platform): append-only access audit trail of roles, memberships and machines (424-263)](https://github.com/akobr/mono.me/pull/202)

Reviewer: Harry · Review date: 2026-11-15

**Verdict: approve-ready, with two items to discuss.** The core design holds up. Each record is written in the same transactional batch as its change, so no outbox is needed. Nothing updates a record, and records expire by TTL. Keyset paging on a time-sortable id merges the two homes correctly. The change also fixes four real pre-existing bugs: the policy upsert without an ETag, the machine list returning `mcert.`/`scr.` documents, non-atomic account + project creation, and racing certificate revocations. I found nothing blocking. The open points are about how the system behaves at scale and when something fails, not about whether the code is correct.

## Important

1. **A failed audit batch after a client-secret reset locks the machine out.** `CosmosAccessService.ResetMachineAccessAsync` (L585–631): for a client secret, the identity provider has already replaced the secret before the `!isRecorded` batch (mask patch + record) runs. If that batch fails (429 after retries, 503, a timeout), the API returns an error and never returns the new secret. The old secret is already invalid, so the machine stays locked out until someone resets it again. Choosing "never hand out a secret without its record" is defensible, but today the failure is silent apart from the 5xx. **Fix:** catch the failure and log it at Error level with the org/project/appId and the correlation id ("credential replaced, record not stored, secret withheld"). Answer with a specific error code/message that tells the caller to reset again, and state this in `access-audit.md`. Alternatively, write the record *before* the IdP call. That would record an attempted reset that might not complete, but no credential would be lost.

2. **The core `"access"` partition: query cost now, size later (needs discussion).** All orgs' records share one logical partition with the accounts and access points. The spec treats the 20 GB limit as an archive problem. Two points it doesn't cover:
   - **Query RU:** `CosmosAccessAuditLog.BuildQuery` (L124) is `STARTSWITH(c.id,'aca.') AND c.Organization = @org … ORDER BY c.id DESC` in that shared partition. With default indexing, Cosmos walks the `id` range newest first and filters on `Organization`. A small org on a busy platform pays to scan everyone else's newer records before it fills a page of 101. **Fix:** add a composite index `(/Organization ASC, /id DESC)` to core in `ContainerFactory` (DbCreator already rewrites core settings for TTL). If the `project`/`action` filters turn out to be common, also add `(/Organization, /Project, /id DESC)`. Then assert the RU in an emulator test or a note.
   - **Size estimate:** "about 1 KB per record" holds for role changes. `KeyValuePolicyChanged`, `MachineAuthenticationPolicyChanged` and issuer records carry old *and* new JSON, each capped at 4,000 chars (`AccessAuditValues.MaxLength`, L18), so a single record can reach ~8–9 KB. That doesn't change the conclusion today, but the docs should give a range, not 1 KB.

## Nits / suggestions

- **Silent fallback when the pending record isn't picked up.** If `PendingAccessAudit.Find` misses for an API key (a different item id or partition key, or a future hash store), `ResetMachineAccessAsync` falls back to the second, non-atomic batch without any signal. Add a `Debug.Assert`/warning log when `machineAccess.CredentialKind.HasApiKey() && !isRecorded`, so a regression in the merged store shows up in tests and logs instead of silently losing atomicity.
- **The authorization source changed.** Grant/revoke now authorize on `caller.Actor.Id` (`CosmosAccessService` L286, L301) instead of `model.CreatedById`. It's documented and the API passes the same value. But any non-HTTP caller that passes `AccessCaller.System` to grant/revoke/set-role/remove will now get `AccessDenied`. That seems right, but a one-line test would pin it. Removing `Permission.CreatedById` is already listed as a follow-up. Until then, `AccessHttp` still sets it for nothing (L303, L336).
- **Cancellation:** none of the new `ExecuteAsync()` calls in `CosmosAccessService`, `CosmosMergedApiKeyHashStore` (L213), `CosmosSharedCertificateStore` or `CosmosMachineAuthenticationPolicyStore` pass a token. This matches the existing interfaces, which take none. The key/value policy and issuer stores pass one, so this is a consistency nit at most.
- **`AccessAuditHttp`:** `from > to` quietly returns an empty page (L72). A 400 `InvalidQuery` would be friendlier. The continuation token doesn't bind the filters, so a client can change filters mid-paging and still get a consistent "older than X" view. That's fine, but worth a sentence in the docs.
- **`CosmosAccessAuditLog.ReadAsync`** (L189) swallows 404 for *both* sources. For core it would hide a missing container as an empty trail. Limit the catch to the organizations call.
- **Ordering across instances:** the ids come from each instance's wall clock, so two records from different instances within clock skew can come back in a slightly different order than they were committed. That's harmless for an audit view, but worth a line in `access-audit.md` ("time order is per writer clock").
- **Seeding** (`Data.MergeMembershipAsync`): when the access point is missing, the record says `AccessPointCreated` with the account as the target. When only one side is repaired, the action is derived from the point's role. Fine, but the `Detail` "Seeded by DbCreator." could also say "repaired" when only one document changed, to help whoever reads the trail later.
- **PR size:** with ~22k lines of generated SDK, the hand-written part is hard to find. Next time, consider putting SDK regeneration in its own commit or PR.

## Good

- The atomicity model is consistent everywhere: membership (point + account + record), access point creation (org + project + account + records, now atomic with account creation), and ETag-guarded replaces that turn 412 into one re-read. No-ops record nothing.
- `PendingAccessAudit` is a clean, narrow use of `AsyncLocal`. The scope restores the previous value. `IsWritten` is only set after the batch succeeds, and the 412 retry in the hash store reuses the same record id safely, since the failed batch created nothing.
- Secret hygiene in `AccessAuditValues`: no hashes or masks, JWKS reduced to a count plus a thumbprint of a canonical form (so a key swap counts as a change and reformatting doesn't), recipient keys reduced to thumbprints, and long values capped with a SHA-256 suffix.
- The continuation token is strictly validated (version, length, id regex) and answers `InvalidQuery`, not a 500. The query was tightened with `IS_DEFINED(AccessPointKey/Action)` against a view named `aca`.
- The route clash `v1/access/points/{key}/audit` vs `v1/{org}/{project}/key-values/audit` was caught and fixed with an organization constraint and route-table tests.
- Thorough tests: one emulator test per operation, failed batches leave neither change nor record, and the paging tests cover both sources.
