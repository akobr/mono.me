# Review of PR #158: [fix(platform): open all the keys of a level from the secrets policy links (424-159)](https://github.com/akobr/mono.me/pull/158)

Reviewer: Harry · Review date: 2026-11-02

**Verdict: approve-ready.** A small, well-scoped Admin UI fix (`key-values.vue`, `KeyValueBulkBar.vue`, a comment in `SecretsPolicyCard.vue`, four Vitest cases, two mobile baselines, spec, spec review and the Storyteller doc; +210/−14). The diagnosis is right: the page folded `state=All` into Deleted, so an active secret of the level never showed. Choosing a real **All** state over linking to Active is the correct call, because `CosmosKeyValuePolicyService.CountInUseAsync` (L284–306) counts by `c.Content.Protection` with no `Deleted` filter, so an Active-only link would show fewer keys than the 409 says. The API (`KeyValueState.All`) and the mock (`listPairs`) already supported it, so this is UI-only with no contract change. The points below are follow-ups, not blockers.

**CI at review time:** "Lint, type-check, test, build" and CodeRabbit were still running (mergeable state `unstable`). I read the diff against the full `key-values.vue`, `KeyValueBulkBar.vue`, the detail route `key-values/[key].vue`, `queries/scope.ts`, the mock handlers and the backend `KeyValueState` / `KeyValueSummary` / `CountInUseAsync`, but did not run it.

## Blocking

None.

## Important

1. **`bulkState` treats any selected key it can't see as active** (key-values.vue L77–88). The deleted set is built from `list.data.value?.Items`, and a key that isn't in the loaded items falls through to `'Active'`. The selection is cleared on a state, project or view change (L62) but **not on a level-filter change**, so in All: select a deleted key, switch the level, and the bar now offers **Delete** / **Change protection** for a key that is deleted. The same happens briefly while the list refetches with new params (the query key changes, so `data` is `undefined` until it loads) and the whole selection reads as active. Nothing destructive follows (a Delete of a deleted key fails per key and stays selected; Purge is never offered by mistake, since unknown keys never count as deleted), but the bar is wrong in exactly the situation the badge is meant to make clear.
   *Fix:* build a `Map<key, IsDeleted>` from the items and return `'Mixed'` (or hide the actions) when a selected key is unknown or the list is pending; and/or add `levelFilter` to the selection-reset watch at L62, which also fixes the same invisible-selection issue in Active and Deleted.

2. **The 409 count and the linked list may still disagree on paging.** The page shows only the first page of `GET …/key-values` (`useKeyValues` ignores `ContinuationToken`), and the "N of M" counter (L277) uses `Items.length`. For a view with many keys of a level (active plus deleted), the link can still list fewer keys than the card's count, which is the very mismatch this PR set out to fix. This predates the PR, so it's not a blocker, but worth a Linear follow-up or a sentence in the spec review.

## Nits

3. **"Select all" in All always yields Mixed** when the view has both states (`toggleAll`, L90–92): the user gets the hint and no actions. Fine as a rule, but the hint could suggest the fix, e.g. "Switch to Active or Deleted to act on all of them," or Select all could pick only the rows of one state.
4. **The Mixed hint isn't announced.** The `<span>` at KeyValueBulkBar.vue L138 replaces the buttons silently; `role="status"` (or `aria-live="polite"`) lets screen-reader users know why the actions vanished.
5. **Duplicated badge markup.** The table builds the badge in a render function (`deletedBadge`, L242) and the mobile list repeats it in the template (L317), and the detail header has a third copy in `[key].vue`. A tiny `KeyValueDeletedBadge.vue` (or a shared props constant) keeps the three in sync.
6. **Badge condition vs `isDeletedRow`.** The key cell and the mobile list check `state === 'All' && row.IsDeleted` inline while the expiry cell uses `isDeletedRow`. Intentional (no badge in Deleted), but a second helper like `showDeletedBadge(row)` would read more clearly than two shapes of the same check.
7. **Mobile list shows no expiry** for a deleted row in All (or Deleted). The desktop column says "expires in N days"; on a phone the badge is the only cue. Optional: append "· expires in N days" to the second line.
8. **"All" beside "All levels".** The new state button sits next to the level select whose first item is "All levels", which reads a bit ambiguously. "Both" or "Active + deleted" would be unambiguous, though "All" matches the API enum, so this is a judgment call.
9. **Brittle pressed-state assertion** (key-values-page.test.ts L133–134). Comparing whole `className` strings works today but breaks on any unrelated class difference (focus ring, first/last-child rounding in `UFieldGroup`). Asserting `aria-pressed` would be sturdier, which means adding `:aria-pressed="state === 'All'"` to the three toggle buttons (also an a11y win, as they behave like a segmented control).
10. **Mobile layout regression accepted.** The third button pushes "8 of 8" onto its own line on phones (baselines updated). Acceptable, but `flex-wrap` with `ms-auto` on the counter, or hiding the counter below `sm`, would keep one line.

## Good

- The root cause is documented end to end (spec with exact lines, backend count semantics, the external SET-SEC-02 test to tighten), and the spec review explains the "expires" prefix decision.
- `state` parsing still narrows cleanly and defaults unknown values to Active; `params` sends `state` only when it's not Active, so the Active request is byte-for-byte unchanged.
- Row actions already keyed off `row.IsDeleted`, so Reveal and Delete stay hidden for deleted rows in All with no extra code, and the detail route already used `includeDeleted = true`, so opening a deleted row from All works.
- Preventing bulk calls on a mixed selection is the right design given the bulk endpoints take one state; the tests cover active-only, mixed and deleted-only transitions, plus the exact link URL of the policy card.
- "Deleted" still lists only deleted keys, and that regression is pinned by a test.
