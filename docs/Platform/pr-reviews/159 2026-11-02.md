# Review of PR #159: [fix(platform): reset a deleted schema or template in the admin UI editor (424-158)](https://github.com/akobr/mono.me/pull/159)

Reviewer: Harry · Review date: 2026-11-02

**Verdict: approve-ready.** A focused Admin UI fix (`CodeEditor.vue`, `DocumentEditor.vue`, `SchemaDetail.vue`, a comment in `TemplateDetail.vue`, Vitest + Playwright + UI automation tests, spec, spec review and the user doc; +329/−63). The diagnosis is right and well documented: CodeMirror's own dispatch of an external value came back through the update listener as an edit, so after a delete `draft` became `{}`, the editor went dirty, and the 404 could no longer put in the starter document (schema) or the empty state (template). ## Important

1. **The `CodeEditor` guard assumes every consumer writes the emitted text back into the prop** (`CodeEditor.vue` L107–113). The listener now emits only when `doc !== props.modelValue`. That is right for `DocumentEditor` (its `text` ref round-trips synchronously) and for `KeyValueDetail.vue` L286 (`v-model="draft"`). But if a future consumer ignores or transforms the emitted value, an edit that brings the document back to the stale prop (type a character, then undo) is silently swallowed and the parent keeps the intermediate value. Worth stating this contract in the component's doc comment ("`modelValue` must follow `update:modelValue`"), or tracking the last emitted/received text in a local variable instead of reading the prop, which makes the guard independent of the parent.
2. **The real `CodeEditor` guard has no unit coverage.** `EchoingCodeEditorStub` replaces `CodeEditor`, so the unit tests exercise only the `DocumentEditor` guard; the `CodeEditor.vue` change is covered only by the new e2e `test/e2e/modeling.spec.ts`. Either is enough to stop the bug, which is good, but a regression in the CodeMirror listener alone would pass the unit suite. A small CodeEditor test (mount it in jsdom, set the prop, assert no `update:modelValue`) or a sentence in the spec review that the e2e is the coverage for it would close that gap.
3. **Coordinate with [#157](https://github.com/akobr/mono.me/pull/157) (424-157).** Both PRs touch `test/helpers.ts` and both fix the "Delete own" prompt of the configuration editor (this one through the editor, #157 in `ConfigurationEditor.remove()`); this PR also tightens CFG-CRE-04 on that basis. They merge cleanly, but #157 makes the default `CodeEditorStub` echo, which after this PR no longer matches the real `CodeEditor`. Pick a merge order and, as the spec review already notes, drop `EchoingCodeEditorStub` (or the echoing default) in the second PR so there is one stub that says clearly what it simulates.

## Nits

4. **Three spellings of "clean".** `SchemaDetail.vue` compares `JSON.stringify(draft) === JSON.stringify(original)` in both watches (L56, L67) while `dirty` (L75) uses `?? null`. They agree today (`undefined` vs `undefined`), but a small `isClean()` helper used by all three keeps them from drifting.
5. **Whitespace-only edits no longer emit** (`DocumentEditor.vue` L71–76). Correct for a value-level editor, and the spec review calls it out, but it means a parent can no longer observe "the user touched the text". Worth one line in the component's doc comment above the props.
6. **Redundant negative assertions in the UI automation tests.** In `LeaveDeletedSchemaAsync`, MOD-TPL-01 and CFG-CRE-04, `DetailPanel.CloseAsync()` already waits for the panel to hide, which can't happen while "Discard changes?" is open, so the following `ToHaveCountAsync(0)` on the dialog adds nothing (and as a negative check it passes at once). Harmless; the title check before it is the meaningful one, since the 404 has already settled (Create/empty state asserted).
7. **`DetailPanel.Gone` is now unused** (spec review, CFG-CRE-04 note). Since it can't serve as an outcome for `DiscardIfShownAsync` anyway, remove it or document that limitation so nobody reaches for it again.
8. **Spec wording is stale** in section 3: it says Create stays enabled via `(!dirty && !missing)`, while the code ships `canSave = (dirty || missing) && textValid`. The review document explains the deviation; aligning the spec sentence avoids confusion.
9. **e2e `leave()` uses `.first()`** on `/^(Close|Back)$/`. Fine today; scoping it to the detail panel (`section` of the detail) would keep it from hitting another Close button if one appears on the page.

## Good

- The root-cause chain in the spec, with exact lines, is the clearest part of the PR, and the fix follows it step by step.
- Making the `missing` watch `immediate` also fixes the remount case with a cached 404, and the "This schema does not exist yet" alert now shows for the first time.
- The `canSave` deviation was caught by MOD-SCH-02 and fixed consistently for the button, ⌘S and the editor's save; the new e2e pins the ⌘S path.
- `remove()` in both details keeps resetting `original` and `draft` together, and the stale-data window between the delete and the 404 is safe (`canSave` is false while both are `undefined`).
- The fix also removes the same echo for `KeyValueDetail`'s JSON editor and for `DocumentEditor` format switches, with no behavior change for typing.
- The UI automation tests drop the "accept both" workarounds and now assert only the fixed behavior, which turns them back into real regression tests.
