# Review of PR #225: [docs: developer guide of the 2S Platform on 42for.net (424-325)](https://github.com/akobr/mono.me/pull/225)

Reviewer: Harry · Review date: 2026-11-24

**Verdict: approve-ready (docs only).** This PR adds a 12-page developer guide under `docs/42for.net/platform/documentation/`, a collapsed sidebar group, links from the introduction and from "Using the platform", and a small table style. It changes no code, so I kept this review short. I compared the C# samples with the sources at `fb8762f`. The APIs and namespaces the guide names exist, with the signatures it uses. I checked these:

- `AddStoryteller` on `IConfigurationBuilder`, `IHostApplicationBuilder`, `IServiceCollection` and `IDistributedApplicationBuilder`. Each one lives in the Microsoft or Aspire namespace, so the "no `using` needed" claims are true.
- `IStorytellerConfigurationRefresher.Status/TryRefreshAsync/SwitchKeyAsync`, and `StorytellerConfigurationStatus.IsDegraded/ActiveKey/Origin`.
- `IExecutionContext.GetAsync` and `StorytellerExecutionContext.Subject/Responsibility/Context/GetSubscriptionStatus`.
- `AddSubscriptions(context, …)`, `WaitUntilReadyOnStart`, `AddSubjectOptions<T>(section)`, and `StorytellerSubscriptionChange.Kind/Subscription.Subject` (a `string`).
- `KeyVaultReferenceResolver(TokenCredential, options)`. `AllowedVaults` is a get-only `IList<string>`, so the collection initializer in the sample is valid.
- The Aspire `WithView/WithApiKey/WithClientCertificate/WithExecution/WithStorytellerKey`.
- `ConfigurationFormatter.Format(JToken?, ConfigurationFormat, string? environmentPrefix)`.
- The TypeScript exports `getResolvedConfigurationConditional` (`notModified`/`etag`), `createFederatedTokenProvider` and `encryptForRecipients`.

CI: at review time, "Build and Deploy Job" was still **in progress** and "Close Pull Request Job" was skipped, as it should be on an open PR. There were no comments or reviews yet. The author says `npm run build` passes with no dead links. The author also says the samples were not compiled and the quick start was not run against a deployment.

## Important

1. **The spec review is out of date, and the PR says so.** `docs/specs/reviews/2026-11-19 Developer Guide of the 2S Platform on 42for.net.md` still describes the preview-package warnings, which were removed later. Fix: add a short "Resolved after review" note to that file, or update the finding, so the specs folder doesn't contradict the pages.
2. **Run the quick start once before you publish.** `quick-start.md` is the page people will copy word for word. Nobody has run it end to end against `api.2s.42for.net`. Fix: run the five steps once, or at least `dotnet build` the `Invoicing` sample.
3. **The worker sample in `hosting.md` swallows errors silently.** The `catch (… OptionsValidationException or StorytellerConfigurationException)` has only a comment in its body. Readers copy samples as they are, and a broken customer document would then disappear without a trace. Fix: inject `ILogger<InvoicingWorker>` and log a warning with the customer, for example `logger.LogWarning(exception, "Configuration of {Customer} is invalid", customer)`.

## Nits

- `cli.md` (install section) says "our prereleases are safe to use". The packages are versioned `0.10-alpha` (`src/Libraries/Platform/Storyteller/version.json`), so I'd tone this down to "prereleases are the current releases", or similar.
- `configuration.md` (install tab) uses `Version="0.10.*-*"`, which goes stale at 0.11. Either add a note to bump it, or show `dotnet add package … --prerelease` only.
- `configuration.md` ("Settings in code"): `using _42.Platform.Storyteller.Sdk.Configuring;` isn't needed there, because the lambda's options type is inferred. It is needed in the refresher snippet, which already has it.
- `formats.md` (.NET sample): `content` comes out of nowhere. Say it is a Newtonsoft `JToken` (for example `JToken.Parse(json)`), because `System.Text.Json` users will reach for `JsonNode`.
- `typescript-sdk.md`: `isTransientError` is imported but not used in the conditional-read sample. `const account` is scoped inside `try` and never used. Either use them or drop them.
- `hosting.md`: the first sample uses `builder.AddStoryteller()` and the worker uses `builder.Services.AddStoryteller()`. Both are valid, but one sentence on when to use which would help: the host-builder overload also adds the `IConfiguration` source.
- `_42styles.css`: `overflow-wrap: anywhere` on table code is fine. Consider `word-break: normal` too, so short identifiers don't get split in odd places on narrow screens.

## Good

- The guide is consistent with the code: the namespaces, the "no `using`" claims and the option defaults (`BeforeEnvironmentVariables`, the 30 s refresh, `Optional` only about reachability) match the sources.
- The security advice is correct and placed where people will see it: pin the GitHub Action to a commit, `env-prefix` is required so `PATH` can't be overwritten, `no-store` for secret reads plus `IStorytellerCacheProtector`, narrow machine scopes, and `-a` restriction.
- The cheat sheet's troubleshooting table (401/403 `AccessDenied` vs `AnnotationRestricted`, `X-2S-Secrets-Withheld`, unresolved `@` values) is very useful.
