# Review of PR #171: [fix(platform): short descriptions of sform story export/import and kv export/import (424-216)](https://github.com/akobr/mono.me/pull/171)

Reviewer: Harry · Review date: 2026-11-08

**Verdict: approve-ready.** The PR changes 12 files (+705/−14) in 6 commits. It is not draft and not trivial. The help-text work is mostly copy, but it carries a real runtime fix: `sform story kv` crashed on every invocation, including `--help`, because McMaster could not resolve the optional `TimeProvider?` of `KeyValueListCommand`. `Startup` now registers `TimeProvider.System`, and a new `StartupTests` guards the whole command tree against the same class of bug. I checked the facts in the four detail texts against the code (`KeyValueFormats.Detect`, `KeyValueImportCommand`, `ExitCodeOf`, `WriteImportResult`) and against `key-values.md` § Who may do what, and they hold. Nothing blocks the merge.

**CI at review time:** on `e2b8a1cf`, the only check was CodeRabbit (in progress, no findings yet). There were no legacy statuses and no .NET workflow run on the head yet. The PR says 1,084 Cli tests pass (1,125 on a trial merge with `main`). I did not build or run the tests myself.

## Blocking

None.

## Important

1. **`StartupTests` checks registration, not resolvability.** `EveryCommand_ResolvesFromTheServicesOfStartup` (`src/Platform/Cli/test/StartupTests.cs`, `IsResolvable` near the end) only asks `IServiceProviderIsService` whether each constructor parameter type is registered. It does not check whether the registered implementations can be built. A future `CommandContext` or `TransferPolling` that depends on something unregistered would pass this test and still crash `sform` the same way. Suggested fix: keep the current test as a fast guard and add one that builds the provider with `new ServiceProviderOptions { ValidateOnBuild = true, ValidateScopes = true }`, with the host and McMaster types from `Provided` registered as fakes. If `ValidateOnBuild` trips on the SDK's `HttpClient` factories, resolve each command's constructor parameters through `provider.GetRequiredService` instead. Not a reason to hold this PR, because the bug it fixes is covered either way.

2. **The root cause is the optional constructor parameter, and nothing stops the pattern from coming back.** `KeyValueListCommand` (line 33) still has `TimeProvider? timeProvider = null`. McMaster ignores default values, so any future command that copies this test-seam pattern with a type that is not registered will crash its whole subtree again. `StartupTests` would catch it, which is the point of that test. A cheaper guard is to say it at the call site. Suggested fix: make the constructor parameter non-optional (`TimeProvider timeProvider`), since it is now registered, and have the tests pass `TimeProvider.System` or a `FakeTimeProvider`. Alternatively, add a one-line comment on the constructor pointing at the `Startup` registration. Either way, the next reader will not assume the default protects them.

## Nits

1. **The kv import help could mislead about `-y` and the view-name prompt.** `KeyValueImportCommand.HelpDetail` says "-y skips the confirmation … A replace that deletes keys asks you to type the view name." In the code, `if (!Yes && !await ConfirmAsync(plan))` means `-y` also skips the view-name prompt, which lives in `ConfirmAsync`. The internal review refuted this as a finding. Still, a reader in a CI script will want it spelled out. Suggested wording: "A replace that deletes keys asks you to type the view name, unless -y is given."

2. **The kv export help leaves out the actor restriction.** "the values of secrets need ContributorWithSecrets" skips the `NoSecretReveal` condition, which the table in `key-values.md` (row "Export with secrets") attaches to the same right. That is fine for a help summary. If there is room, add "(not through an actor under NoSecretReveal)" or "see key-values.md". Optional.

3. **The refusal exit code is missing from the kv help.** The import detail now names `2` and `45`, but not `44`. `ExitCodeOf` maps a `403` to `44`, and that is what a Contributor without secret rights gets for an import that carries secrets. One clause ("a refusal exits with 44") would make the exit-code list complete. Otherwise, drop the codes from the help and point to `key-values.md`.

4. **Tests depend on each other through a helper.** `StorytellerTransferCommandTests` calls `TransferHelpTests.Unwrap` (an `internal static` on another test class). Move `Unwrap`, and ideally `Lines`, into a small `HelpText` test helper, so a refactor of one test class does not break the other.

5. **Role suffixes are now inconsistent across `sform`.** The two view commands now end with "(for administrators)", while other `sform` descriptions still end with "(Administrator)", as the spec notes. The issue asked for this wording, so this is not a change request. Consider a follow-up that aligns the rest, so the parent lists read the same everywhere.

6. **The `Startup` comment is broader than the fix.** "Constructor injection of McMaster resolves every parameter, also one with a default value (KeyValueListCommand)." This is accurate, but it explains McMaster rather than the registration. "Needed by KeyValueListCommand: McMaster ignores parameter defaults" reads faster. Cosmetic.

## Good

- **The crash is the most valuable part of the PR.** The author found it by running the built tool rather than trusting the unit tests, which create commands with `new` and could never have seen it. The PR description explains the mechanism precisely: McMaster creates the parent model for any subcommand, so the whole `kv` subtree failed.
- **`StartupTests` walks the real `[Subcommand]` tree from `PlatformCommand` and asserts it contains `KeyValueListCommand`,** so the test cannot pass vacuously.
- **The detail texts are grounded in the code.** The `.env`, `*.env`, `.env.*` before `*.json` order matches `Detect` exactly. `2` for an invalid plan (`400` → `ExitCodeOf` → `ERROR_WRONG_INPUT`) and `45` for a failed write (`WriteImportResult` → `WARNING_PARTIAL_RESULT`) match the code paths. The scopes per kind match `export-import.md` § Access. I measured the longest detail lines at 75–78 characters, under the 79 limit.
- **`TransferHelpTests` tests the rendered help, not just the attributes.** It checks the parent list at 80 columns, the footer placement after `-?|-h|--help`, the line width, and the option and argument templates. That is how a "nothing of the old text is lost" claim should be held. Using raw string constants as attribute arguments keeps the source WYSIWYG, and the line-ending normalization in `Lines`/`Unwrap` keeps the tests stable on CRLF checkouts.
- **The docs moved with the code.** `export-import.md` no longer quotes the old sentences, and `key-values.md` now states the export guess by name only, plus the `2` vs `45` distinction.
