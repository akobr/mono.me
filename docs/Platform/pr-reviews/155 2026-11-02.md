# Review of PR #155: [feat(platform): test cases of the admin UI and their automation (424-152)](https://github.com/akobr/mono.me/pull/155)

Reviewer: Harry · Review date: 2026-11-02

**Verdict: needs changes.** The suite itself is careful, well-structured work, but the branch conflicts with `main` and has to be rebased. Several of `main`'s newer changes to the user pool and the defaults also make parts of this PR's docs and mock profile stale.

What I checked:

- The description, the full diff at head `ee13a10d` against `main` `307648f1` (225 files, +30163/−346, 86 commits), and a trial merge with `git merge-tree`.
- The runtime change in `UiTest`, the role model (`PlatformTest.Roles.cs`), `[MockOnly]`, the `RoleProjects` setting and its target check, and the helpers (`Eventually`, `MockApi`, `PageScripts`, downloads, second pages, disposable projects).
- The hosted-page sign-in (`PlatformTest.ACC.cs`), `AuditTrail` polling, and samples of the tests, including the ones that tolerate admin UI bugs and the organization tests.
- The workflow change, the mock settings, and the docs.
- CI: only CodeRabbit has a check run (still in progress), and the only comment is its placeholder. No build or test workflow has run on this head, and I didn't build it locally.

This PR has no Orleans or web API code. The C# concerns are async and cancellation, test isolation, secret handling and the public runtime API.

## Blocking

1. **The branch conflicts with `main`.**
   **Where:** GitHub reports `mergeable_state: dirty`. A trial merge conflicts in `CLAUDE.md` and in `docs/Platform/UI.Admin.AutomationTests/automation-tests.md`.
   **Fix:** Rebase onto `main` and resolve both files. Then re-run the mock suite at both the desktop and phone widths, because the numbers in the description were measured before `main`'s changes listed below.

2. **The PR's pool assumptions predate `main`'s pool changes.**
   **Where:** Since the branch was cut, `main` changed several things:
   - `581c2a16` defaults `Target:BaseUrl` to `http://localhost:5173`.
   - `f048c7f7` commits an 8-user pool to `src/testsettings.json`: 2 Owners, 2 Administrators, 2 Contributors and 2 Readers.
   - `1e7632c9` makes CI pass 8 pool passwords.
   - `aaffce8e` and `27da8bd4` make the highest layer that has an e-mail define the pool, and ignore password-only indices.

   `testsettings.json` auto-merges, but several things no longer match:
   - The comment in `testsettings.mock.json` (around line 30) justifies 8 mock users by "the user secrets of a deployed pool of up to eight users". Under `main`'s rule the mock layer defines the pool anyway and password-only indices are ignored, so that reasoning is outdated.
   - The description and the docs say CI maps six pool users. `main` now maps eight.
   - The recommended deployed pool in the docs (three Owners plus a ContributorWithSecrets) doesn't match the pool `main` committed (two Owners, no Contributor with secrets).

   **Why it matters:** `RequiredUser` and the pre-lease mock skip decide which tests run. A pool that differs from the documented one changes the skip counts and the lease contention for the 48 Owner tests at `MaxParallelTests: 4`, and nobody has measured that yet.
   **Fix:** After the rebase, reconcile the mock profile comment, `automation-tests.md` ("Configure" and the pool section) and `CLAUDE.md` with `main`'s committed pool. State what the Secrets and Owner tests need from that pool. Re-check that `[UserRole(Role.Secrets)]` and `[UserRole(Role.Contributor)]` resolve to a user, or skip with a clear reason, against the committed pool with an empty `RoleProjects`.

## Important

1. **Tests that accept both the buggy and the fixed behaviour hide regressions.**
   **Where:**
   - `Tests/Annotations/AnnotationCatalogTests.cs:124` and `:324` accept `^[12] annotations deleted$`.
   - `Tests/Configurations/ConfigurationCreateTests.cs:229` and `ConfigurationInheritanceTests.cs:55`.
   - `Tests/Modeling/ModelingSchemaTests.cs:22,153,432` and `ModelingTemplateTests.cs:26,101`.
   - `Tests/Settings/SettingsSecretsPolicyTests.cs:96`.

   **Why it matters:** Once the four admin UI bugs are fixed, nothing forces these assertions to become strict. Meanwhile a regression back to the buggy output stays green.
   **Fix:** Open a tracked issue for each bug and put its id in the comment instead of "424-152 review". Better still, assert the correct behaviour and mark these cases as expected failures or skipped with a link, so a fix turns them green on its own.

2. **The deployed path has never run.**
   **Where:** The description says the AuthKit hosted-page sign-in, the second-page writers, audit polling and the large views were only exercised against the mock.
   **Fix:** Before relying on the suite as a gate, run it once against a deployed target with `RoleProjects` mapped. Until then, note in `test-cases.md` which cases are mock-verified only.

3. **The sign-in helper's tracing can fail the wrong way.**
   **Where:** `PlatformTest.ACC.cs:77` drops the current trace chunk (`StopChunkAsync()` without a path). Line 96 only starts a new chunk when the page is back on the app or could be emptied. If neither works, `TestScope` (`UI.Automation.Runtime/src/TestScope.cs:341`) later calls `Tracing.StopAsync(path)` with no active chunk. Also, an exception from `StartChunkAsync` in the `finally` block would replace the redacted `SignInException`.
   **Why it matters:** That masks the real failure, and the trace from before the sign-in is lost on every traced run, even a passing one.
   **Fix:**
   - Save the pre-sign-in chunk to its own file with `StopChunkAsync(new() { Path = ... })` rather than discarding it.
   - Wrap the restart in a try/catch that records "trace not resumed" on the scope.
   - Confirm that `TestScope` tolerates a stopped trace. A unit test with a fake context would cover it.

4. **The request recorder keeps request bodies.**
   **Where:** `Support/PageScripts.cs` (`RequestRecorder`) wraps `fetch` and stores the method, URL and body in `window.__requests`. `WaitForRequestAsync` prints the recorded requests when it times out.
   **Why it matters:** On a deployed target those bodies include secret values. Secrets reveal and rotate, and exports with secret values, are exactly what several tests do. The bodies then end up in exception messages and in Playwright traces.
   **Fix:** Record bodies only when a test opts in. Otherwise store just the method and URL, and redact known secret fields in the timeout message.

5. **Created organizations and projects are never cleaned up.**
   **Where:** `CreateDisposableProjectAsync` (`PlatformTest.Helpers.cs`) and `Tests/Projects/OrganizationTests.cs:19-20` (ORG-ORG-01 creates an organization on every run), plus ORG-PRJ-01.
   **Why it matters:** On a shared deployed target every run leaves organizations and projects behind. Over time that fills the `/orgs` list that `PlatformTargetCheck.CheckRoleProjectsAsync` and the navigation tests read, and it may hit per-user organization limits.
   **Fix:** Add a cleanup step, either in an `[After(TestSession)]` hook that deletes what `Scope.Properties["disposableProject"]` recorded, or in a scheduled job that removes anything with the run prefix older than a day. Also mark ORG-ORG-01 and ORG-PRJ-01 as `DisposableProject` so they can be filtered out of runs against long-lived targets.

6. **`Eventually` neither backs off nor observes cancellation.**
   **Where:** `Support/Eventually.cs:38`, `catch (Exception exception) when (exception is PlaywrightException or TimeoutException && clock.Elapsed < Limit)`.
   **Why it matters:** An attempt that fails fast loops with no delay for up to 60 s. A closed page or a crashed browser is also a `PlaywrightException`, so it keeps retrying for a full minute instead of failing at once. The loop ignores the test's cancellation token, so a timed-out or cancelled test keeps driving the browser. `AuditTrail` (`Pages/AuditTrail.cs:122,137`) reloads the page on every attempt, so it isn't hot in practice today, but the type is general-purpose.
   **Fix:** Add a short growing delay between attempts (for example 250 ms up to 2 s). Pass and honor `TestContext.Current.CancellationToken`. Rethrow at once when `page.IsClosed` is true or the error is "Target closed".

7. **The `RoleProjects` target check is shallow.**
   **Where:** `PlatformTargetCheck.cs:141` (`CheckRoleProjectsAsync`).
   **Why it matters:** It signs in one sampled user and only checks the badge in the project link text. The optional view part of an `org/project/view` entry is never checked, so a missing view fails later inside a test instead of up front.
   **Fix:** Also open each mapped view, or at least the project's views list, and fail the check with the entry name.

8. **The runtime library gets a new public API.**
   **Where:** `UI.Automation.Runtime.TUnit/src/UiTest.cs` adds `protected virtual string? GetSkipReason(TestContext, AutomationSession)`, which `BeginUiTest` calls before `TestScope.Create`.
   **Why it matters:** The change is additive and covered by `UiTestTests.cs`, but the library is packable, so it needs a minor version bump and a changelog line.
   **Fix:** Bump the package version, and add an XML doc comment saying the hook runs before the user lease and must not touch the page.

## Nits

- `PlatformTest.cs:23`: the `Target` property calls `Settings.Bind<PlatformTarget>` on every access. `Routes`, `RoleProject` and `RequiredUser` read it many times per test, and each read copies the `RoleProjects` dictionary. Cache it in a `Lazy<>` or a field per instance.
- `PlatformTest.Roles.cs:121`: the role cache keys on `(Type, method name)`. With overloads that carry different `[UserRole]` attributes, the result depends on the order `GetMethods` returns them in. Either reject overloads or key on the `MethodInfo`.
- `Support/MockApi.cs` (`WaitForMockAsync`) uses the page's default timeout, so the "mock never came up" message only appears after whatever the action timeout is. Pass an explicit timeout.
- `DownloadAsync` reads the whole download into memory. That's fine for the current exports, but a size guard would keep a runaway export from blowing up the run.
- `MockOnlyAttribute.ShouldSkip` returns `false` when the settings are null. That's deliberate (the session isn't built yet), but a one-line comment would save the next reader from wondering.
- The `testsettings.json` comment should point to the new `RoleProjects` section of the docs.

## Good

- The pre-lease skip (`GetSkipReason` before `TestScope.Create`) is the right shape. Phone-only, desktop-only and missing-role cases don't hold a pool user, and they don't produce traces or videos.
- The hosted-page sign-in is careful with secrets: input is typed rather than filled, pre-sign-in steps are kept out of the trace, inputs are emptied after a failure, and the e-mail and password are redacted in every encoded form (`PlatformTest.ACC.cs`).
- Generated names get a hex prefix and are seeded per session, test and attempt (`SeededData`), so retries and parallel runs don't collide.
- The init scripts are idempotent, and the wait helpers' timeout messages say what was expected and what was seen.
- `PlatformAutomationSetup.CheckRoleProject` validates the role names and the `org/project[/view]` shape at startup.
- Pinning the mock UI to `127.0.0.1:4174` in the workflow avoids the IPv6 localhost resolution trap.
- The description and `test-cases.md` are thorough: a verification table, honest gaps, and the bugs found are written down instead of silently worked around.
