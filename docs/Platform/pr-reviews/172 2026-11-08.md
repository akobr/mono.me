# Review of PR #172: [feat(platform): read the name of an sform -x property as a path (424-213)](https://github.com/akobr/mono.me/pull/172)

Reviewer: Harry · Review date: 2026-11-08

**Verdict: approve-ready, with one important fix worth making first.** The PR changes 16 files (+1,806/−31) in 7 commits. It is not a draft. It adds a JSON path parser (`JsonPaths.Parse`, `ParsePrefix`, `Of`, `JsonPathFormatException`) next to the existing printer in ConfigurationFormats, and `sform story config set` / `template set` now write each `-x path=value` into the built document at its path. ## Important

1. **Names are matched case-sensitively, but configuration keys are not.** `InlineProperties.Apply` looks up `obj[segment.Name!]` and `Put(JObject, …)` uses `obj.Property(name, StringComparison.Ordinal)` (`src/Platform/Cli/src/Commands/InlineProperties.cs`, the object branch of the walk and `Put`). `DocumentFlattener` validates and flattens with `StringComparer.OrdinalIgnoreCase`, "as IConfiguration compares keys". So `-i app.json -x "Logging.LogLevel.Default=Warning"` over a file with `"logging": { … }` builds a document with both `logging` and `Logging`. `sform` does not catch that, so it reaches the API, which either rejects it as a duplicate path (a server error instead of the clean exit 2 the PR promises for wrong input) or stores two spellings that collapse into one key. Before this PR the risk was limited to top-level names. Now that `-x` writes into nested objects from the `-i` file, it is the most likely user mistake. Suggested fix: look up the existing property with `StringComparison.OrdinalIgnoreCase` and keep the existing spelling, both in the walk and in `Put`. That matches how the value will be read. Add tests for `-x Db.Port=1` over `{"db":{"host":"x"}}` and for two `-x` with different casing. If you'd rather refuse it, throw a `WrongInputException` naming both paths, but merging is what an IConfiguration user expects.

2. **`-x "hosts[0]=x"` does not do what it reads like on a stored configuration.** The new docs say this plainly. Without `--replace`, the API joins arrays, so `hosts[0]=x` adds `x` instead of replacing the first item, and `list[0].name=n` adds a new object. That is honest documentation of a surprising result, but a CI script will not read the docs. Suggested fix: when a path holds an index and `--replace` is not set, write one line to standard error, for example "an index in -x builds the array of the sent document; the API joins it with the stored array, so use --replace to set items". Alternatively, say it in the `-x` help text, which is where people will look. It is cheap and prevents a real mistake.

3. **Breaking change for colon-style names.** `-x "Logging:LogLevel:Default=Warning"` is the natural IConfiguration spelling. Before, it was stored as a top-level property with that name. Now it fails with exit 2. The hint "':' does not separate names: write a.b" is good, and the release notes cover dotted names. Please also name the colon case explicitly in the release notes and the "Changed" paragraph of `sform.md`, because that is the form people paste from `appsettings` docs and environment variables. Also check whether the next `sform` version should be a minor or major bump under the repo's versioning, since existing scripts that passed `a.b=1` will now silently set `{ "a": { "b": 1 } }` instead of failing.

## Nits

1. **`\uXXXX` accepts a lone surrogate.** `ReadHexCodeUnit` returns any code unit, so `['\uD800']` produces a name that is not valid UTF-16. It is later serialized as U+FFFD or rejected by the API. Refuse a high surrogate that isn't followed by `\uDC00`–`\uDFFF` and a lone low surrogate, with a `JsonPathFormatException` at the backslash. The printer never writes one, so the round trip is unaffected.

2. **`InlineProperties` is both a class and a property name.** `ConfigSetCommand` and `TemplateSetCommand` have a `string[]? InlineProperties` property. Today only `JsonInputBuilder` calls the static class, but any future call inside a command needs `Commands.InlineProperties.Apply(...)`. A name like `InlinePropertyWriter` avoids the trap.

3. **The public `Apply` has no argument checks.** `InlineProperties.Apply(JObject, IReadOnlyList<string>)` is public and dereferences both arguments. Add `ArgumentNullException.ThrowIfNull` for both, as `JsonPaths.Parse` does.

4. **`-x` values and `-i` values now type dates differently.** The `-i` file is read with `DateParseHandling.None`, so a date-like string stays a string. That is right and matches the SDK. `PropertyValueParser` still turns `-x when=2026-11-08` into a `DateTimeOffset`. The PR keeps this "as before" on purpose and tests it. It may be worth one sentence in `sform.md` so nobody is surprised that the same text becomes a date from `-x` and a string from `-i`.

5. **`JsonInputBuilder.JsonMergeOptions` now only applies to the file.** Its `MergeArrayHandling.Union` and null handling no longer affect `-x`, since nothing is merged anymore. A one-line comment saying it only copies the `-i` file into the empty document (dropping top-level nulls) would save the next reader a trip through Newtonsoft's merge code.

6. **Repeated path printing on error paths.** `JsonPaths.Of` builds the path by string concatenation, and `Take` allocates an iterator. That only runs when building an error message, so it doesn't matter for performance. Mentioning it only so nobody moves it into a hot path later.

## Good

- **The parser lives next to the printer, and the round trip is tested.** `Parse(Of(steps))` is checked against 2,000 seeded random step lists and the conformance vectors, so the syntax people copy from an error message is guaranteed to parse back. That is the right design.
- **`ParsePrefix` reads the path before looking for `=`.** That makes `-x "['a=b']=c=d"` work correctly and avoids the classic `Split('=', 2)` bug for bracketed names.
- **The error messages never include the value.** `AMessage_NeverHoldsTheValue` covers secrets that look like tokens, base64 and a `::warning::` injection attempt. The shell hints for stripped quotes (`a[b.c]`) and an expanded `$binding` (`['']`) are targeted and precise.
- **The walk is careful about Newtonsoft quirks.** Replacing by remove and insert instead of the indexer avoids the case where `JValue` equality drops a date with another offset, and `AReplacedProperty_KeepsItsPlace` keeps property order stable. Existing containers are entered by reference, so nothing is copied.
- **Strict index rules.** No leading zeros, an `int.MaxValue` cap checked in `long`, and an index past the end is an error rather than a sparse array. A typo cannot blow up the document.
- **Good docs.** The "Write a configuration" section in `sform.md` covers the syntax, the errors, what the API's merge does with arrays, and quoting for bash, zsh, PowerShell and Actions. The warning that the NuGet `sform` silently stores `db.port` as a flat name is helpful.
