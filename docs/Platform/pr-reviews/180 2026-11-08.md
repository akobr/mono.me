## Why the diagnosis is right

On Unix, .NET's `Console` asks the terminal for the cursor position (`ESC [ 6 n`) when Sharprompt reads `CursorTop`/`CursorLeft`, then reads the `ESC [ r ; c R` reply from stdin. util-linux `script` only copies bytes, so nobody answers and .NET eats the test's keystrokes while waiting. Answering the query from a cursor model fed by the pty output is the correct fix, and serialising answers and test input through one `SemaphoreSlim` (`ScriptChild.cs:68-79`, `:106-125`) correctly keeps a report from landing inside a key sequence.

## Blocking

- **Superseded by the base branch, and conflicts with it.** `origin/feat/424-215` now has `Running/Processes/TerminalResponder.cs` plus a rewritten `ScriptChild.cs` (commit `8aacc672`). Merging this PR means resolving a conflict in `ScriptChild.cs` and choosing between two trackers. ## Important

- **No application cursor-key mode (DECCKM).** The base fix also rewrites arrows to `ESC O A..D` after `ESC [ ? 1 h`, because .NET switches the keypad to application mode. This PR keeps sending `ESC [ A..D`. It happens to pass here (the `.NET` key parser accepts both forms today), but a real terminal would send `ESC O x`, so the harness is less faithful. If anything from this PR survives, keep the responder's `Keys` rewrite.
- **The new tests are the most valuable part, and the base fix has none.** `TerminalCursor_FollowsTextWrapsAndMoves` and `TerminalCursor_AnswersEachPositionQuery` (`OutputSelfTests.cs:179-212`) cover pending wrap, CR/LF/TAB, CSI moves, save/restore, clamping, a query split across chunks, and private/other DSRs not being answered. Port them to `TerminalResponder` so its parser has coverage.
- **Behaviour worth porting into the responder:** pending wrap at the last column (`TerminalCursor.cs` `Print`, xterm-correct and matters for long prompts at narrow widths), TAB stops, `ESC 7/8` and `CSI s/u`, `CSI G/d/E/F`, and string sequences (OSC title etc.) being skipped up to BEL/ST. Check which of these `TerminalResponder` already handles before copying.

## Nits

- `OutputSelfTests.cs:176-178`: the new tests were inserted between the existing comment for `WrappedJson_FoldsAreJoined` ("WriteJson renders at 80 columns…") and that test, so the comment now sits above `TerminalCursor_FollowsTextWrapsAndMoves` and `WrappedJson_FoldsAreJoined` has lost it. Move the inserted block above that comment.
- `TerminalCursor.Csi` (`TerminalCursor.cs:296-308`): an `ESC`, `CAN` or `SUB` inside a CSI is ignored instead of aborting the sequence. With a truncated `ESC [` followed by `ESC [ 6 n`, the second `[` ends the first CSI and the query is missed, which would bring back the original hang. Rare, but cheap to handle: on `\u001b` switch to `State.Escape`, on `\u0018`/`\u001a` return to `State.Text`. Likewise `Escape` drops a second `ESC` (`ESC ESC [ 6 n`).
- "Every character counts as one column": wide (CJK, most emoji) and combining characters will drift the column. Fine for sform's prompts today; worth a one-line note in the class comment that a story name with emoji can shift the reported column.
- `CSI r` (scroll region, also homes the cursor) and the alternate screen (`CSI ? 1049 h/l`, which saves and restores the cursor) are not followed. Sharprompt doesn't use them; mention it in the comment so nobody is surprised later.
- `ScriptChild`: the `SemaphoreSlim` is never disposed (harmless since `AvailableWaitHandle` isn't used, but the base version disposes it). If `RedirectedChild.Start` throws after output arrived, `started` is never completed and any `TypeAnswerAsync` waits forever; `child.started.TrySetException(...)` in a catch would close that.
- `TypeAnswerAsync` is fire-and-forget; an exception outside the three filtered types would go unobserved. Acceptable in a harness, but a `catch (Exception)` that writes to the sink as a harness note would make a future failure visible.

## Good

- Clear, reproducible root-cause write-up, including a minimal Python driver that answers DSR and makes `sform assist key` succeed under the same `script` command line.
- No test, assertion or timeout loosened, and ConPTY untouched.
- `TerminalCursor` is a small, readable state machine: handles chunk-split sequences, the C1 CSI (`\u009b`), private CSI prefixes, surrogate pairs, and clamps to the pty size.
- The `started` TaskCompletionSource with `RunContinuationsAsynchronously` correctly handles output arriving before `Start` returns, without running the write on the pump thread.
- Docs in `automation-tests.md` updated alongside the code.
