## Important

1. **Router hook: deprecated name, which a newer hook silently overrides.** `docs/42for.net/.vitepress/theme/analytics.js` L154–160 wraps `router.onAfterRouteChanged`. In VitePress 1.6.4 (the version in `pnpm-lock.yaml`), that property is `@deprecated`, and the router calls `(router.onAfterRouteChange ?? router.onAfterRouteChanged)?.(href)` in both `go()` and the `popstate` handler. If anything sets `onAfterRouteChange`, this hook is never called and SPA navigations stop counting, with no error. That could be a future theme change, a plugin, or a VitePress upgrade that drops the alias. The deployed build uses rc.35 from `package-lock.json`, so the old name can't simply be swapped for the new one. **Fix:** chain whichever hook is present and set both, for example:
   ```js
   const previous = router.onAfterRouteChange ?? router.onAfterRouteChanged
   const hook = async (to) => { await previous?.(to); await nextTick(); capturePageview() }
   router.onAfterRouteChange = hook
   router.onAfterRouteChanged = hook
   ```
   (`??` makes sure it runs only once.) Better still, fix the lockfile drift (below) so only one VitePress version is in play.
2. **Shared PostHog project versus the "30 days" in the privacy text.** L6–7 reuses the project token of `sform` and the admin UI's local runs. The privacy text in the spec review (section 5) promises website visits are kept 30 days. Retention in PostHog is set per project, not per event source. Check that this project's retention really is 30 days and that it suits `sform` too, or use a separate project for the site. A separate project also keeps CLI telemetry dashboards free of `$pageview` noise. Mixing them works only as long as everyone filters on `$host` or `environment`.
3. **The Do Not Track / GPC gate was only tested by hand.** The pure helpers `pageOf` (L36), `scrubUrl` (L42) and `scrubEvent` (L73) carry the privacy guarantees. The Playwright run in the review doc wasn't committed, so a later edit to the regexes (L17–23) can quietly leak a click id. Add a small unit test, for example with Node's built-in `node:test` (no new dependency). It should cover: `/x`, `/x.html` and `/x/index.html` resolving to one page; a cross-site URL becoming its origin; a same-site URL losing its query and hash; and the `$session_entry_utm_*` and `$initial_gclid` properties being dropped. To make that possible, export the helpers.
4. **The two lockfiles drift apart even more.** `package-lock.json` (which Oryx deploys from) pins VitePress rc.35 and resolves `dompurify` 3.4.18. `pnpm-lock.yaml` has VitePress 1.6.4 and `dompurify` 3.4.16. The PR documents this as out of scope, which is fair. But item 1 exists only because of it, and Playwright tested the build from whichever lockfile was installed locally. State which VitePress version the browser check ran on, or open the follow-up now and keep one lockfile.

## Nits

- **`defaults: '2026-05-30'` (L101).** posthog-js ignores unknown options silently. Pin the `posthog-js` version exactly, not `^1.450.0`, so a minor release can't change what this `defaults` snapshot or any explicit opt-out means without a lockfile diff. That matters for a privacy promise.
- **Bundle.** 133 KB gzip of SDK for one `POST /e/` per page. It's lazy and never awaited, so first render isn't affected, but a plain `fetch` to the capture endpoint with your own scrubbing would be a tiny fraction of that. It would also remove PostHog's start-up storage probes (`__mplssupport__`, `ph_debug`, `__ph_opt_in_out_*`) and the `#__posthog=` toolbar write that the lawyer note has to explain. Worth a discussion, not a change in this PR.
- **`scrubUrl` returns `undefined` on a parse failure (L51).** That's fine, since the property disappears from the JSON. Add a short comment saying it's deliberate, so nobody "fixes" it to return the raw value.
- **IP address.** If approximate location isn't needed, turn on PostHog's project setting to discard client IP data. Then the privacy text gets simpler. (Owner decision.)
- **`theme/index.js`** is still missing its final newline, and the indentation is a mix of 4 and 6 spaces. Both predate this PR, but the file is being touched now.
- **Chunk-size warning.** The build log prints Rollup's chunk-size warning. It's probably pre-existing (Mermaid), but confirm that the PostHog chunk isn't the new offender.

## Good

- Gating before download (L149) is the right order: SSR via `import.meta.env.SSR`, then the host allow-list, then DNT/GPC. Forks, previews and `localhost` never request the chunk. `respect_dnt` stays on as a second guard for a signal turned on after load.
- Page dedupe with `pageOf` plus `lastPage` (L84–96) matches how VitePress resolves URLs, and hash-only navigation correctly sends nothing. VitePress's `popstate` handler already ignores `state === null`.
- The first-page race is handled: `capturePageview()` runs again once the chunk resolves (L162–167).
- `disable_beacon` was chosen so no posthog.com cookies are sent, with `person_profiles: 'never'`, flags and remote config off, and `disable_external_dependency_loading`. The only request is `POST /e/`.
- The spec, the four-lens review and the after-merge checklist (delete the GA property, privacy text, YouTube follow-up) are thorough and honest about what is still open.
