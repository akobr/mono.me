# Review of PR #150: [🐛 fix(platform): keep the Graph empty state below the legend and offer the create actions (424-130)](https://github.com/akobr/mono.me/pull/150)

Reviewer: Harry · Review date: 2026-11-01

**Verdict: approve-ready.** A clean, well-scoped admin UI fix: the empty and error states now sit in a flex column below the legend instead of covering it, the Graph page gets **New** and **Bulk create** through a new shared `AnnotationCreateActions` component, and an empty frame no longer overwrites the remembered layout. Nothing blocking; a few small follow-ups below.

**CI at review time:** "Lint, type-check, test, build" and CodeRabbit were still running. "Build and Deploy Job" failed within a minute; on earlier PRs that was the Azure Static Web Apps staging-environment limit, so it is probably unrelated, but worth a glance. I couldn't run the unit tests locally (no `node_modules` in my checkout), so I relied on reading them and on CI.

## Blocking

None.

## Important

1. **Keyboard guard covers only Enter** (`components/graph/AnnotationGraph.vue`, `onKeydown`, ~L510-531). The new `event.target === event.currentTarget` check stops Enter on a legend chip or an empty-state button from opening the active node, which is right. But the arrow keys still `preventDefault()` and move the active node while focus is on a chip, and Escape on a chip still closes the detail. Suggest applying the same "the event started on the wrapper" check at the top of the handler (return early when `event.target !== event.currentTarget`), so controls inside the graph keep all their native keys. A unit test like the new Enter one would cover it.
2. **Command palette still goes to Annotations from Graph** (`components/shell/CommandPalette.vue`, L102-114). Now that Graph mounts both dialogs, "New annotation" and "Bulk create annotations" from the palette still `router.push(.../annotations)` before `show()`. That works (the palette awaits the push, so the new `onBeforeRouteLeave` reset runs before `show()`), but it takes the user off the Graph they were on. Consider opening the dialog in place when the current route is Graph, or note it as intentional in the spec.

## Nits

1. **Duplicated dialog wiring** (`pages/[org]/[project]/[view]/annotations.vue` L55-63 and `graph.vue` L15-24). Both pages repeat the same two `open` refs plus the same `onBeforeRouteLeave` reset with the same comment. A small composable (for example `useAnnotationCreateDialogs()` that registers the guard and returns both refs) would keep the "a dialog left open must not reopen on the other page" rule in one place.
2. **Redundant `canEdit` check on the slot** (`graph.vue` L73). `AnnotationCreateActions` already renders nothing without `edit`, so `v-if="canEdit"` on `#empty-actions` is only there to keep `$slots['empty-actions']` empty for a Reader. That's fine, but a one-line comment would save the next reader from removing it.
3. **Legend above an error** (`AnnotationGraph.vue`, the new overlay column). When the catalog fails to load, `empty` is false, so the legend shows all-zero counts above the error state. That was true before as well; hiding the legend on `catalog.status === 'error'` would be tidier.
4. **Empty-frame early return** (`onFrame`, ~L351-355). The logic is right: `layingOut` is never set for a zero-node graph, and the next real frame now fits because `fitted` isn't flipped by the empty one. It relies on `layoutSeed` treating the empty `positions` array as "not the remembered frame", which holds, but it's subtle; a sentence in the comment pointing at `layoutSeed` would help.

## Good

- Moving the states into a `pointer-events-none` flex column, with `pointer-events-auto` only on the legend and the states, solves the overlap however many rows the legend wraps to, and keeps the canvas pannable around them.
- Extracting `AnnotationCreateActions` removes the duplicated header and empty-state buttons from Annotations, and the unit tests cover both variants, the shared open state and the Reader case.
- Calling the reset in `onBeforeRouteLeave` rather than on unmount is the correct choice, and the comment explains why (the palette opens the dialog before the old page unmounts). Nested detail routes under Graph don't trigger it, so opening the newly created annotation keeps the dialog flow intact.
- Good test breadth: unit tests for the reload keeping the layout, the empty view without a legend, "Every type is hidden" below the legend, and Enter on a control; e2e for bulk create and the first annotation on an empty Graph, Reader visibility, the Back case, plus visual snapshots in both themes and viewports. Docs (`admin-ui.md`, README) are updated to match.
