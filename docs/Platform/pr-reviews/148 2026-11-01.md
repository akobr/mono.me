# Review of PR #148: [feat: UI automation testing project for the admin UI (424-133)](https://github.com/akobr/mono.me/pull/148)

Reviewer: Harry · Review date: 2026-11-01

**Verdict: needs changes.** The framework is careful and well tested, but three paths can still send a pool user's session (cookies, tokens) or sign-in data somewhere public or third-party, and the run teardown has one non-exception-safe step. None of the real integrations (AuthKit, Testiny, BrowserStack, the GitHub environment, the workflow itself) has been exercised yet.

Checked locally on `879176db`: the three library test projects pass under `dotnet test` (Testiny 93, Runtime.TUnit 28, Runtime 220, 0 failures), and `UI.Admin.AutomationTests` builds clean in Release. CI doesn't run any of this (the traversals set `Test="false"` for the TUnit project and the workflow is hand-run only).

## Blocking

1. **Testiny uploads `trace.zip` by default.** `TestinyOptions.Attachments` defaults to `Failures`, and `testsettings.reporting-testiny.json` sets `"Attachments": "Failures"`, which sends `failure.png`, `trace.zip`, `console.log` and `video.webm` of every failed test to Testiny. Your own docs say a trace holds the pool user's session cookies and tokens, and the workflow goes out of its way to strip `*.zip` from the public artifact, yet the reporter ships the same file to a third-party SaaS. Exclude traces by default (e.g. `AttachTraces = false`, or an explicit kind list without `Trace`), and say in the Testiny docs that turning it on shares live sessions.
2. **`console.log` is written unredacted and uploaded everywhere.** `TestScope.cs:294-296` logs every browser console message and every `RequestFailed` URL, and `:346` writes them verbatim. Failed request URLs on an OAuth flow can carry `code`/`state` or tokens in the query, and app console output is outside your control. The file survives the "Keep the traces private" step (it only deletes `*.zip`, `ui-admin-automation.yml:337-340`), so it lands in the public artifact and in Testiny. Run the lines through `SecretRedactor` (with the pool passwords and the BrowserStack key) and strip query strings from `requestfailed` URLs.
3. **`upload_traces=true` publishes live sessions in a public repo.** The input (`ui-admin-automation.yml:38`, `:65`) skips the zip deletion on a deployed target, and Actions artifacts of a public repository are downloadable by anyone signed in. Remove the input, or gate it behind a separate protected environment with required reviewers, and keep the default path zip-free.

## Important

4. **`StopCoreAsync` isn't exception-safe** (`AutomationSession.cs:525-548`). If `Reporting.CompleteAsync` throws (Testiny down, cancellation), `BrowserProvider.DisposeAsync` never runs, so BrowserStack sessions stay open until their idle timeout and get billed or block the parallel limit for the next run. Wrap the reporting call in `try/finally` and dispose the provider in the `finally`.
5. **The cached stop task captures the first caller's token** (`AutomationSession.cs:347-353`, and the same pattern in `ReportingDispatcher.CompleteAsync`). `stopping ??= StopCoreAsync(cancellationToken)` means a second caller with a different token waits on the first caller's cancellation semantics. Run the core with `CancellationToken.None` and let each caller do `stopping.WaitAsync(cancellationToken)`.
6. **`Assertions.SetDefaultExpectTimeout` is process-global** (`AutomationSession.cs:150`). Fine for one session per process, but any test that sets its own default (or a second session in unit tests) races with it. Document "one session per process" on the type, or pass the timeout per `Expect(..., new() { Timeout = … })` through a helper.
7. **`RetryPolicy.WillRetryAsync` re-implements TUnit's internal retry decision** so that only the final attempt is reported. That's coupled to TUnit internals and will silently double- or under-report after an upgrade. Pin `TUnit`/`TUnit.Core` with a comment in `Directory.Packages.props`, and add a contract test that runs a failing `[Retry(2)]` test through the real engine and asserts exactly one report.
8. **Verify `concurrency.queue: max`** (`ui-admin-automation.yml:97`). If the key isn't accepted by GitHub's workflow schema, the whole file fails validation and the workflow can't be dispatched at all; it has never run, so nothing has caught it. Dispatch it once against the mock UI before merge.
9. **The `ui-admin-automation` environment needs a branch rule.** `workflow_dispatch` can be started from any branch, and that branch's version of the workflow gets the environment's secrets (pool passwords, Testiny and BrowserStack keys). Restrict the environment's deployment branches to `main` (and add required reviewers if you keep `upload_traces`).
10. **Test data is never cleaned up.** The admin tests create records named `at-<runId>` and delete nothing ("intended load"). Against a shared deployed target that grows without bound and eventually slows the lists the tests themselves read. Decide on a retention story: a nightly sweep of `at-*` older than N days, or a dedicated throwaway project per environment.
11. **Land it as a squash merge.** Commit `27fd74ea` doesn't compile on its own, and the branch is 21k lines in 14 commits; a squash keeps `git bisect` usable on `main`.

## Nits

- `StorageStateCache.cs:319-336`: the `sign-in-failure.png` screenshot can show the typed e-mail (and a visible password field if AuthKit ever renders it unmasked). Mask the inputs with `ScreenshotOptions.Mask` or blur the form before capturing.
- `StorageStateCache`: the per-user `SemaphoreSlim`s are never disposed. Harmless in practice, but make the cache `IDisposable`, or comment why not.
- `TestScope.cs:397`: `KeepSignInsAsync` uses `Pages[0]`, which throws or picks the wrong page if a test closed its first page or opened a popup first. Use the scope's main page reference.
- `TestScope`: tracing with `Sources = true` bloats every trace with the test sources; you don't need them for a UI repro. Also, a test that signs in on its own page records the password into its trace, since only the cache's sign-in runs untraced. Worth a sentence in the docs.
- `TestScope.Properties` exposes the `ConcurrentDictionary` as `IDictionary`; expose `IReadOnlyDictionary` plus a `Set` method, or keep the concrete type so callers see the concurrency contract.
- `UiAutomationSession.StartAsync` (`Runtime.TUnit`) rethrows every `OperationCanceledException`, including an `HttpClient` timeout (`TaskCanceledException`). Then every test fails with "session has not started" instead of the real cause. Filter with `when (context.SessionCancellationToken.IsCancellationRequested)`.
- `[ConfiguredRetry]` silently replaces an explicit `[Retry(n)]` on the same test. Either refuse the combination or let the explicit one win.
- `TestinyOptions` accepts `http://` for `BaseUrl`, and `X-Api-Key` is sent to whatever host is configured. Require `https` except for `localhost`.
- `BrowserStackBrowserProvider`: `AcquireAsync` checks `disposed` outside the gate, so a per-test browser connected while `DisposeAsync` runs isn't in `leases` yet and can leak; the `closing` list is never pruned. Take the gate for the check and add the lease before the connect returns.
- `SecretRedactor` replaces any non-empty secret, so a very short value (a 1-3 char test password) would mangle every log line. Ignore or warn about secrets below a minimum length.
- `ResultsFile` reopens `results.jsonl` on every append; a single `FileStream` held for the run (flushed per line) is cheaper.
- `ReportingDispatcher`'s pending counter can dip below zero briefly; harmless, but an `Interlocked` decrement guard or a comment would stop the next reader from chasing it.
- Artifact names embed the raw `profile` input. Validate it against a fixed list (`choice` input) so odd characters can't break the upload step.

## Good

The secret handling is genuinely thorough: `SecretRedactor` covers raw, URL-encoded and JSON-escaped forms, the BrowserStack key never reaches a log, and sign-in typing uses `PressSequentially` so BrowserStack's `sendType` masking applies. The workflow is hardened the right way (`permissions: contents: read`, `persist-credentials: false`, inputs only through `env`, secrets only in the `--no-build` Run step, an image/Playwright version check). `UserPool` is correct, reporting can never fail a test, `TimeProvider` and `IFileSystem` are injected everywhere, the Testiny client has a clean typed error split with a pooled `HttpClient`, and the 341 unit tests plus the two docs (`readme.md`, `automation-tests.md`) are unusually complete, including an honest account of the trace and token risk.
