## Important

- **The new user name won't reach accounts that already exist** (`src/Platform/Storyteller/DbCreator/src/Constants.cs:12`). `Data.SeedAccountAccessAsync` (`Backend.CosmosDb/src/Data.cs`) only sets `UserName` when it creates the account. On an existing account it changes only `AccessMap` (`account with { AccessMap = accessMap }`). This PR caps throughput, so DbCreator has already run in production per runbook 11.2. If it seeded the base account there, that account keeps `kobr.ales@outlook.com`. The staging `AuthKitOwner` (`SeedAccounts.cs:13`), which also uses this constant, has the same problem. If the stored value matters, fix it once by hand, or let the merge update `UserName`/`Name` when they differ. If only new environments need the new value, say so in the PR description.
- **Check the AuthKit staging user.** `SeedAccounts.AuthKitOwner` (`user_01M41P6G2TTSXXMM88WNVMRQKG`) now gets the user name `ales@42for.software`. Make sure that's the email of that AuthKit staging user. Otherwise the seeded user name won't match the identity. If they really differ, give `AuthKitOwner` its own literal.

## Nits

- **The comment above the parameter is now out of date** (`src/Platform/Deployment/parameters/prod.bicepparam:42-43`). It still reads as the "before" state ("No account-wide throughput limit until…"). Suggested wording: `// Capped at 1000 RU/s, the free tier, now that DbCreator has created core and organizations (runbook, phase 11.2); a capped account refuses containers without explicit throughput, so set -1 again before DbCreator has to create a container.`
- **Re-running DbCreator gets harder.** After this PR, any DbCreator run that has to create a container (a recreated database, the hierarchical-partition-key probe of step 5a, a new container later) will fail under the cap. The note above covers that. A line in the runbook's troubleshooting section would help too.
- **The old email is still in other places.** `kobr.ales@outlook.com` still appears in `Api.Web/src/Program.cs:103` and `Api.Functions/src/OpenApi/OpenApiConfigurationOptions.cs:25` (OpenAPI contact), and in the published `Sdk.NSwag/open.api.v0.8*.json` files. If the switch to `ales@42for.software` is on purpose, update the two contact blocks too. Leave the versioned OpenAPI snapshots as they are.
- **Check the what-if before the deploy.** Per the runbook, it should show only `capacity.totalThroughputLimit -1 => 1000` on `prod-2s-42fornet-cdb`. Merge only once `az cosmosdb sql container list` lists `core, organizations`.

The throughput change follows runbook 11.2 exactly (a PR to `main`, then `main.bicep`). The defaults in `main.bicep` and `modules/cosmos.bicep` are already 1000, so the parameter file now matches the template defaults.
