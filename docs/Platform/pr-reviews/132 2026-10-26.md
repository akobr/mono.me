# Review of PR #132: [MCP sign-in token exchange](https://github.com/akobr/mono.me/pull/132)

Reviewer: Harry · Review date: 2026-10-26

**Verdict: needs changes.** The RFC 8693 exchange itself is well built, but `NoSecretReveal` can be bypassed in two ways. Code was read only, since the review box had no `dotnet` and CI hadn't run on this stacked PR (it sits on #131).

## Blocking

1. **A delegated user can grant rights that include secrets.** `PostGrantPermission` in `AccessHttp.cs` (l.275-306) and `GrantPermissionAsync` in `CosmosAccessService.cs` (l.323) check neither the actor nor `NoSecretReveal`. An MCP agent that manages an account could grant `ContributorWithSecrets` to another account it controls and read secrets through it. The PR already guards machines (`EnsureActorMayGiveOutSecretReads`) and federation rules, but not this route. Add the same guard and a test. Invitations with a secret-bearing role may have the same gap (not verified).
2. **A delegated user can confirm a guessed secret value.** Under `NoSecretReveal` the caller loses the secret read right but keeps the write right. `IsSameValueAsync` (`CosmosKeyValueService.cs` l.735-744) decrypts and compares the value, so `SetAsync` returns no new version on a match, and a dry-run import reports `Unchanged` or `Update` per secret. That lets someone test PINs or default passwords in bulk. When the caller can't read secrets, skip the comparison and treat the secret as always changed.

## Important

3. Client assertion replay protection (`jti`) is kept in memory per instance, so an assertion can be reused on another instance within its 5-minute life. Use a shared store with a TTL, or shorten the lifetime to about 60 seconds and accept the risk.
4. The workload-identity proof has no reuse check and no age limit, so a Kubernetes or Entra token can live up to an hour. Add an `iat` max-age check.
5. An empty `AllowedClientIds` on an actor accepts a user token issued to any client, while the Keycloak validator refuses to start in that case. Require at least one entry, or log a startup warning.
6. Confirm whether delegated agents should keep the right to write and delete secrets. If not, removing it also closes finding 2.

## Nits

- The MCP side reads a missing `restrictions` claim as unrestricted. Default it to `NoSecretReveal`.
- Unknown scopes are dropped silently. Return `invalid_scope` or log them.
- Run the per-user throttle before the account lookup.
- Require `typ` to be `Bearer` for Keycloak tokens.
- The spec at line 11 still says Keycloak isn't supported.
- Add a migration note for the `Mcp:EntraId:*` to `Mcp:Authentication`, `Mcp:Actor` and `Storyteller:Scopes` config change.

## Good

No Keycloak container, realm export or real secret is committed. The strict check order, the `aud` taken from `PublicBaseUrl`, and the refusal of nested `act` are all solid. No tests cover findings 1 or 2.
