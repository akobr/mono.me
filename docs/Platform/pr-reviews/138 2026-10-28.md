# Review of PR #138: [Shared conformance vectors for configuration providers and SDKs, with CI and a gated SDK release (424-105)](https://github.com/akobr/mono.me/pull/138)

Reviewer: Harry · Review date: 2026-10-28

**Verdict: needs discussion.** The code is solid and nothing in it is blocking. Stacked on `feat/424-104`; 54 files, +4176/−95.

Neither new workflow has ever run. They only trigger on main or on PRs into main, and the only check so far is CodeRabbit, which skipped. The PR description says the `storyteller-sdk` environment and the `NUGET_API_KEY` and `NPM_TOKEN` secrets don't exist yet. The TypeScript side was run locally: `tsc --noEmit` is clean and vitest passes 322 tests with 1 skipped (on Node 20, while `.nvmrc` asks for 24). The .NET side couldn't be run (no SDK available).

## Important

1. **Run both workflows once before merging.** Use `workflow_dispatch` from a temporary branch or a throwaway PR into main, plus a dry-run release with `publish: false`.
2. **The gate doesn't cover KeyVault, but the release ships it.** The release packs `Configuration.KeyVault` (about l.83-85), but the conformance path filters leave out `Configuration.KeyVault/**` and `dotnet test` skips its `test` project. Add it, or drop it from the release.
3. **NuGet and npm handle a re-release differently.** `dotnet nuget push --skip-duplicate` (l.151) silently does nothing, while npm fails on a duplicate. Check for an existing NuGet version in the pack job like npm does, and drop `--skip-duplicate`.
4. **Lock the release down further.** The main-only check is good. Also restrict the `storyteller-sdk` environment's deployment branches to `main`, and consider pinning actions by commit SHA since this workflow handles publish tokens.
5. **`RefreshScenarioTests` uses a 1s real-clock timeout** (`TimeoutOfAHang`, about l.233), a flakiness risk on slow Windows runners. Raise it to about 5s or use a fake time provider.
6. **The two `ConformanceFiles` helpers have drifted.** One rejects duplicate property names but doesn't cache; the other caches but doesn't check duplicates. A duplicate key in a vector would fail in one runner and pass in the other. Share one linked source file.
7. **TypeScript can order keys differently from .NET.** `{"b":1,"0":2}` flattens to `0, b` in TS, but .NET keeps document order. `conformance.md` explains why the vectors avoid this, but the SDK README doesn't warn users.
8. **The CI TypeScript job skips lint and build.** Add at least `npm run build`.

## Nits

- `SuiteTests.cs` l.588 calls `Math.Abs` on a `long`, which throws for `long.MinValue`.
- The TS `readLeaves` is recursive, so a very deep document throws `RangeError` instead of `InvalidDocumentError`.
- `formatConfiguration` canonicalizes twice for `env`.
- `foldCase` hardcodes tables tied to .NET 10 / Unicode 16. Comment the version and add a drift vector.
- No vector covers the fixed-to-E-notation switch (`1E+16` vs `1E+17`).
- `publish-npm` checks out the repo but only needs the artifact.
- `errors.ts` now treats a blank `ErrorCode` as `undefined`, which deserves a changelog line.
- `prepublishOnly` only works from inside the repo. Add a comment.

## Good

The suite checks itself thoroughly, the same vectors run against .NET and TS, and the workflows are careful: inputs go through `env` only, no credential persistence, permissions are `contents: read`, and packages are packed once and published exactly as packed. The quickest unblock is item 1; after that and the KeyVault gap, approve-ready.
