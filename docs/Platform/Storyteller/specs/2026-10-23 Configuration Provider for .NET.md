# Configuration Provider for .NET

Linear: [424-85](https://linear.app/424fun/issue/424-85/create-config-provider-for-net-and-c).

## Problem

A .NET application that keeps its configuration in Storyteller has no way to load it. It has to call the API itself, flatten the JSON into `IConfiguration` keys, poll for changes, survive an outage of the platform and resolve its secret references. Every team would write that code again, and each copy would behave differently.

The issue asks for the reference provider of the shared integration contract (sections 3 and 5 of the platform study):
- **A configuration provider** (`IConfigurationSource`) bound to one configuration by its full key. It reads the `STORYTELLER_*` variables, polls with `If-None-Match`, keeps a last-known-good cache and supports `STORYTELLER_OPTIONAL`.
- **A dynamic binding.** The "currently active" key can change at runtime, and the configuration reloads.
- **Documents on demand.** A service in the container that a job calls to read any configuration while it runs.
- **Secret references resolved locally**, substituted automatically, as the substitution concept of the legacy implementation did.
- **`ETag`/304 support in the C# and TypeScript SDKs**, which the provider builds on. The study also asks the C# SDK for retries and a token provider for client credentials and federated tokens.

The server side of conditional reads exists ([Conditional Reads of Configurations](2026-10-17%20Conditional%20Reads%20of%20Configurations.md)). The prerequisite 424-51 (PR #126) makes the 304 of a document with bindings cheap; it does not change the API, so this change does not depend on its code.

## Current State

Paths are relative to `src/Platform/Storyteller`.

### Server contract of the two reads

- **Routes.** `GET v1/{organization}/{project}/{view}/configuration/{key}` (effective) and `…/configuration/{key}/resolved` (`Api.Functions/src/V1/ConfigurationHttp.cs:99-196`). The base URL includes `/api`.
- **Access.** A machine needs `Configuration.Read`. Secret values in the resolved read also need `Secrets.Read`, and an mTLS certificate when the project policy sets `RequireMtlsForSecretDelivery` (the default).
- **Tags.** Always weak, `W/"<e|r|b>.<22 base64url characters>"` (`Api.Functions/src/ConditionalReads/ConfigurationEntityTags.cs`). `If-None-Match` is parsed as a strict list with weak comparison; `*` matches; a header that does not parse is ignored and answers 200.
- **Headers, the same on a 200 and a 304, never on an error.** Both depend on the **caller's rights, not on the content**:
  - `ETag`;
  - `Cache-Control: no-store` when the caller may read secrets (resolved read), otherwise `private, no-cache`. A `Secrets.Read` machine with mTLS gets `no-store` even for a document without bindings;
  - `X-2S-Secrets-Withheld: mtls-required` on every resolved read of a machine that has `Secrets.Read` but no mTLS under a policy that requires it, whether or not the document has secret bindings (`Api.Functions/src/Security/HttpRequestDataExtensions.cs:131-135`, `ConfigurationHttp.cs:182-185`). The read still answers 200, with secret bindings left as written (`@…`).
- **Errors** (`ErrorResponse`: `Message`, `Hint`, `ErrorCode`; plain JSON, not problem details):
  - 400 for a key that does not parse;
  - 401 with an empty body;
  - 403 `AccessDenied` or `AnnotationRestricted`;
  - 404 with an **empty body** for a missing configuration, or `AnnotationDeleted`;
  - 422 `binding.evaluation` / `binding.limit.*` (resolved only);
  - 424 `CustomerKeyUnavailable`, 501, and 503 `KeyEncryptionUnavailable` with `Retry-After` (resolved only, not in the OpenAPI document).
  - `AnnotationInactive` and `MtlsRequired` never come from these two reads: a configuration of an inactive annotation still resolves, and withheld secrets are signalled by the header.
- **Bodies.** `Configuration` with `AnnotationKey`, `Version`, `Content` (a JSON object), `Modified`, `Hash`, `Labels`, `Values`. The resolved body keeps the effective `Version` and `Hash`. A version-0 configuration gets `Modified` = the time of the read, so only the tag is a change signal.

### Keys

- `Abstractions.Annotations/src/FullKey.cs:51,80` accept 5 to 7 segments, so the 8-segment full key of a unit of execution (`@org.project.view.uxe.subject.responsibility.context.unit`) does not parse. `AnnotationKey.IsValid` already checks the count per type.
- `TryParse` accepts an empty organization (`@.project.view.rst.x`). `Parse` throws `ArgumentNullException` for text without `@`.
- `FullKey.TryParse` and `Parse` have no callers; the provider is the first.
- There are no `FullKey` tests. `Backend.Core/test/AnnotationModelTests.cs` tests annotation keys with Shouldly.

### Machine credentials

- Only `sform` has them (`Platform/Cli/src/Authentication/*`):
  - API key, sent as `Authorization: ApiKey …`;
  - certificate;
  - client credentials, with AuthKit token-URL discovery for `client_` ids that also checks that the platform's provider is AuthKit (`MachineAuthenticationService.cs:619-640`);
  - federation: an RFC 8693 exchange at `v1/{org}/{project}/access/token`, with the subject token re-read before every exchange, or the GitHub Actions OIDC token when `STORYTELLER_CLIENT_ID` is a GUID and the `ACTIONS_ID_TOKEN_REQUEST_*` variables are set;
  - token file.
- Token cache: one gate, renewal 60 s before expiry, `expires_in` capped at a day, else the JWT `exp`, else five minutes. A refused token is dropped only if no newer one replaced it, so a burst of 401s renews once (`:423-431`).
- `http` is allowed only to `localhost` or a loopback address literal, never to a name that DNS resolves (`MachineSignInSettings.cs:117-124`).
- `sform` reads `STORYTELLER_API_URL`, `_API_KEY`, `_CERTIFICATE_FILE`, `_CERTIFICATE_PASSWORD`, `_CLIENT_ID`, `_CLIENT_SECRET`, `_TOKEN_URL`, `_TOKEN_SCOPE`, `_SUBJECT_TOKEN_FILE`, `_SUBJECT_TOKEN_TYPE` and `_TOKEN_FILE` (bearer, re-read before every request) (`docs/Platform/Storyteller/authentication.md:195-218`). `sform account machine create` prints these names.
- The issue's contract uses other names for three of them: `STORYTELLER_ENDPOINT`, `STORYTELLER_CLIENT_CERTIFICATE`, and `STORYTELLER_TOKEN_FILE` for "a federated token on disk".

### Secret references

- A key/value pair of a reference content type stores `kv://{vault}/{name}[/{version}]`, a vault secret URI, or the App Configuration `{"uri":…}` JSON (`Backend.Core/src/KeyValues/SecretReferences.cs`, `docs/Platform/Storyteller/key-values.md:88`). It is public.
- A binding puts the stored text into the resolved document as a plain JSON string (`Binding.Core/src/KeyValueBindingSource.cs`); the content type is lost. The platform never resolves a reference (`Backend.CosmosDb/test/ClientEncryptionAndReferenceTests.cs:221`). Accepted and rejected shapes are pinned at `:162-193`.
- The server parses a secret URI with `Uri` and checks only the scheme and the path, so it accepts any `https` host, a port, a query and user info. The TypeScript `parseSecretReference` accepts only `*.vault.azure.net` (`sdk.typescript/src/lib/key-values.ts:333-337`).

### Legacy implementation

The attached archive shows a simpler provider and a substitution library. The ideas worth keeping (no names or code are reused):
- **An updateable key holder** shared by the configuration source and the container, through which a service switches the key and reloads the whole configuration. The legacy holder lost the switched key on `IConfigurationRoot.Reload()` and did not serialize reloads.
- **One loader** used by the provider and by on-demand reads of jobs; the legacy code built throw-away provider instances for that.
- **Substitution through registered resolvers**, where the first resolver that accepts a value wins, a resolver can decline, and a failure is an error. The legacy library resolved lazily and synchronously inside the configuration indexer, over every source, cached failures forever and never saw a rotated secret.

`src/Libraries/Utils/Configuration.Substitute` is a port of that library. It triggers on a leading `@`, which is the Storyteller binding syntax and appears in effective and withheld documents; it is synchronous, untested and unused. It is not reused.

### Conventions that constrain the design

- **Namespace.** `_42.Platform.Storyteller.Configuration` is a type (`Abstractions.Annotations/src/Model/Configuration.cs`), and `_42.Platform.Storyteller.Configuring` is the server's namespace. A namespace named after either collides or confuses.
- **Packages.** In `Directory.Packages.props`:
  - `Microsoft.Extensions.Http.Resilience`, pinned to 10.0.5, which restores as 10.1.0 with NU1603;
  - `Azure.Security.KeyVault.Secrets` 4.9.0, `Azure.Identity`, `Microsoft.Extensions.Caching.Memory`, `Microsoft.Extensions.Hosting.Abstractions`;
  - `TestableIO.System.IO.Abstractions*`.

  `Microsoft.Extensions.Configuration.EnvironmentVariables` and `Microsoft.Extensions.TimeProvider.Testing` are not there.
- **Configuration framework (.NET 10).**
  - `ConfigurationProvider.Load()` is synchronous. `IConfigurationRoot.Reload()` calls it again on the same instance.
  - `ConfigurationManager.Sources.Insert`, and any later change of the sources or properties, builds and loads **new instances of every provider**, before it disposes the old ones.
  - `OnReload()` runs every `IOptionsMonitor` rebind synchronously on the calling thread, and an exception in a rebind propagates out of `OnReload()`. A failed rebind leaves `CurrentValue` throwing until the next change.
  - `IConfiguration[key] = value` calls `Set` on every provider.
  - The unprefixed `EnvironmentVariablesConfigurationSource` is the last environment source in `Host.CreateApplicationBuilder` and `WebApplication.CreateBuilder`; only the command line comes after it.
  - The host disposes `ILoggerFactory` before `IConfiguration`.

## Proposed Changes

The work is delivered in three phases, each in its own commits:
- **Phase 1** (sections 1-4): the SDK and key-parsing prerequisites.
- **Phase 2** (sections 5-12): the provider. It also adds the public resolver contract of section 13 (`ISecretReferenceResolver`, `SecretResolutionException`, the `ReferenceResolver` option), so that the options compile; substitution itself is Phase 3.
- **Phase 3** (sections 13-16): substitution, the Key Vault resolver, documents on demand and the documentation.

Tests are listed in section 17; build and verification in section 18.

**Local URL rule**, used wherever a URL is checked below: absolute; `https`, or `http` only when the host is `localhost` or an IP loopback literal (`127.0.0.1`, `[::1]`), never a name that DNS resolves (so not `http://loopback`); no user info. A trailing slash is ignored.

### 1. Full keys with eight segments (`Abstractions.Annotations`)

- `FullKey.TryParse` and `FullKey.Parse` accept 5 to 8 segments: three for the scope plus the 2 to 5 of the annotation key. `AnnotationKey.IsValid` stays the check per type, so an 8-segment key whose annotation is not a `uxe` still fails.
- Both reject an empty organization, project or view.
- `Parse` throws `FormatException` with the reason, instead of `ArgumentNullException` or `ArgumentOutOfRangeException`. It has no callers.
- New `Backend.Core/test/FullKeyTests.cs`:
  - a 7-segment `exe` and an 8-segment `uxe` key parse, and their parts are right;
  - an 8-segment `exe…` key, a 9-segment key, an unknown type code, a missing `@` and an empty organization fail;
  - `FullKey.Create(…).ToString()` parses back to the same text, for every annotation type.

### 2. Conditional reads in the C# SDK (`Sdk.NSwag`)

New hand-written file `Sdk.NSwag/src/ApiSdk.Conditional.cs`, a `partial` of `ConfigurationsApiClient` and of `IConfigurationsApiClient`.

**Methods.**
```csharp
Task<ConditionalResponse<Configuration>> GetConfigurationConditionalAsync(
    string organization, string project, string view, string key, string? ifNoneMatch, CancellationToken cancellationToken = default);
Task<ConditionalResponse<Configuration>> GetResolvedConfigurationConditionalAsync(
    string organization, string project, string view, string key, string? ifNoneMatch, CancellationToken cancellationToken = default);
```

- They join the existing partial interface `IConfigurationsApiClient`, so DI consumers see them without a new registration. No class in the repo implements the interface by hand, and the Moq mock still compiles. An external implementer of the interface would break; the SDK is `0.9-alpha`.
- **Request.** The route is built like the generated method: `BaseUrl`, `v1/`, then each segment through `Uri.EscapeDataString(ConvertToString(…))`, and `/resolved` for the resolved read. The hook order of the generated code is kept:
  1. `PrepareRequest(client, request, urlBuilder)`;
  2. set `RequestUri`;
  3. `PrepareRequest(client, request, url)`, which applies authorization;
  4. send with `ResponseHeadersRead` and the caller's token;
  5. `ProcessResponse`.

  A non-empty `ifNoneMatch` is added unchanged with `TryAddWithoutValidation("If-None-Match", …)`.
- **Answer.** 200 reads the body with `ReadObjectResponseAsync<Configuration>`, so `DateParseHandling.None` holds. 304 returns no body. Every other status throws what the generated method throws for it: `ApiException<ErrorResponse>` for 400, 403, 404 with a body, 422 (resolved) and 500; a plain `ApiException` for 401, a 404 without a body and anything unexpected. The messages are copied from the generated methods.
- **No state** is kept in client fields; one client instance serves concurrent calls.

**Result type** (new `Sdk.NSwag/src/ConditionalResponse.cs`, immutable):

| Member | Meaning |
| --- | --- |
| `int StatusCode` | 200 or 304 |
| `bool IsNotModified` | `StatusCode == 304` |
| `TResult? Result` | the body of a 200, `null` on a 304 |
| `string? ETag` | the raw `ETag` header value, weak prefix included, for sending back as it is |
| `string? CacheControl` | the raw `Cache-Control` value, `null` when absent |
| `bool IsNoStore` | `Cache-Control` contains `no-store` |
| `string? SecretsWithheld` | the value of `X-2S-Secrets-Withheld` |
| `IReadOnlyDictionary<string, IEnumerable<string>> Headers` | all response and content headers, copied before the response is disposed, case-insensitive keys |

The generated `GetConfigurationAsync` and `GetResolvedConfigurationAsync` do not change.

### 3. Credentials and resilience in the C# SDK (`Sdk.NSwag`)

New folder `Sdk.NSwag/src/Credentials`, namespace `_42.Platform.Storyteller.Sdk.Credentials`. The SDK gains these package references:
- `TestableIO.System.IO.Abstractions` and `.Wrappers`, for file reads;
- `Microsoft.Extensions.Http.Resilience`, which the study names for the SDK transport.

It also gets `InternalsVisibleTo` for its new test project. CLI code is the behavioural reference only; there is no dependency in either direction, and `sform` keeps its own code.

**`StorytellerCredential`** (abstract, immutable):
```csharp
ValueTask<AuthenticationHeaderValue?> GetAuthorizationAsync(AuthenticationHeaderValue? rejected, CancellationToken cancellationToken);
virtual X509Certificate2? ClientCertificate { get; }      // the mTLS certificate, if any
virtual bool CanRenew { get; }                           // whether a rejected value can be replaced
StorytellerCredential WithClientCertificate(X509Certificate2 certificate);
virtual StorytellerCredential Bind(StorytellerCredentialBinding binding);
```

- **`rejected`** is the value the API refused, or `null` for a normal call. A cached token is dropped only when it equals `rejected`, so a burst of 401s renews once, as in `sform`.
- The type is public and abstract, so an application or a test can implement its own credential.
- **`Bind`** returns a copy that knows the context of its requests. It returns `this` for kinds that need none. `StorytellerCredentialBinding` (public, immutable) has:
  - `Uri Endpoint`, the API base;
  - `string? Organization` and `string? Project`, the target project;
  - `Action<SocketsHttpHandler>? ConfigureHandler`, for proxies and TLS on token and discovery requests;
  - `TimeProvider? TimeProvider`;
  - `StorytellerResilienceOptions? Resilience`.

  Federation needs the endpoint and the project; AuthKit discovery needs the endpoint. A value set in the credential's own options wins over the binding's; the binding fills what they left unset. The provider and the document service always bind with their validated options, so a key or endpoint set in code wins over the environment.
- **Unbound.** A credential that needs a binding and has none falls back to `STORYTELLER_ENDPOINT` (fallback `STORYTELLER_API_URL`) and to the organization and project of `STORYTELLER_KEY`, split as `@{organization}.{project}.…` without a reference to `Abstractions.Annotations`. Without them it throws `StorytellerAuthenticationException` (`Configuration`).

Factories:

| Factory | Authorization |
| --- | --- |
| `FromApiKey(string apiKey)` | `ApiKey <key>`; a leading `ApiKey ` and whitespace are removed |
| `FromCertificate(X509Certificate2)` | none; the certificate only |
| `FromClientCredentials(ClientCredentialsOptions)` | `Bearer` from a `client_credentials` token request |
| `FromTokenFile(string path, IFileSystem? fileSystem = null)` | `Bearer` with the file's content, read again before every request; a leading `Bearer ` is removed |
| `FromFederatedTokenFile(FederatedTokenOptions)` | `Bearer` from an RFC 8693 exchange of the subject token in the file |
| `FromEnvironment(…)` | see below |

- `WithClientCertificate` combines a certificate with an API key; that is the only combination with a certificate, as in `sform`.
- **Certificates** load through `StorytellerClientCertificate.Load(path, password, IFileSystem?)` with `X509CertificateLoader.LoadPkcs12` and the default key storage flags (Windows cannot use an ephemeral key for client authentication). A certificate without a private key is rejected.
- **Client credentials** (`TokenUrl?`, `ClientId`, `ClientSecret`, `Scope?`, `Endpoint?`): a form POST of `grant_type=client_credentials`, `client_id`, `client_secret`, and `scope` when set.
- **AuthKit discovery**, without `TokenUrl`, only for a client id that starts with `client_`:
  - an anonymous `GET {endpoint}/v1/auth/configuration` on the token client (no redirects, local URL rule);
  - it requires `Provider == AuthKit` and an `https` `AuthKitDomain` without path, query or user info;
  - it posts to `{AuthKitDomain}/oauth2/token`, and caches the discovered URL per endpoint;
  - any other client id without `TokenUrl` is a configuration error.

  The docs recommend `STORYTELLER_TOKEN_URL`, which `sform account machine create` prints.
- **Federation** (`Endpoint`, `Organization`, `Project`, `ClientId` = the machine id, `SubjectTokenPath`, `SubjectTokenType` = `urn:ietf:params:oauth:token-type:jwt` by default, `Scope?`):
  - a form POST to `{endpoint}/v1/{organization}/{project}/access/token`;
  - fields: `grant_type=urn:ietf:params:oauth:grant-type:token-exchange`, `client_id`, `subject_token` (the file, trimmed, read again before every exchange), `subject_token_type`, and `scope` when set;
  - `jwt`, `id_token` and `access_token` are accepted as short forms of the type.
- **Token and discovery requests**:
  - go through their own `HttpClient` with `AllowAutoRedirect = false` and no `Authorization` header;
  - follow the local URL rule;
  - use the resilience pipeline below, including retries of the POST: a token request has no side effect, and the exchange answers 503 with `Retry-After` when it is temporarily unavailable;
  - read `access_token`, `token_type` (absent or `Bearer`) and `expires_in`.
- **Proxies and tests.** Every credential option type has `Action<SocketsHttpHandler>? ConfigureHandler` and `TimeProvider? TimeProvider`; the credential sets `AllowAutoRedirect = false` again after the callback. An internal handler override, visible to `Sdk.NSwag/test`, is the seam for tests.
- **Token cache** (client credentials and federation):
  - one `SemaphoreSlim`, so concurrent callers share one request;
  - renewal 60 seconds before expiry;
  - expiry from `expires_in` capped at one day, else the JWT `exp` (read, not validated), else five minutes;
  - an injectable `TimeProvider`.
- **No secret in logs, messages or `ToString()`.** Option types override `ToString()` without secrets, as the CLI records do.

**`StorytellerAuthenticationException`** (public) carries a `Reason`:

| Reason | When | Class (section 8) |
| --- | --- | --- |
| `Configuration` | missing or conflicting variables, an unreadable token or certificate file, a binding that is needed but missing, a URL that breaks the local URL rule | definitive |
| `Rejected` | 400, 401, 403, 404 or any other 4xx except 408 and 429 from a token or discovery request (`invalid_client`, `invalid_grant`), or a discovery answer that is not AuthKit | definitive |
| `Unavailable` | a network error, a timeout, an open circuit, or 408, 429 or 5xx from a token or discovery request, after retries | transient |

The message includes `error` and `error_description` of an OAuth answer, never a secret.

**`StorytellerCredential.FromEnvironment(Func<string, string?>? getVariable = null, IFileSystem? fileSystem = null, TimeProvider? timeProvider = null)`** returns the credential that the `STORYTELLER_*` variables describe, still unbound, or `null` when they describe none. Values are trimmed; empty means unset.

| Kind | Variables (the issue's names; `sform` names accepted as fallbacks) |
| --- | --- |
| API key | `STORYTELLER_API_KEY` |
| Certificate | `STORYTELLER_CLIENT_CERTIFICATE` (fallback `STORYTELLER_CERTIFICATE_FILE`) and `…_PASSWORD` (fallback `STORYTELLER_CERTIFICATE_PASSWORD`); alone or with an API key |
| Client credentials | `STORYTELLER_CLIENT_ID`, `STORYTELLER_CLIENT_SECRET`, `STORYTELLER_TOKEN_URL`, `STORYTELLER_TOKEN_SCOPE` |
| Federation | `STORYTELLER_CLIENT_ID` (the machine id) with `STORYTELLER_TOKEN_FILE` and no client secret (fallback `STORYTELLER_SUBJECT_TOKEN_FILE`); optional `STORYTELLER_SUBJECT_TOKEN_TYPE` and `STORYTELLER_TOKEN_SCOPE` |
| Token file | `STORYTELLER_TOKEN_FILE` without `STORYTELLER_CLIENT_ID` |

- **Why the fallbacks.** The issue makes the shared names the contract for every language. Machines that exist today were printed by `sform account machine create` with the `sform` names. Accepting both, where they mean the same thing, lets one set of variables drive `sform` and the provider for every kind except the GitHub Actions source (out of scope). When a name and its fallback are both set with different values, reading fails and names both.
- **`STORYTELLER_TOKEN_FILE`** keeps the `sform` meaning (a bearer token) on its own. With `STORYTELLER_CLIENT_ID` it is the federated subject token of the issue. In `sform` that combination is an error, so the extension breaks no working setup.
- **`STORYTELLER_CLIENT_ID` alone**, without a secret or a token file, is a `Configuration` error that names the missing variables.
- **Two kinds at once** are a `Configuration` error that names them, as in `sform`.

**`StorytellerCredentialHandler : DelegatingHandler`** sets `Authorization` from the credential.
- On a 401 it asks once more with the refused value as `rejected` and resends, under three conditions:
  - the credential `CanRenew`;
  - the request has no body, or a `ByteArrayContent`;
  - no redirect changed `RequestUri` or `Authorization`.

  It passes the caller's token.
- New extension `IHttpClientBuilder.AddStorytellerCredential(StorytellerCredential)` adds it. `AccessTokenFactory` must then stay null, otherwise `PrepareRequest` sets `Authorization` too; the README says so. The certificate still goes to `SdkConfiguration.ClientCertificate` on that path.

**Resilience** (new `Sdk.NSwag/src/Resilience`):
- **`StorytellerResilienceOptions`** (public, mutable):

  | Member | Default |
  | --- | --- |
  | `int MaxRetryAttempts` | 3 |
  | `TimeSpan BaseDelay` | 500 ms; exponential backoff with jitter. Tests set it to zero |
  | `TimeSpan AttemptTimeout` | 5 s |
  | `bool RetryUnsafeMethods` | `false`. The API pipeline retries `GET` only; the token client sets `true` |
  | `double FailureRatio` | 0.5 |
  | `int MinimumThroughput` | 3 |
  | `TimeSpan SamplingDuration` | 60 s |
  | `TimeSpan BreakDuration` | 30 s |

  `Retry-After` is always honoured.
- `StorytellerResilience.CreatePipeline(StorytellerResilienceOptions)` builds the pipeline of section 7 for a hand-built client.
- New `IHttpClientBuilder.AddStorytellerResilience(Action<StorytellerResilienceOptions>?)` adds it as a `ResilienceHandler`. It is opt-in, so `sform` and existing `AddStorytellerSdk` users see no change. An application that already gets `AddStandardResilienceHandler` from Aspire's service defaults should not add a second one; the README says so.

### 4. Conditional reads in the TypeScript SDK (`sdk.typescript`)

- **`lib/fetcher.ts`.** The request part of `storytellerFetch` moves to an internal `storytellerRequest(url, init): Promise<Response>`:
  - the base URL, and the default and per-request headers;
  - the token;
  - the 401 retry, with body cancel and `onUnauthorized`;
  - the abort and network mapping to `StorytellerError` status 0.

  `storytellerFetch` becomes `storytellerRequest` followed by `readBody` and the error mapping. Its behaviour and the existing tests do not change.
- **New `lib/conditional.ts`**, exported from `index.ts`:
  ```ts
  export interface ConditionalResult<T> {
    status: 200 | 304
    notModified: boolean
    etag?: string            // undefined when the header is not readable (cross-origin without exposure)
    value?: T                // the body of a 200
    cacheControl?: string
    secretsWithheld?: string
  }
  getConfigurationConditional(organization, project, view, key, options?: RequestInit & { ifNoneMatch?: string }): Promise<ConditionalResult<Configuration>>
  getResolvedConfigurationConditional(…same…): Promise<ConditionalResult<Configuration>>
  ```
  - The URLs come from the generated `getGetConfigurationUrl` and `getGetResolvedConfigurationUrl`.
  - `ifNoneMatch` is sent as `If-None-Match`; a header in `options.headers` is overridden by it.
  - A 304 is handled before the error mapping. Any other non-2xx throws `StorytellerError.fromResponse`, as the fetcher does.
  - `signal` and the other `RequestInit` fields pass through.
- **README.** A "Conditional reads" section. When a name and its `sform` fallback are both set with different values, validation fails and names both, as in section 3.
- **Binding.** A credential, from the environment or set in code, is bound (section 3) to the validated `Endpoint`, the organization and project of `Key`, `ConfigurePrimaryHandler`, `TimeProvider` and `Resilience`.

- **`Resilience.AttemptTimeout`.** The study proposes 2 s. A cold start of a Functions host and a resolved read that calls Key Vault regularly take longer, and a 2 s cap would turn a cold start into a failed start. 5 s is the default, and it can be set.

- **Clocks.** `TimeProvider` drives the poll timer, the jitter, the token cache, the secret refresh and the status timestamps. An internal seam of the provider, visible to `Configuration/test`, supplies the random source of the jitter and a stub primary handler, so startup tests run without advancing fake time.

### 7. Transport

One internal factory builds the `HttpClient` for the provider and for the document service of section 15:

```
StorytellerCredentialHandler            (outermost: Authorization, one renewal on a 401)
  └─ ResilienceHandler                  (StorytellerResilience.CreatePipeline, section 3)
       └─ primary SocketsHttpHandler    (client certificate, AllowAutoRedirect = false, PooledConnectionLifetime = 5 min)
```

- **Pipeline** (`StorytellerResilience.CreatePipeline(options.Resilience)`):
  - retry with `HttpRetryStrategyOptions`: 3 attempts, exponential backoff from 500 ms, jitter, `Retry-After` honoured, `GET` only;
  - circuit breaker with `HttpCircuitBreakerStrategyOptions`: failure ratio 0.5, minimum throughput 3, sampling 60 s, break 30 s. The standard handler's minimum throughput of 100 would never trip for a poller;
  - attempt timeout `Resilience.AttemptTimeout`;
  - `HttpClient.Timeout` is infinite; `ReadTimeout` and the caller's token bound a whole run.
- **`ConfigurePrimaryHandler`** runs on the primary handler, then the provider sets the certificate and `AllowAutoRedirect = false` again, so a proxy setting cannot drop either. Token and discovery requests get the same callback through the binding (section 3), without the certificate, unless the credential's own options set one.
- **No DI client.** The provider runs before the container exists, and the document service uses the same factory, so both behave alike. This also avoids two problems of `AddStorytellerSdk` in an application that already uses the SDK:
  - its `TryAdd` of `ISdkConfiguration` would collide;
  - Aspire's `ConfigureHttpClientDefaults(AddStandardResilienceHandler)` would stack a second resilience handler.
- **SDK client.** `new ConfigurationsApiClient(httpClient, new SdkConfiguration { … })` with:
  - `BaseUrl = endpoint`;
  - `AccessTokenFactory = null`;
  - `ClientCertificate = certificate`;
  - `ClientCertificateHeaderName = "X-ARR-ClientCert"` only for `http` under the local URL rule, otherwise `null`. That reproduces what `sform` does for a local host.

### 8. Reading a document

**Identity.** Endpoint + organization + project + view + annotation key + mode, with the type code lower-cased. An `ETag` is never sent for another identity.

**One internal reader** calls the conditional method of the mode with the stored `ETag` and classifies the outcome:

| Outcome | When |
| --- | --- |
| `Changed(document, etag, cacheControl)` | 200 |
| `NotModified(etag?, cacheControl)` | 304; a missing `ETag` keeps the stored one |
| `Withheld` | `X-2S-Secrets-Withheld` on a 200 or 304 in `Resolved` mode |
| `Definitive(status, errorCode, message)` | 400, 401, 403, 404 (with or without a body), 422, 501, any other 4xx except those below; a `StorytellerAuthenticationException` with `Configuration` or `Rejected` |
| `Transient(status?, exception)` | network errors, timeouts (attempt or `ReadTimeout`), an open circuit, 408, 424, 429, and 5xx except 501; a `StorytellerAuthenticationException` with `Unavailable` |

- **`Withheld` fails loudly**, as the issue asks: the provider does not start with literal `@` expressions in place of secrets. Because the server sends the header per caller, a machine with `Secrets.Read` but no certificate fails even on a document without secrets. The exception message names the fix: present the machine certificate (`STORYTELLER_CLIENT_CERTIFICATE`), or remove `Secrets.Read` from the machine.
- **Unbound bindings without the header.** A machine without `Secrets.Read` gets the `@…` expressions without the header. In `Resolved` mode the reader logs one warning per applied document with the count and the JSON paths of strings that start with `@`. It never logs their values, so the case is visible.
- **Exceptions.** Errors become `StorytellerConfigurationException` with `Key`, `StatusCode`, `ErrorCode`, `IsTransient` and the inner exception.

### 9. Flattening and validation

An internal flattener turns the `Content` object into `IConfiguration` keys, following study section 3.3:
- Object properties join with `:`, array items with their index: `db:hosts:0`.
- A string is its value. A number or boolean is its JSON text (`true`, `5432`, `0.5`).
- `null` produces no key; an empty object or array produces no key.
- Property names keep their casing.

A document is **invalid**, and is never applied, when:
- a property name contains `:`;
- a property name is empty;
- two keys differ only in case (`IConfiguration` compares keys case-insensitively).

The error names the JSON path. A test-vector file, `Configuration/test/Vectors/flattening.json`, pins the study example and each rule, in a shape another language can reuse (`name`, `document`, `keys` or `error`).

Numbers are read by the SDK as `double`, so `1.50` arrives as `1.5`. Binding to `decimal` or `double` is unaffected; the docs state it.

### 10. Last-known-good cache

New internal `LastKnownGoodCache` on `IFileSystem`, active only with a `CacheDirectory`.

**Entry.** One file per cache identity: the identity of section 8 plus a fingerprint of the credential. The fingerprint is not secret: the kind, plus the client id, the machine id of an API key, or the SHA-256 of a certificate's thumbprint. An entry written under one principal is therefore never applied under another. The file name is the first 32 hex characters of SHA-256 over the cache identity. The content is:
- `identity`, `etag`, `storedAt`;
- `cacheControl`: the response class;
- `document`: the server's body **before** local reference resolution, so a locally resolved secret never reaches the disk.

`document.Content` is kept as raw JSON text and parsed with the SDK's settings (`DateParseHandling.None`), so a document flattens to the same keys from the cache as from the platform.

**When an entry is written:**
- **`no-store`.** In `Resolved` mode, a plain entry is written only when `Cache-Control` is present and has no `no-store`. A missing header counts as `no-store`: the server always sends one of the two, so its absence means something in between changed it.
- **Deletion.** A `no-store` response, a 200 or a 304, deletes an existing plain entry of the identity (RFC 9111 §5.2.2.5). The skip is logged once per identity. This covers every resolved read by a caller that may read secrets.
- **Protection.** With `CacheProtector` set, **every** entry is protected, whatever its `Cache-Control`. That is the issue's "or encrypted" option: the application chooses DPAPI, Data Protection or a mounted key.
  - The contract is `IStorytellerCacheProtector` with `byte[] Protect(byte[] plaintext, string identity)` and `byte[] Unprotect(byte[] protectedData, string identity)`. It must be authenticated encryption, and the identity is its purpose or associated data, so blobs cannot be swapped between files.
  - The whole serialized entry is one blob, behind a format marker outside it.
  - A reader with a protector rejects plain files; a reader without one rejects protected files.
  - No protector ships in this change. The docs show one over a standalone `DataProtectionProvider`, with its key ring outside the cache directory and protected at rest, and warn that an ephemeral key ring makes every entry unreadable after a restart.

**Trust in an entry.**
- A **protected** entry is authenticated. Its `ETag` is sent on the first read (startup, switch), and a 304 applies it.
- A **plain** entry is not authenticated: someone who can write the directory could keep its tag and change its document. Its `ETag` is never sent. It is used only as the fallback after a transient failure (section 11).

**Files.**
- On Unix the directory is created with mode 0700 and files with 0600. An existing directory that is group- or world-writable is used, with a warning. On Windows the directory inherits its ACL; the docs recommend a per-user location.
- Writes go to a unique temporary file in the same folder (`{hash}.{guid}.tmp`, `FileMode.CreateNew`), then `Move(…, overwrite: true)`. A failed write deletes its temporary file.
- Reads open with `FileShare.ReadWrite | FileShare.Delete`.
- Any `IOException` or `UnauthorizedAccessException` is a logged, non-fatal cache error. The applied document and the result of the run do not change, and the next applied document tries again. Several processes can share a directory.
- Temporary files older than one hour are deleted when the directory is first used.
- A file that does not parse, cannot be unprotected, or names another identity is treated as absent, with a warning.

### 11. Source, provider and engine

**State lives in an engine, not in the provider.** `ConfigurationManager` builds new provider instances whenever its sources change, and `ConfigurationBuilder.Build()` builds a new one per call. An internal `StorytellerConfigurationEngine`, created by `AddStoryteller` and held by the source, owns:
- the options, the transport and the refresher;
- the current snapshot, the timer and the status.

Each `Build()` returns a new `StorytellerConfigurationProvider` attached to that engine. One source therefore has one poller and one cache writer, however often it is built.

**Snapshot.** Immutable, swapped with one reference assignment. It holds:
- the active identity and key;
- the `ETag` to send on the next read. A snapshot built from a **plain** cache entry has none, so the first poll after a start from such an entry is unconditional (section 10);
- the server document, the flattened data, and the resolved references with their resolution times;
- the response class and the origin (`Platform`, `Cache`, `Empty`);
- a sequence number that grows with every snapshot the engine creates, a rollback included.

**`StorytellerConfigurationProvider : ConfigurationProvider, IDisposable`.**
- It attaches to the engine in its constructor, that is, at `Build()`.
- `Load()`:
  - the first time for the engine, it runs the startup read below, synchronously (`Task.Run(…).GetAwaiter().GetResult()`, `ConfigureAwait(false)` throughout), bounded by `ReadTimeout`. Concurrent first loads share one startup;
  - a failed startup is not remembered: the next `Load()` runs it again, and a required provider throws again;
  - after a successful startup, it publishes the current snapshot without a request. `IConfigurationRoot.Reload()` therefore does not fetch; the refresher does.
- **Publishing.** Under the provider's own lock, the provider reads the engine's current snapshot and skips it when its sequence number is not newer than the last one this provider published. Otherwise it sets `Data` to a new case-insensitive dictionary copied from the snapshot. `OnReload()` is called after the lock is released.
  - A late or concurrent notification can therefore never put an older document back.
  - A copy per provider means that an `IConfiguration[key] = value` on one root never leaks into another. Such a local override lasts until the next applied document, as with other reloading providers.
- `Dispose()` detaches it from the engine.

**Engine lifecycle.** The engine keeps an attach count and an epoch, both changed under its lock.
- **Stop.** When the last provider detaches, which happens at every host shutdown, the engine increments the epoch, disposes the timer, and cancels the in-flight run. It disposes the `HttpClient` once that run has ended. A run that ends by that cancellation, or by an `ObjectDisposedException`, ends silently and changes no status.
- **Epoch check.** A run captures the epoch at its start. It swaps, notifies, writes the cache and re-arms the timer only if, under the lock, the epoch is unchanged and a provider is attached. A stopped engine never polls again.
- **Restart.** A later attach increments the epoch again, creates a new transport and timer, and publishes the current snapshot.
- **While stopped**, `TryRefreshAsync` returns `false` and `SwitchKeyAsync` throws `InvalidOperationException`.
- A root that is built and never disposed keeps its provider attached and polling. The docs say to dispose temporary roots.

**Startup read.** A run (section 12) of steps 1-4 and 6; there is nothing to notify, because `Load()` publishes the result to the provider that called it, and the root reads `Data` after `Load()`.
1. Read the cache entry of the identity, if any.
2. Read the document. The `ETag` of a **protected** entry is sent; a 304 applies that entry.
3. Apply: flatten, validate, resolve references.

| Outcome | Required (`Optional = false`) | Optional |
| --- | --- | --- |
| Applied | start | start |
| Transient, usable cache entry | start from the cache, degraded | start from the cache, degraded |
| Transient, no usable cache entry | throw | start empty, degraded |
| Definitive, `Withheld` or invalid document | throw | throw |
| A resolver failure, transient | throw | start empty, degraded |
| A resolver failure, definitive | throw | throw |

- **Optional is only about reachability.** The issue defines `STORYTELLER_OPTIONAL` as "start without the platform when it is unreachable and nothing is cached", and asks for withheld secrets to fail loudly. A wrong key (404), a missing credential (401) or withheld secrets therefore fail an optional provider too.
- **A cache entry is usable** only if it can be applied, references included. The cache holds the document before resolution, so a cached document whose references cannot be resolved is not usable. A document is never applied with the text of a reference that a resolver accepted.
- **Throwing.** A required provider throws `StorytellerConfigurationException`, and startup fails: the issue's "fail fast". `ConfigurationManager` is not usable after a provider's `Load()` throws, so the exception is never swallowed.
- **Degraded starts** keep polling, so the provider recovers when the platform answers.

**Placement** (`AddStoryteller`):
- `BeforeEnvironmentVariables` inserts the source in front of the **last** `EnvironmentVariablesConfigurationSource` whose `Prefix` is null or empty. The order is then `appsettings*.json < Storyteller < environment variables < command line` (study 3.4). Without such a source (an empty builder or `DisableDefaults`), it appends.
- `Last` appends: nothing local can override the platform (strict mode).
- **Cost.** On a `ConfigurationManager` the insert rebuilds and reloads every source added before it. The engine makes that harmless for Storyteller, but network-backed providers added earlier (Key Vault, App Configuration) load again. The docs recommend calling `AddStoryteller` before them; they are appended after the command line either way, so their precedence over Storyteller does not change.

**Extensions** (namespace `Microsoft.Extensions.Configuration`, so `builder.Configuration.AddStoryteller(…)` needs no `using`):
```csharp
IConfigurationBuilder AddStoryteller(this IConfigurationBuilder builder, Action<StorytellerConfigurationOptions>? configure = null);
IConfigurationBuilder AddStoryteller(this IConfigurationBuilder builder, Action<StorytellerConfigurationOptions>? configure, out IStorytellerConfigurationRefresher refresher);
```

The repo keeps extensions in its own namespaces, except `Aspire.ServiceDefaults`. A configuration extension in `Microsoft.Extensions.Configuration` is the convention of every Microsoft and Azure provider, and the shape the issue shows.

### 12. Refresh, refresher and key switching

**A run** is startup, a timer refresh, a `TryRefreshAsync` or a switch. It is bounded by `ReadTimeout`. Steps 1-4 run under the engine's run gate (`SemaphoreSlim(1)`), so runs never overlap. The gate is released before step 5, and the same thread then runs steps 5 and 6. A run's task completes after step 6, so an awaited `TryRefreshAsync` or `SwitchKeyAsync` returns once `IConfiguration` and `IOptionsMonitor` show the result.

**Apply pipeline**, shared by every run and by section 15:
1. **Read** (section 8). Protected cache entries only: on a switch, the `ETag` of the new identity's entry.
2. **304.** On `NotModified`:
   - if its `Cache-Control` is `no-store` (or missing, in `Resolved` mode) and there is no protector, delete the identity's plain cache entry;
   - if the snapshot's references are older than `SecretRefreshInterval`, resolve them again and continue at step 4 only if a value changed;
   - otherwise the run ends successfully.
3. **200.** On `Changed`, flatten and validate (section 9), then resolve references (section 13).
4. **Swap** in the new snapshot.
5. **Notify** each attached provider: it publishes (section 11) and calls `OnReload()`.
   - **Rejection.** If `OnReload()` throws, the document did not bind: an `IOptionsMonitor` rebind failed validation or conversion. The engine rolls back:
     - it creates a **new** snapshot with the previous content and identity and a new sequence number, so providers publish it;
     - it swaps that snapshot in only if the current snapshot is still the rejected one, so a newer run that swapped in the meantime wins;
     - it notifies again, so the options cache is rebuilt from valid data;
     - it records the error, and remembers the rejected `ETag` **for the rejected identity**. Later polls of that identity send it, so an unchanged document answers 304 and is not applied and rolled back every interval; a new server document is tried again. That is the issue's "a document that does not bind keeps the previous one".
   - A rejection during a switch makes `SwitchKeyAsync` throw; the rollback restores the previous key.
   - If the second notification throws too, the error is logged and the rolled-back snapshot stays.
6. **Cache.** Write the cache entry (section 10), only after a successful step 5, and only if the snapshot of this run is still the current one, so an older document never overwrites a newer entry.

**Failures.**
- A failure in steps 1-3 keeps the previous snapshot, logs a warning without values, and records the error in the status.
- A rejection in step 5 does the same, after the rollback.
- A cache error in step 6 is logged and changes neither the snapshot nor the result of the run.

**Timer.**
- `TimeProvider.CreateTimer`, one-shot, re-armed after each run under the epoch check, so runs never overlap.
- Each delay is `RefreshInterval × (0.9 + 0.2 × r)` with `r` uniform in [0, 1), so a fleet started together drifts apart.
- `RefreshInterval = 0` creates no timer.
- A run never blocks a reader: readers see the published `Data` until the swap.

**`IStorytellerConfigurationRefresher`** (public, one per engine, stable across rebuilds):
```csharp
string ActiveKey { get; }                                           // the full key of the current snapshot
StorytellerConfigurationStatus Status { get; }
Task<bool> TryRefreshAsync(CancellationToken cancellationToken = default);
Task SwitchKeyAsync(string key, CancellationToken cancellationToken = default);
```

**`TryRefreshAsync`** queues a run and returns whether it succeeded. It never throws for a failed read.
- Concurrent callers share one **queued** run that has not yet started. A run that has already sent its request is never joined, so every call sees a read made after the call.
- A call from inside a change callback (step 5) queues a new run, which can take the free gate, so it never waits on its own notification.
- Before the first `Load()`, and while the engine is stopped, it returns `false`.

**`SwitchKeyAsync`** is the dynamic binding of the issue.
- **Key.** `key` is a full key, or an annotation key in the active organization, project and view.
- **Scope.** The organization and project must stay the same, because a machine credential belongs to one project; anything else throws `ArgumentException`.
- **Run.** It waits for the run gate, that is, for steps 1-4 of a running run (it does not cancel it), then runs as one run on the new identity. It never waits for a notification, so a call from a change callback cannot wait on itself.
- **Commit.** The new identity becomes active with the snapshot swap of step 4, so a change callback sees the new `ActiveKey` together with the new data. The caller's token is honoured until that swap.
- **Failure.** It throws `StorytellerConfigurationException`, and the previous key and document stay.
- **Active key.** A switch to the active key is a refresh that throws on failure.
- **Before the first `Load()`** it throws `InvalidOperationException`; it waits for a running startup.
- **Lifetime.** A switch lasts for the process. A restart starts from the configured key.

**`StorytellerConfigurationStatus`** (immutable):
- `ActiveKey`, `ETag`;
- `Origin`: `Platform`, `Cache` or `Empty`;
- `LastAppliedAt` and `LastSucceededAt` (a 200 or 304);
- `LastError` and `LastErrorAt`;
- `ConsecutiveFailures` and `TotalFailures`, which is the issue's "counted";
- `IsDegraded`: true while the origin is `Cache` or `Empty`, while the last run failed, or while the server's document is a rejected one. A 304 that answers a rejected `ETag` updates `LastSucceededAt` (the platform answered) but keeps `IsDegraded` and `LastError`. A 304 that confirms a protected cache entry turns the origin to `Platform`.

**Container integration** (namespace `Microsoft.Extensions.DependencyInjection`). `services.AddStorytellerConfiguration()`:
- **Refresher provider.** Registers `IStorytellerConfigurationRefresherProvider` (`IReadOnlyList<IStorytellerConfigurationRefresher> Refreshers`). It finds the engines by walking `IConfigurationRoot.Providers` on each access, including `ChainedConfigurationProvider.Configuration`, so it copes with rebuilds.
- **Single refresher.** Also registers `IStorytellerConfigurationRefresher` itself, resolved to the only refresher. Zero or several throw `InvalidOperationException`, which points to the provider.
- **Logging.** Registers an `IHostedLifecycleService`. At `StartingAsync` it hands the container's `ILoggerFactory` to every engine that was given none. Each such engine then logs its status once if it is degraded, so a degraded start before the container existed is still reported. At `StoppedAsync` it hands `NullLoggerFactory` back, because the host disposes the logger factory before the configuration.

Without `AddStorytellerConfiguration()` (or `options.LoggerFactory`) the provider is silent. The package readme and the docs show it in the minimal `Program.cs`.

`services.Configure<T>(configuration.GetSection(…))` then follows every applied document through `IOptionsMonitor<T>`, with no further code.

### 13. Secret references

**Resolver contract** (public, neutral about vaults, so AWS, Google or HashiCorp resolvers can implement it later):
```csharp
public interface ISecretReferenceResolver
{
    bool CanResolve(string value);                                    // the whole, trimmed string value
    ValueTask<string> ResolveAsync(string value, CancellationToken cancellationToken);
}
```
- **`SecretResolutionException`** (public) carries `IsTransient`, plus the vault and secret names, never a value. Any other exception from a resolver counts as definitive.
- **`SecretReferenceResolver.FirstOf(params ISecretReferenceResolver[])`** combines resolvers; the first that accepts a value resolves it.

**`SecretReference`** (public, immutable) parses the platform's own reference forms, for the Key Vault resolver and for diagnostics. It has a strict `static bool TryParse(string? value, out SecretReference? reference)`:

| Form | Rule |
| --- | --- |
| Shorthand | `kv://{vault}/{name}[/{version}]`; vault `[A-Za-z0-9-]{3,24}`, name `[A-Za-z0-9-]{1,127}`, version 32 hex |
| Secret URI | `https://{host}/secrets/{name}[/{version}][/]`; no user info, port, query or fragment |
| App Configuration | a string that holds the JSON object `{"uri": "<secret URI>"}` |

- The whole trimmed value must match. A reference inside a longer string (interpolation) is not recognized.
- Members: `Original`, `Form`, `VaultName` (shorthand only), `VaultUri` (`null` for the shorthand), `Name`, `Version?`.
- It follows `Backend.Core/src/KeyValues/SecretReferences.cs`, but is stricter about the URI parts. The accepted and rejected examples of `ClientEncryptionAndReferenceTests` become test vectors. The provider does not reference `Backend.Core`.

**Substitution:**
- **When.** It runs in `Resolved` mode only, and only with a `ReferenceResolver`.
- **What.** It walks the string values of the document, never property names. A value that the resolver accepts is replaced by the resolved value.
- **Failures.** A failure fails the apply, with the class of the `SecretResolutionException` (sections 11 and 12). There is no fallback to the reference text.
- **Unclaimed references.** A value that parses as a platform `kv://` shorthand, but that no resolver accepts, fails the apply, because the shorthand is unambiguous. Any other value that no resolver accepts stays as it is. If it parses as another `SecretReference` form, the engine logs a warning with its path and host.
- **No resolver.** Without a resolver, values that parse as a `SecretReference` are left as they are, with one warning per applied document listing their paths.
- **Cache.** Resolved values are kept in memory per value text, with their resolution time, and reused until `SecretRefreshInterval`.
  - A changed document reuses fresh entries.
  - Section 12 step 2 resolves expired entries again on a 304, so a rotated secret reaches the application without a document change.
- **Logging.** Resolved values are never logged, cached on disk or put in exceptions. Logs name the path, the vault and the secret name only.
- **Scope.** Only Storyteller documents are substituted: the provider's and those of section 15. Unlike the legacy wrapper, a reference in an environment variable or `appsettings.json` stays literal: those sources are local, and resolving them would make the provider read secrets for sources it does not own. The docs state it.

**Trust model.** Anyone who can write the configuration document can make the application read any secret that its own identity can read, and put it under a key of their choice. The ambiguity limit is the same: an ordinary string with a reference's shape is resolved too, because Storyteller does not report which paths came from reference pairs (study capability C6). The docs state both, and recommend `AllowedVaults` (section 14) and least-privilege vault access for the application's identity.

### 14. Key Vault resolver (`Configuration.KeyVault`)

`KeyVaultReferenceResolver(TokenCredential credential, KeyVaultReferenceResolverOptions? options = null) : ISecretReferenceResolver`. It is built on `SecretReference`.

**Options.**

| Option | Default | Meaning |
| --- | --- | --- |
| `DefaultVaultSuffix` | `vault.azure.net` | the suffix a `kv://{vault}/…` shorthand expands to, as on the server; always allowed |
| `AllowedHostSuffixes` | `vault.azure.net` | the hosts a secret URI may name; sovereign clouds and a local emulator are added here |
| `AllowedVaults` | empty = any | vault names; when set, every other vault is declined. The name of a secret URI is the first label of its host, so `myvault` admits both `kv://myvault/x` and `https://myvault.vault.azure.net/secrets/x` |
| `SecretClientOptions` | — | passed to each `SecretClient` |
| `SecretClientFactory` | — | `Func<Uri, SecretClient>`; replaces the default factory (tests, custom clients) |

- **Host match.** Case-insensitive on the IDN host: equal to the suffix, or ending with `.` + the suffix, so `evilvault.azure.net` does not match `vault.azure.net`.
- **`CanResolve`** accepts a value that `SecretReference.TryParse` accepts, and whose host and vault pass the options.
- **Clients.** One `SecretClient` per vault origin, cached in a `ConcurrentDictionary`.
- **Read.** `GetSecretAsync(name, version, cancellationToken)`. A `RequestFailedException` becomes `SecretResolutionException`:
  - transient for 408, 429, 5xx, network errors and timeouts;
  - definitive for 401, 403, 404 and a disabled secret.

  The exception names the vault and secret, never the value.
- **Wiring:** `options.ReferenceResolver = new KeyVaultReferenceResolver(new DefaultAzureCredential())`, the issue's line.

### 15. Documents on demand (`IStorytellerDocuments`)

For a job that reads configurations while it runs. `services.AddStorytellerDocuments(Action<StorytellerConfigurationOptions>? configure = null)` registers it as a singleton. It uses the same environment contract, transport, reader and apply pipeline as the provider.

**Options it honours:** `Endpoint`, `Key` (optional here; when set, its organization, project and view are the default scope), `Mode`, `Credential`, `ReferenceResolver`, `SecretRefreshInterval`, `ReadTimeout`, `Resilience`, `LoggerFactory` (default: the container's), `TimeProvider` and `ConfigurePrimaryHandler`. The others (`RefreshInterval`, `Optional`, `CacheDirectory`, `CacheProtector`, `Placement`) do not apply and are ignored. A federated credential needs the organization and project, so it needs `Key`. An application that uses both the provider and the documents passes the same `configure` delegate to both.

```csharp
public interface IStorytellerDocuments
{
    Task<StorytellerDocument> GetAsync(string key, CancellationToken cancellationToken = default);
    Task<StorytellerDocument> GetAsync(string key, StorytellerReadMode mode, CancellationToken cancellationToken = default);
}
```

- **Keys.** `key` is a full key, or an annotation key in the default scope (`ArgumentException` without one).
- **`StorytellerDocument`** (immutable):
  - `Key` (the full key), `Mode`, `ETag`, `Version`, `Hash`, `Modified`, `Labels`, `Values`;
  - `JObject Content`, after reference substitution: the resolved document as the job should use it;
  - `IConfiguration Configuration`: the flattened keys, in a `ConfigurationRoot` over a memory source;
  - `T Get<T>(string? section = null)`, which binds with `ConfigurationBinder`.
- **Revalidation.** Every call revalidates with `If-None-Match`, because the API sends `no-cache` or `no-store`. A 304 returns the cached document, resolving expired references again as in section 12.
- **Memory cache.** A `MemoryCache` per identity, with a size limit of 1024 and `Size = 1` on every entry. Entries have a sliding expiration of twice `SecretRefreshInterval`, because they hold resolved secrets.
  - A 401, 403, 404 or `Withheld` evicts the identity.
  - Concurrent calls for one identity share one request through a separate `ConcurrentDictionary` of in-flight tasks, removed on completion. Sharing therefore works even when the cache is full.
  - Nothing is written to disk.
- **Failures** throw `StorytellerConfigurationException`, `Withheld` in `Resolved` mode included. There is no last-known-good for on-demand reads: a job decides itself what to do without its configuration.
- **Disposal.** The service is registered by factory, so the container disposes it. Its `Dispose` disposes the `HttpClient` and the `MemoryCache`.

## Decisions on the CodeRabbit plan

The coding plan on the issue was read as a second opinion. This spec follows most of it; it differs here:

- **Namespace.** The plan's `_42.Platform.Storyteller.Configuration` collides with the `Configuration` record. The packages keep the issue's names; the namespace is `_42.Platform.Storyteller.Sdk.Configuring`.
- **Interface.** The conditional methods join `IConfigurationsApiClient` instead of a new `IConditionalConfigurationsApiClient`; nothing in the repo implements it by hand.
- **SDK tests** get their own project, `Sdk.NSwag/test`, instead of `Platform/Cli/test/Sdk`: the credentials are new SDK code.
- **Environment names.** The plan accepts only the issue's names. This spec also accepts the `sform` names as fallbacks, because existing machines were printed with them.
- **Credentials.** The certificate is part of `StorytellerCredential`, as the issue's `StorytellerCredential.FromEnvironment() // API key, certificate, …` shows. Credentials bind to the validated options, so a key set in code also drives federation. They renew against the rejected value, not a `forceRefresh` flag.
- **Resilience** is in `Sdk.NSwag`, as the study asks, and opt-in there.
- **Error classes.** `MtlsRequired` and `AnnotationInactive` never come from configuration reads, so they are not mapped. 424 is transient. Credential and resolver failures are classified too.
- **Cache.** The plan writes the pre-resolution document unless `no-store`. This spec also treats a missing header as `no-store`, sends a plain entry's `ETag` never, and separates entries per credential. The server sends `no-store` to every caller that may read secrets, so the opt-in `CacheProtector` gives those callers a cache without shipping cryptography.
- **State in an engine.** The plan puts state in the provider. `ConfigurationManager` rebuilds providers, so the state lives in an engine shared by every instance of one source.
- **A document that does not bind** is rolled back, as the issue asks; the plan does not cover options validation.
- **Resolver contract.** The plan's `CanResolve(SecretReference)` only fits Azure. Here a resolver sees the string, and `SecretReference` is a helper for the platform's own forms.
- **Document service transport.** The plan registers it through `AddStorytellerSdk`. This spec uses the provider's own transport (section 7).
- **`AttemptTimeout`** is 5 s, not 2 s (section 6).
- **TypeScript.** The mutator is `storytellerFetch`, not `customFetch`, and the generated URL helpers exist.
