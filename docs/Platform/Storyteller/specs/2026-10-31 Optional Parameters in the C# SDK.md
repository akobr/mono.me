# Optional Parameters in the C# SDK

Line numbers refer to the tree this plan was written against (`origin/main` at `596b07c8`). No application code is changed by this document.

Linear issue [424-118](https://linear.app/424fun/issue/424-118/c-sdk-generate-optional-parameters-with-nswag). The issue has a CodeRabbit coding plan (`2026-10-29 Optional parameters in NSwag.md`, attached to its comment). It was written against an older checkout (no MCP project, `open.api.v0.10.0.json` as the newest snapshot), so this plan takes its ideas but checks each claim against the current tree; where the two disagree, the reason is given below.

## Problem

The C# SDK (`src/Platform/Storyteller/Sdk.NSwag`, `42.Platform.Storyteller.Sdk.NSwag`) is generated by NSwag without `/GenerateOptionalParameters`. Every parameter the OpenAPI document marks as optional is still a required argument of the generated method, so a caller passes `null` for each one it does not use:

```csharp
await configurations.GetConfigurationAsync(organization, project, view, key, null, null, cancellationToken);   // format, If-None-Match
```

The 0.10 documents made this visible: the configuration reads took the optional `format` query and the optional `If-None-Match` header, and the MCP server (8 calls) and `sform` now pass `null` for them. Every generated operation also has two interface members, one with and one without a `CancellationToken`, so a test double has two members per operation to set up.

Nothing outside the repository consumes the SDK yet, so its generated shape can still change cheaply: every caller is internal and the compiler finds each one.

### Moq: what C# 14 changes

The issue and the CodeRabbit plan both assume CS0854 ("an expression tree may not contain a call that uses optional arguments"), so that every Moq expression that leaves out the token stops compiling. That is no longer true: C# 14 (the language version of the .NET 10 SDK, `LangVersion` latest) allows optional arguments to be left out in expression trees. A probe interface `Task<int> GetAsync(string a, string? b = null, CancellationToken cancellationToken = default)` with `api => api.GetAsync("x")` fails with CS0854 under `LangVersion` 13 and compiles under 14.

So the many `sform` test setups written against the overload without a token (for example `api.GetViewImportAsync(Org, Project, View, "job-2")`) compile unchanged. They now bind to the one member with the omitted arguments as constants, so Moq matches them only for calls with `CancellationToken.None` (and `null` for any omitted optional parameter). That is exactly what the calls they stood for pass: a call to the old overload without a token *was* a call with `CancellationToken.None`. The matching does not change.

What does break is at run time: a typed delegate given to `Callback` or `Returns`/`ReturnsAsync` must take every parameter of the method. Run against the regenerated file, 183 of the 1062 `sform` tests fail with `ArgumentException: Invalid callback. Setup on method with parameters (…, CancellationToken) cannot invoke callback with different number of parameters`, in 12 test classes (`MachineCreateFederatedTests`, `MachineCreateCommandTests`, `StorytellerTransferCommandTests`, `MachineAuthSetCommandTests`, `MachineIssuerCommandsTests`, `MachineRulesCommandTests`, `KeyValueSetAndGetCommandTests`, `KeyValueImportExportCommandTests`, `KeyValueProjectCommandTests`, `StorytellerSetCommandTests`, `KeyValueBulkAndDeleteCommandTests`, `StorytellerReadCommandsTests`).

## Proposed Changes

### 1. Generation

- Add `/GenerateOptionalParameters:true` to the command in the "Generate" section of `Sdk.NSwag/README.md`, and say what it does (one member per operation, optional parameters last with defaults, a required body ahead of them).
- Regenerate `src/ApiSdk.g.cs` from `open.api.v0.10.11.json` with NSwag 14.6.3. Check that the header still names 14.6.3.0 / 11.5.2.0 and that the diff has only the changes in the table above. No change to any `open.api.v*.json` or to `sdk.typescript`.

### 2. Hand-written SDK code

- `ApiSdk.Conditional.cs`: give `ifNoneMatch` of all five twins a default, `string? ifNoneMatch = null`, in the interface and in the class, so that the twins read like the regenerated reads (`GetConfigurationConditionalAsync(o, p, v, key)` is the first read of a poll). `format` of the formatted twins stays required. No change to what they send or return.
- `ApiSdk.partial.cs`, `ServicesCollectionExtensions.cs`: compile check only. The `null` of `AddStorytellerSdk(null, …)` is a DI argument, not an operation parameter, and stays.
- `Sdk.NSwag/test/ConditionalReadsTests.cs`: leave the placeholder `null`s out of the generated reads; keep the tests that pass a tag or an empty string; add a test that a twin called without `ifNoneMatch` and without a token sends no `If-None-Match`.

### 3. `sform`: the reordered operations

- `KeyValueImportCommand.cs:75`: `ImportKeyValuesAsync(org, project, view, document, mode, dryRun: true, keyPrefix: Prefix)`; `:97`: `ImportKeyValuesAsync(org, project, view, document, mode, keyPrefix: Prefix)`. The `null` that stood for `dryRun` in the apply call is left out.
- `StorytellerImportCommand.cs:95`: `archive` moves after `view`; `include`, `existing`, `IsForced ? true : null`, `IsDryRun ? true : null` and `fileName` follow in that order (the conditional values are options, not placeholders).
- Tests: the setups, verifications, callbacks and `ReturnsAsync` delegates at the lines listed above take the new order. Each fix is checked by hand against the parameter names, not only against the compiler: `mode`, `keyPrefix` and `fileName` are all `string`.

### 4. `sform` tests: typed callbacks

- Every typed `Callback<…>` and `Returns`/`ReturnsAsync` delegate set up on a generated operation gains a last `CancellationToken` type argument and a last lambda parameter (`_`). Parameterless callbacks stay as they are.
- Setups and verifications that leave out the token stay as they are (see "Moq: what C# 14 changes"): they keep matching `CancellationToken.None`, which is what `sform` passes. No `It.IsAny<CancellationToken>()` is added to them; that would loosen what they check and touch hundreds of lines for no change in behaviour.

### 5. Placeholder `null`s in production code

- Leave out every `null` that only fills an optional parameter at the end of a call, in `sform` and in the MCP server. Where a `CancellationToken` follows, pass it by name (`cancellationToken: cancellationToken`), since the `null`s before it are gone.
- Check each call against the regenerated signature before removing a `null`. A `null` before a value that is passed stays (no switch to named arguments: it would change lines for no gain). Conditional values (`x ? true : null`) and `null`s that build a body stay.
- `ifNoneMatch: null` on the twins (`ConfigGetCommand.cs`) goes, with the default of section 2.
- `Configuration` and `Hosting` are not changed: the provider passes live values to the twins.
- Mock setups and verifications in the MCP and `sform` tests keep every argument they list today.

### 6. Placeholder `null`s in tests that call the clients

- Leave the placeholders out of the direct client calls listed under "Current State" (they show the short form), keeping what each test asserts. A test that is about the value (`null` or `""` sends no header, an explicit tag is sent) keeps it.

### 7. Docs

- `Sdk.NSwag/README.md`: the command (section 1); the note on the generated reads (`format` and `if_None_Match` are optional; they still throw on `304` and return the body without the headers); the twins' `ifNoneMatch` is optional; the encryption example without `includeDeleted: null`; a note that the compiler lets a caller leave out a request body the document marks optional, but the API answers a missing body of most of them with `400`.
- `docs/Platform/Storyteller/export-import.md`: the new `StartViewImportAsync` order; line 657 says the body is optional in the SDK and the command always sends one.
- `inheritance.md:403` and `configuration-formats.md:66`: say the generated C# reads take `format` and the tag as optional parameters.
