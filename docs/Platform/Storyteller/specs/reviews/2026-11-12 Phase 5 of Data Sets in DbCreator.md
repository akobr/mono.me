# Phase 5 of Data Sets in DbCreator

## Overview

Phase 5 of the spec [Data Sets in DbCreator](../2026-11-12%20Data%20Sets%20in%20DbCreator.md) (424-252) covers section 5, the documentation. Phases 1 to 4 delivered the importer, the bulk writer, the sets, the commands, the built-in sets, Aspire, the tests and CI (see their reviews); phase 4 already updated `docs/github/workflows.md`, the `db-seed` row of the Aspire page and the Cosmos DB note of `docs/Platform/development.md`. This phase adds the page of the data sets, `docs/Platform/Storyteller/data-sets.md`, and brings the other pages that describe DbCreator, the import, the playground and the admin UI's showcase in line with the code as it is after phase 4. The pages describe the code, not the spec: where the phases deviated (the rounds of a seed, the plan before any write, the refusal of another owner's organization only for a missing project, the dry run over several sets), the pages follow the code. `CLAUDE.md` is left to the main agent. It is one commit, `docs(platform): document the data sets of DbCreator (424-252)`.

## What Was Done

### 5.1 `docs/Platform/Storyteller/data-sets.md` (new)

The page of the data sets, in the style of the other Storyteller pages (a code list, tables, relative links):

- **What DbCreator does**: the three commands; the root command unchanged in behaviour, with the core annotations now seeded as the set `core` through the services (audit entries, maintained relation arrays, a second run that writes nothing, a soft delete that stays), where every run upserted raw entities before; what `seed` does not seed.
- **A set**: the folder, the export's file names (only the names count), the reader shared with the import, what is ignored (version files, `export.json`, a nested `set.json`, other names) and skipped (hidden paths, `__MACOSX`), an unpacked export as a set, the limits of the reader for sets (1,000,000 files, 2 GiB, 2 MB per document), and what a set cannot carry.
- **`set.json`**: an example, a table of the members with their defaults and meaning, and the rules (any case, unknown members refused, comments and trailing commas, trimming, the name rules of the set name, `Version` of 1 or more).
- **`annotations.jsonl`**: literal and generator lines, `$count` and `$start`, the placeholders `{n}` and `{0…0}` in every string at any depth (the key included, not member names), the 200,000 limit counted before any expansion, duplicates against files and earlier lines, a table of the codes of a line that cannot be read, and what a failed line fails.
- **The catalog**: the built-in folder next to the tool (and in the tool package), `--path` (one set or a folder of sets), names found twice, `DependsOn` with cycles and unknown names.
- **The target**: options first, then the agreeing manifests of the named sets (not of the dependencies), the default view, the name rules (the dotted organization included); **the owner and the creation of the target** in the order of `DataSetProvisioner`: the refusal of a missing project in an organization the owner does not own, the account first, an existing project used as it is, the view registered with the System actor, a dry run that only reads.
- **The seed record**: where it is, its members, why the queries never see it, the hash (paths, NUL, content hashes, LF for text, Git's binary test), a table of what a seed does with no record, the same record, a changed set and a stopped run, and that a seed never overwrites or deletes.
- **Seeding a set**: the steps of `DataSetSeeder`, with the rounds of files and lines (the deviation of phase 3) and the lines that cannot be read failing before the files; sets after a failed dependency; the outcomes and codes with a link to the import's; the dry run with the overlay carried over the steps and the sets, and its one remaining difference.
- **Bulk writing**: the decisions, the reads of many items, the units and waves (100 operations, about 1.5 MB, plans of 2,000 units, 4 batches at once), the relations wave with its repair, the retries (5 attempts, `RetryAfter` or the fallback), and the progress lines.
- **Timings** from the phase 3 and 4 reviews (vNext emulator): the root run, `large` (41 s), 10,000 annotations (35 to 39 s), dry run, seeded already, `--again` (30 s), `showcase` (24 to 25 s), the playground, and the slowdown of a filled emulator.
- **Commands**: the configuration (`ConnectionStrings__cosmos` before `CosmosDb__Connection`, `app.config.json`, `baseAccount__id`, `stagingSeed__enabled`), the root, `seed` with every argument and option and its steps (the plan before the database, the containers also in a dry run), an example output assembled from `DataSetOutput`, `sets`, and the exit codes `0`, `-1`, `1`, `2`, `3` and `4`.
- **The built-in sets** `core`, `large` and `showcase` with their targets and content, and the playground's folder; `showcase` is generated by `showcase-set.test.ts` and regenerated with `npx vitest run test/unit/mock/showcase-set.test.ts -u` (the path first), never edited by hand.
- **Adding a set**, **Running it** (`dotnet run`, the Aspire resources `db-creator` and `db-seed`, the dotnet tool from `dotnet pack`, production through the cookbook) and **Tests** (the four test projects involved, the commands, the emulator note, CI).

The Storyteller docs have no index page and are not part of the VitePress sidebar (`docs/42for.net/.vitepress/config.mjs` lists only `docs/42for.net/platform/`), so none was created. The page is linked from `export-import.md`, `annotation-lifecycle.md`, `playground.md`, the Aspire page, `development.md`, the admin UI README and both deployment documents.
