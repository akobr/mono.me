# Phase A of TypeScript SDK

## Overview

Phase A delivers section 1 of [TypeScript SDK and API extensions for the Administration UI](../2026-10-09%20TypeScript%20SDK%20and%20API%20extensions%20for%20the%20Administration%20UI.md): the npm package `@42for.net/2splatform.sdk` in `src/Platform/Storyteller/sdk.typescript/src`.

- **Input:** generated by Orval 8 from `open.api.v0.8.91.json`. That export already contains the endpoints of phases 0a to 0c, so the planned two-step generation (first v0.8.89, later 0.9) collapsed into one run.
- **Outputs:** four outputs from one document:
  - plain fetch functions;
  - TanStack Query for Vue composables;
  - Zod 4 schemas;
  - MSW handlers with Faker data.
- **Hand-written code:** the fetcher (the Orval mutator), the error type and helpers for annotation keys, roles, paging and cache invalidation.
- **Project and solution:** the package builds with tsup, is tested with Vitest, and is part of `42.mono.slnx` through `sdk.typescript.esproj`.

### 1.2 Orval configuration

`orval.config.ts` has three targets: `client`, `vueQuery` and `zod`. All of them use `mode: 'tags-split'`, `formatter: 'prettier'` and one input with a transformer. The option names were checked against Orval 8.41, and several differ from the spec:

| Spec | Implemented | Why |
| --- | --- | --- |
| `prettier: true` | `formatter: 'prettier'` | Orval 8 name. |
| `clean: true` per target | `scripts/generate.mjs` deletes `generated/` once | `client` and `vueQuery` share `generated/model`, so a per-target clean would delete each other's output. |
| `shouldExportQueryKey` | `query: { signal: true, shouldExportKeys: true }` | Orval 8 name. |
| `query.useQuery: true, useMutation: true` | not set | With `useQuery: true`, Orval generates **every** operation as a query, including PUT, PATCH and DELETE. The defaults already give queries for GET and `useMutation` for the rest. |
| `mock: { type: 'msw', … }` | `mock: { generators: [{ type: 'msw', useExamples: true, delay: false, baseUrl: '*/api' }] }` | Orval 8 shape. |
| `useDates: false` | not set | It is the default. |
| (zod) | `override: { zod: { version: 4 } }` | Selects Zod 4 explicitly. |

**Input transformer** (`scripts/openapi-transformer.mjs`). It corrects the document before all three targets read it:

1. **JSON Patch bodies.**
   - **Problem:** `PatchConfiguration` and `PatchTemplate` declare `[OpenApiRequestBody("application/json-patch+json", typeof(JArray))]`, which the OpenAPI extension documents as `type: object`. The SDK would then type a JSON Patch document as `{ [key: string]: unknown }`, and the Zod schema would reject every real patch, because a patch is an array.
   - **Fix:** the transformer adds `components.schemas.JsonPatchOperation` (`op` enum, `path`, `from`, `value`, with `op` and `path` required). It sets every `application/json-patch+json` body to a **required** `JsonPatchOperation[]`.
   - **Result:** `patchConfiguration(org, project, view, key, operations, params?)`, `PatchConfigurationBody = zod.array(…)`, and mutation variables `{ …, data: JsonPatchOperation[] }`.
2. **Deprecations.** `GrantUserAccess` and `RevokeUserAccess` are marked `deprecated`, as suggested in the phase 0b review, so the generated functions and composables carry `@deprecated` and the UI uses the members endpoints. The API document itself is unchanged, so NSwag emits no `[Obsolete]` for the CLI.

### 1.3 Generated surface (v0.8.91)

89 operations in 5 tags:

| Tag | Operations | Notes |
| --- | --- | --- |
| Access | 29 | the spec's list, plus `getMembers`, `setMemberRole`, `removeMember`, the invitation operations (`getInvitations`, `createInvitation`, `resendInvitation`, `revokeInvitation`, `getMyInvitations`, `acceptInvitation`, `declineInvitation`), `grantUserAccess` and `revokeUserAccess` (deprecated, section 1.2), `getMachineAccess` and `renewMachineCertificate` |
| Annotations | 17 | the spec's list, plus `setAnnotationsSimple` and the views registry (`getViews`, `createView`, `updateView`) |
| Configurations | 11 | the spec's list, plus `getConfigurations` (listing) |
| Schemas | 23 | type, annotation and descendant-type schemas with versions and diffs, `getCombinedConfigurationSchema`, `getConfigurationSchemas` (listing) |
| Templates | 9 | the spec's list, plus `getTemplates` (listing) |

- **Request functions:** each function takes path parameters, then the body, then query parameters, then `options?: RequestInit`.
- **Query composables:** they accept `MaybeRefOrGetter` parameters and `{ query?, request? }` options.
- **Query keys:** they are the path segments, for example `['v1', org, project, view, 'configuration', key]`, followed by the params object when there are query parameters.
- **Mutation composables:** they take `{ mutation?, request? }` and a `QueryClient`, and are called with variables such as `{ organization, project, view, key, data, params }`.
- **Path parameters** are not URL-encoded by Orval's fetch client. Names follow `NameRules`, and annotation keys contain only name segments and dots, so this is safe for the current API.

### 1.4 Fetcher (`lib/fetcher.ts`)

It is implemented as specified, with these details:

- **Token provider:** `getAccessToken` may return the token synchronously or as a promise.
- **URLs:** `configureStoryteller` trims trailing slashes from `baseUrl`, and absolute URLs passed by a caller are used unchanged.
- **Headers:** headers from the configuration are merged with the caller's headers.
- **401 handling:** after a `401`, the request is sent once more with a fresh token. If that also returns `401`, `onUnauthorized` is called and the error is thrown.
- **Response bodies:**
  - `204`, `205`, `304` and empty bodies return `undefined`;
  - `application/json` and `application/*+json` are parsed;
  - every other content type is returned as text (PEM, unified diffs).
- **Failures before a response:**
  - a network failure becomes `StorytellerError` with `status: 0` and the message "The Storyteller API is not reachable (…)", with the path only;
  - an abort becomes `StorytellerError` with `status: 0` and the message "The request was aborted.".
- **Typed errors:** the mutator file also exports `ErrorType<T> = StorytellerError` and `BodyType<T> = T`, which Orval picks up. The `error` of every generated query and mutation is therefore typed as `StorytellerError` instead of `ErrorResponse | void`. That matches what the fetcher actually throws.
- **One configuration instance:** tsup emits a shared chunk for the four entry points, so `configureStoryteller` from `.` configures the same module instance that `./vue-query` uses. A Node ESM import of `dist/` confirmed this.

### 1.5 Hand-written helpers

- **`errors.ts`:**
  - `StorytellerError` has `status`, `hint`, `errorCode`, `schemaErrors` (the generated `SchemaValidationErrorDetail[]`) and `body`.
  - `fromResponse` reads `Message`, `Hint`, `ErrorCode` and `Errors`. When they are missing, it falls back to the text body or to the status line.
  - Guards: `isStorytellerError`, `isUnauthorized`, `isForbidden`, `isNotFound`, `isConflict`, `isPreconditionFailed`, and `hasErrorCode(error, code)` for the `ErrorCodes` of phases 0a to 0c (`LastOwner`, `PatchTestFailed`, …).
- **`invalidation.ts`:**
  - Orval 8 query keys are segment arrays, not one path string as the spec assumed.
  - `pathToQueryKey` splits a path into those segments and drops the query string.
  - `invalidateByPath` and `removeByPath` rely on TanStack's prefix matching. `queryKeyStartsWith` (the spec's `pathKeyStartsWith`) is exported for custom predicates.
- **`paging.ts`:**
  - `paginate` (an async generator) stops on a missing or empty token and checks `signal.throwIfAborted()` before every page.
  - `collectAll(fetchPage, selectItems, signal)` flattens the pages into one array.
- **`keys.ts`:**
  - `annotationTypes` (code, segment count, merge order), `getAnnotationTypeInfo`, `parseAnnotationKey` (case-insensitive type code), `isValidAnnotationKey`, `isValidName` and `buildAnnotationKey` (throws on a missing or invalid part).
  - `getDirectAncestors` follows the merge order from `inheritance.md`. `getAllAncestors` is level-ordered and de-duplicated.
- **`roles.ts`:** `roleOrder`, `roleRank`, `hasRole`, and `getRole(accessMap, accessPointKey)`, where unknown values count as `None`.

### 1.6 Package

- **Exports and peers:**
  - `package.json` follows the spec for the name, `type: module`, `sideEffects: false`, the four `exports`, `files: ["dist"]` and `engines.node >= 22.18`.
  - All peers are optional (`@faker-js/faker >= 9`, `@tanstack/vue-query ^5`, `msw ^2`, `vue ^3.5`, `zod ^4`).
- **Version:** `0.8.91`. `npm run generate` takes the first three parts of `info.version` (`0.8.91.29486` → `0.8.91`).
- **Scripts:** `generate`, `build` (tsup), `prepare`, `typecheck`, `lint` and `test`.
- **Dev dependencies:** Orval 8.41, TypeScript 6.0, tsup 8.5, Vitest 4.1, oxlint 1.87, Prettier 3, MSW 2.15, Faker 10, Vue 3.5, TanStack Vue Query 5, Zod 4.6.
- **Deviations:**
  - **tsup instead of `tsc -p tsconfig.build.json`:** it gives one shared chunk (section 1.4) and declaration files per entry point, so there is no `tsconfig.build.json`. The DTS build needs `ignoreDeprecations: '6.0'`, because tsup sets `baseUrl`.
  - **TypeScript 6.0 instead of 5.x:** 6.0 is current. TypeScript 7 (native) is not supported yet by tsup's declaration build or by typedoc, an Orval peer.
  - **ESLint dropped for the SDK:** lint is oxlint only, plus `tsc --noEmit` with `strict` and `noUncheckedIndexedAccess`. The hand-written code is small, and `generated/` is excluded anyway. `ui.admin` keeps oxlint plus ESLint as planned.
  - **No `version.json` (NBGV):** the package version is the API version, set by the generate script. NBGV would need an extra npm integration and would version by commit height instead.
  - **`.nvmrc` pins Node 24 LTS.**
- **npm 10.9.2 crash:** npm 10.9.2 crashes (`Cannot read properties of null (reading 'edgesOut')`) when it resolves this dependency set without a lockfile. The lockfile was created once with `--legacy-peer-deps`. `npm ci` and `npm install` from the lockfile work, and the README documents this.

### 1.7 esproj and solution

`sdk.typescript.esproj` uses `Microsoft.VisualStudio.JavaScript.Sdk/1.0.6887863` (the spec had 1.0.6578810):

- **No Node by default:** `ShouldRunNpmInstall` and `ShouldRunBuildScript` are false unless `-p:BuildJavaScript=true` is passed.
- **NU1012 fix:** the project clears `TargetPlatformIdentifier` and `TargetPlatformMoniker`. The JavaScript SDK sets `None`, which NuGet in the .NET 10 SDK rejects with `NU1012: net6.0-none`.
- **Solution:** the project is added to `42.mono.slnx` under `/Platform/Storyteller/`, after `Sdk.Kiota`.
- **Verified builds:** `dotnet build` of the esproj succeeds both with and without `-p:BuildJavaScript=true`.

- **API: 0.9 bump.** Bump the API to 0.9 when the next export is made (companion spec, section 3). Then delete the superseded `open.api.v0.8.*.json` files and regenerate `Sdk.NSwag`.
- **CI.** Add a check that regenerates the SDK and fails on `git diff --exit-code` (spec section 1.1). It could join the `ui.admin` workflow planned in the UI spec.
- **Path parameter encoding.** If keys ever allow characters outside the name rules, encode path parameters in the fetcher or through an Orval `override.paramsSerializer`.
- **Node and npm.** Move local development to Node 24 LTS with a current npm. That removes the npm 10.9.2 workaround and the Vitest engine warning on Node 23.
