# Phase 2 of Native Key-Value Storage

## Overview

Phase 2 of [Native Key-Value Storage](../2026-10-11%20Native%20Key-Value%20Storage.md) (sections 23–26) exposes the key/value service of Phases 1a and 1b through the Functions API: the view-scoped routes of the pairs, their versions, diffs, export and import, and the project-scoped routes of the policy, the customer key, rotation, the recipients, the audit trail and the usage report. It adds the two machine scopes for secrets, reserves the route words, exports the OpenAPI document (version `0.8.97` at the time; `0.9.6` after the rebase on `main`, see the note at the end) and regenerates both SDKs: the C# client gains `IKeyValuesApiClient` and a client-side encryption helper, the TypeScript SDK gains the `key-values` functions, composables, schemas and mocks, the helpers of `lib/key-values.ts` and the subpath `./hyok`. The CLI (Phase 3) and the admin UI (Phase 4) are not part of it.

Every test project that the change touches is green: `Api.Functions.UnitTests` 232 (60 new) in Debug, `Backend.CosmosDb.UnitTests` 296 (4 new: the three reserved words and the TypeScript document), `KeyValues.Azure.KeyVault.IntegrationTests` 13, `Access.Certificates.UnitTests` 60, `Binding.Language.UnitTests` 103, `Binding.Object.UnitTests` 194, and the TypeScript SDK 99 (37 new) with `typecheck`, `lint` and `build` clean. `dotnet build 42.mono.slnx` succeeds. The API tests also ran in Release, where the Debug-only `DEV_AUTH` shortcut is off: every new test passes, and the two failures (`MachineHttpTests.GetMachine_StoredRecord_ReturnsIt`, `KeycloakId_GetResetAndDelete_ReachTheAccessService`) are older tests that count the access-service calls a Debug build skips; they are untouched by this phase.

## What Was Done

### 23. Routes

- `Api.Functions/src/Definitions.cs`: `Routes.KeyValues.V1` (the view-scoped `…/{view}/key-values`, `…/{key}`, `restore`, `purge`, `protect`, `export`, `import`, `…/{key}/versions[/{version}[/diff[/{versionFrom}]]]`, and the project-scoped `…/key-values/policy`, `policy/byok/setup`, `policy/byok/verify`, `policy/rotate`, `recipients[/{id}]`, `audit`, and `…/usage/key-values`), `RouteIds.KeyValues` with the operation names of the spec, the tag `KeyValues`, the query parameter names and the shared response descriptions.
- `V1/KeyValuesHttp.cs` (the pairs), `V1/KeyValuePolicyHttp.cs` (policy, BYOK, rotation, recipients) and `V1/KeyValueUsageHttp.cs` (audit, usage); `V1/KeyValueRequests.cs` holds the shared authorization helpers and the query parsing. Every handler follows the `CheckScope` and `CheckAccessToProjectAsync` pattern, takes the caller from `GetSecretRightsAsync(...).AsAmbient()`, and lets the domain exceptions reach the middleware (403, 404, 409, 412, 424, 501, 503 with their error codes).
- The collection actions are `POST` only and no route with `{key}` accepts `POST`, so a key named `restore` or `export` is reached with `GET`, `PUT` and `DELETE`; `RouteTableTests.KeyValueActions_ArePostOnly_AndKeyRoutesNeverPost` keeps it that way. The behaviour of the Functions router itself was not exercised by a running host in this phase.
- **Deviation:** `key-values` joined `audit` and `usage` in `NameRules.ReservedProjectAndViewNames`, because the project-scoped routes put the literal `key-values` where the view routes have `{view}`; a view of that name would make its key `policy` unreachable.
- **Deviation:** a query parameter that does not parse (a level, a state, a boolean, a version, a date) answers `400` with the new code `InvalidQuery`, so the clients can tell it from a bad body.
- `DiffUnifiedResponseDocumentFilter` lists the two key/value diff operations, so their `200` offers `text/plain` as well.
- The responses that carry a secret value (a reveal, a revealed version, an export with secrets, the diffs of a caller with secret rights) are `Cache-Control: no-store`; `PUT` strips the value of a secret from its response, as the service returns it for public pairs only.

### 24. Authorization

- The matrix of the spec is implemented as documented in `key-values.md`: Readers list, read without reveal, see versions, policy and recipients; Contributors write public pairs, restore and import public items; secrets need secret rights, which the service enforces per key (a bulk restore by a Contributor gives `Forbidden` for the secrets only); permanent deletes, purges, the policy, the customer key, rotation, the recipients, the audit trail and the usage are Administrator operations that `KeyValueAuthorization.CheckAdministratorAsync` refuses to any machine before the role is looked up.
- An explicit request for a secret (a reveal, a secret version or diff, an export with secrets, a write of a secret) by a machine whose only missing piece is the mTLS certificate answers `403 MtlsRequired`: the handlers check `SecretRights.IsWithheldByMtls` up front where the request says it wants a secret, and `UnderMtlsRuleAsync` turns the service's `AccessDenied` into `MtlsRequired` where only the service knows the key is a secret.
- `MachineAccessScope.SecretsRead = 6` and `SecretsReadWrite = 7`; `MachineAccessScopes.Get` maps them to `Configuration.Read` + `Configuration.Secrets` (+ `Configuration.ReadWrite`). `ApiKeyAuthenticationMiddleware` now uses that one mapping instead of its own copy, so API-key machines get the new scopes too; AuthKit machines get every `PermissionMap` permission that falls within the scope (a permission mapped to `Configuration.Secrets` now reaches these two scopes), and Keycloak clients get the scopes in their claim. `AzureAdMachineAccessService` assigns the optional app roles `Auth:AppRoles:SecretsRead` / `SecretsReadWrite` and answers `400 ProtectionNotConfigured` when a deployment has not configured them; the options validator still requires only the two base roles.

### 25. OpenAPI and SDKs

- **Export without a host.** `Api.Functions/test/OpenApiExportTests.cs` renders the document with the engine the Functions host uses (`OpenApiHttpTriggerContext`, the API's `OpenApiConfigurationOptions`, visitors and document filters) and writes it to the path in `STORYTELLER_OPENAPI_EXPORT`. The extension scans every assembly next to the one it renders, and next to the test copy sit the test platform assemblies whose types do not load, so the test renders the copy in the API project's own output directory, loaded in a separate `AssemblyLoadContext`. The document is `open.api.v0.9.6.json` in `Sdk.NSwag/` and `sdk.typescript/` (it was `v0.8.97` before the rebase); both folders keep their earlier copies. The READMEs of both SDKs describe the procedure.
- **NSwag.** `Sdk.NSwag/src/ApiSdk.g.cs` regenerated with NSwag 14.6.3 (the version of the previous generation): `KeyValuesApiClient` / `IKeyValuesApiClient` with one method per operation, registered by `AddStorytellerSdk`, and the partial constructor with `ISdkConfiguration` like the other clients.
- **C# client-side encryption.** `Sdk.NSwag/src/ClientSideEncryption/KeyValueClientEncryption.cs` builds on the `KeyValues.ClientEncryption` project (a project reference, so the SDK package depends on that package): `Encrypt(value, recipients, organization, project, view, key)` takes the generated `ClientEncryptionRecipient` models and skips disabled ones, `CreateWrite` returns a ready `KeyValueWrite` of the `Hyok` level, `Decrypt(document, recipientId, privateKey)` and `GetPlace(document)` read one. **Deviation:** the spec placed the JWE code itself in the SDK; it lives in `KeyValues.ClientEncryption` since Phase 1b, so the SDK only adapts the generated models.
- **TypeScript SDK.** `npm run generate` from the new document produced the `key-values` client, Vue Query composables with their keys, Zod schemas and MSW handlers; `msw.ts` adds `getKeyValuesMock()` to `getStorytellerMock()`, and the package version follows the document (`0.9.6`).
  - `lib/key-values.ts`, exported from the root entry: `isValidKeyValueKey`, `normalizeKeyValueKey`, `isSecretProtection`; `parseDotEnv` and `serializeDotEnv` (`#` comments, `export`, double-quoted values with `\n`, `\r`, `\t`, `\"` and `\\`, single-quoted literals, inline comments after unquoted values, `db.password` ↔ `DB__PASSWORD`); `flattenJson`, `unflattenJson`, `toFlatJson`, `toKeyValueDocument`; `detectKeyValueFormat` (`document`, `flat-json`, `json`, `dotenv`, `unknown`); `isSecretReference`, `parseSecretReference` (the `kv://` shorthand, the vault URI and App Configuration's `{ "uri": … }`) and `formatSecretReference`.
  - `hyok.ts`, the subpath `./hyok` (a tsup entry and a package export): `encryptForRecipients(value, recipients, place, contentType)` accepts the generated recipient shape or a plain `{ id, publicKey }` with a JWK or a SPKI PEM, refuses keys under 3072 bits, and writes the same JWE General JSON Serialization as the C# library; `decryptClientSecret(jwe, privateKey, recipientId)` takes a `CryptoKey`, a private JWK or a PKCS#8 PEM; `getHyokPlace`, `parseHyokDocument`, `readHyokHeader`, `getHyokRecipientIds` and `generateRecipientKeyPair` (3072-bit RSA-OAEP-256 by default) complete it. WebCrypto only, so it runs in browsers and in Node 22 or later; `jose` is a dev dependency for the interoperability tests.
- The admin UI (`ui.admin`) links the SDK by path; its production build was run against the regenerated package to make sure the existing screens still compile.

### 26. Tests and documentation

- `Api.Functions/test/KeyValuesHttpTests.cs` (29 cases): the caller passed to the service (rights, channel, correlation id), the mTLS rule for reveals, writes, protect, export and diffs, the `MtlsRequired` and `AccessDenied` outcomes, `no-store` cannot be observed without the ASP.NET Core context and is not asserted, the stripped secret value of `PUT`, 404 with `KeyValueNotFound`, the bulk validation (keys or a prefix, the level of protect), the machine refusals of the Administrator operations, the query parsing of the listing, the import and the audit, `InvalidQuery`, the diff versions, the policy and recipient handlers, and the usage defaults (the last 30 days, on a fixed clock). Role refusals of users skip under `DEV_AUTH` and ran in Release. `KeyValueTestDoubles.cs` has the request builders, the recording services and the shared `RoleAccess` / `FixedKeyValuePolicies`, which `SecretRightsTests` now uses too.
- `OpenApiExportTests` (every key/value operation under the tag, `KeyValuePolicy` among the schemas, the server URL, the unified diff content type), `RouteTableTests` (the 25 routes, the POST-only invariant), `MachineAccessRulesTests` (the two scopes), `NameRulesTests` (the three reserved words).
- `Backend.CosmosDb/test/ClientEncryptionAndReferenceTests.Document_FromTheTypeScriptSdk_ValidatesAndDecrypts`: a document the TypeScript SDK encrypted for a committed test key is validated by the server's validator and decrypted by the C# library.
- TypeScript: `test/key-values.test.ts` (keys, `.env` parsing, serializing and the round trip, flattening, documents, format detection, references) and `test/hyok.test.ts` (several recipients, the API recipient shape with disabled ones, refusals, tampering, `jose` decrypts what the SDK writes and the SDK decrypts what `jose` writes, PEM keys); `test/msw.test.ts` also checks `getKeyValues` and `getKeyValuePolicy` against the generated mocks and schemas.
- **Left out:** the recording-logger test that searches the output of every endpoint for a plaintext. The handlers log keys and counts only, and the service never logs values; a test that proves it across the endpoints needs the function host pipeline and stays open.
- Documentation: `key-values.md` has the API section (routes, who may do what, examples, the SDKs) and the updated delivery rules; `authentication.md` the two machine scopes, the Entra app roles and the AuthKit permission rule; `access.md` the reserved words; `Sdk.NSwag/README.md` the export procedure and the client-side encryption; `sdk.typescript/README.md` the export procedure, the helpers and `./hyok`.

## Rebase on `main` (13 Oct 2026)

`main` had moved to `0.9-alpha` and shipped its own OpenAPI document (`v0.9.1`, soft-delete and audit of annotations) before this branch was merged.
