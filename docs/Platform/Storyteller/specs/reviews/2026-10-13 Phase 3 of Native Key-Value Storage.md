# Phase 3 of Native Key-Value Storage

## Overview

Phase 3 of [Native Key-Value Storage](../2026-10-11%20Native%20Key-Value%20Storage.md) (sections 27–28) adds the `sform story kv` command group to the CLI, on the C# SDK of Phase 2: the listing and the pairs, the lifecycle (delete, restore, purge, protect), versions and diffs, export and import in three file formats, local encryption and decryption of client-encrypted values with re-encryption for new recipients, and the project commands for the policy, the customer key, rotation, the recipients, the audit trail and usage. On the way it fixes two defects of the generated clients that the CLI ran into: the OpenAPI document declared a default for nullable enums and described `DateOnly` as an object, so the document and both SDKs were regenerated. The admin UI (Phase 4) is not part of it.

Every test project that the change touches is green: `Cli.UnitTests` 122 (47 new), `Api.Functions.UnitTests` 235 (3 new), the TypeScript SDK 99, and `Sdk.NSwag` builds with the regenerated client. `dotnet build 42.mono.slnx` succeeds.

## What Was Done

### 27. Commands

- `src/Platform/Cli/src/Commands/KeyValues/`: `KeyValueListCommand` (`kv`, `key-values`; the group with every subcommand), `KeyValueGetCommand`, `KeyValueSetCommand`, `KeyValueDeleteCommand`, the bulk commands `KeyValueRestoreCommand`, `KeyValuePurgeCommand` and `KeyValueProtectCommand` (`KeyValueBulkCommands.cs`), `KeyValueVersionsCommand` and `KeyValueDiffCommand` (`KeyValueVersionsCommand.cs`), `KeyValueExportCommand`, `KeyValueImportCommand`, `KeyValueReencryptCommand`, the policy group (`KeyValuePolicyCommand`, `set`, `byok-setup`, `byok-verify`, `rotate`), the recipients group (`KeyValueRecipientsCommand`, `add`, `enable`, `disable`, `remove`), `KeyValueAuditCommand` and `KeyValueUsageCommand`. `StorytellerListCommand` lists the group; `CommandNames` gained the words of the spec plus `byok-setup`, `byok-verify`, `rotate`, `add`, `enable` and `disable`.
- `KeyValueCommandBase` holds `IKeyValuesApiClient` and turns an `ApiException` into the message and error code of the API's `ErrorResponse` and an exit code (`WARNING_UNAUTHORIZED_ACCESS` for 401 and 403, with the mTLS explanation for `MtlsRequired`; `ERROR_WRONG_INPUT` for 400, 404, 409 and 412; `ERROR_CRASH` otherwise). `KeyValueBulkCommandBase` takes keys or `--prefix`, never both. `KeyValueLevels` parses the level names case-insensitively and converts them to the per-property enums of the generated client. `ExitCodes.WARNING_PARTIAL_RESULT = 45` is the exit code of a bulk operation or an import that did not do every key.
- **Deviation:** the spec's `-p|--prefix` and `-v` were not free: `BaseContextCommand` already uses `-p` for the project key and `-v` for the view, so the prefix is `--prefix` only, and `--values`, `--deleted`, `--all` are long options. `-k|--continuation-token` is as planned.
- **Listing and reading.** The table shows Key, Level, Version, Author and Updated, with `--values` the public values (secrets as `••••••`, references marked), and with `--deleted` or `--all` the expiry of a deleted key. `get` prints the pair as JSON (`--value-only` the value alone, `--version` one stored version, `-e` saves it). With `--private-key` (a file or the PEM text) a `hyok` value is decrypted locally by `ClientSecretDecryptor`; `--kid` picks the recipient, and is optional when the document has one.
- **Writing.** `set` decides the level as the spec says: `--protection`, `--secret` for the policy's `DefaultSecretProtection`, `--reference` for a public reference (the content type `application/vnd.2s.secret-reference`, refused with a secret level), otherwise one `GET` tells a new key (stored `Public`, with a note) from an existing one (the level is kept by sending no `Protection`). The value comes from the argument, `--stdin`, `-i <file>`, or the hidden prompt (`Password`) for a secret; a secret as an argument prints the shell-history warning. A `hyok` value is encrypted with `KeyValueClientEncryption.Encrypt` for the enabled recipients of `GET …/recipients`.
- **Lifecycle.** `delete` prints the restore command; `--permanent` asks to type the key unless `-y`. `purge` asks for a confirmation (the view name for a prefix), `protect` refuses `public` and `hyok` before the call and reminds that older versions keep their level. The bulk results are a table of Key, Outcome, Version and Note, and the exit code is `45` when a key was not done.
- **Files.** `KeyValueFormats` ports the conventions of the TypeScript SDK: the `json` document, `flat` JSON (nested objects flattened to dotted keys on import, one flat object on export), and `env` lines with comments, `export`, quoted values and escapes, `db.password` ↔ `DB__PASSWORD`. `Detect` looks at the file name (`.env`, `*.env`, `.env.*`), then at the content (`Format` or `Items` make a document, another object is flat). `KeyGlob` matches `--secret` globs case-insensitively. `import` always runs the server's dry run first, prints the plan, asks for a confirmation unless `-y` (the view name when the plan deletes keys), then imports; `--dry-run` stops after the plan. `export` leaves secrets without a value out of `flat` and `env` with a note that names them.
- **Re-encryption.** `reencrypt` lists the `hyok` keys under the prefix (or takes the keys), reveals each, decrypts it with the given recipient's private key, encrypts it for the current recipients and writes it as a new version with `ExpectedVersion` set to the revealed version, so a concurrent change is not overwritten. Keys that are not client-encrypted or not encrypted for the given recipient are skipped and reported, with exit code `45`.
- **Project commands.** `policy` prints the policy as JSON; `policy set` builds a `KeyValuePolicyUpdate` with only the given members (`--hsm-rotation-days` becomes a `TimeSpan` string, `--byok-key` and `--byok-tenant` the `Byok` settings) and refuses an empty change. `policy byok-setup` prints the four steps with the consent URL and the role, `policy byok-verify` the health and version of the customer key, `policy rotate` refuses `byok` and shows the re-wrap counters. `recipients add` reads the public key from a file or inline; `enable`, `disable` and `remove` (with a confirmation) complete it. `audit` passes `--key`, `--operation`, `--from`, `--to`, the continuation token, and the view only when `-v` was given, since the project commands ignore the context view otherwise. `usage` takes `--from` and `--to` as `yyyy-MM-dd`.
- **Deviation:** `diff` has no `--reveal`; the server delivers the text of a secret diff to a caller with secret rights and refuses the others, so a flag would change nothing.
- **Deviation:** `recipients` gained `enable` next to `disable`, because the API has it.

### Fixes of the generated clients (Phase 2 follow-up)

- The OpenAPI generator declared the first member as the `default` of every enum property, also of the nullable ones whose absence means "keep" or "unset". NSwag then initialized `KeyValueWrite.Protection`, `KeyValueBulkRequest.Protection` and `KeyValuePolicyUpdate.DefaultSecretProtection` to `Public`, and the Zod schemas applied the same default, so an SDK update without a level would have turned a secret public. `Api.Functions/src/OpenApi/Filters/NullableEnumDefaultDocumentFilter.cs` removes the default from nullable enum properties (and items); `NullableEnumDefaultDocumentFilterTests` covers the filter and the rendered document.
- `System.DateOnly` (`KeyValueUsageReport.From`, `To`, `KeyValueUsageDay.Date`) was described as an object with `Year`, `Month` and `Day`, while the API serializes it as `"2026-09-01"`; NSwag generated a `DateOnly` class (which also made `DateOnly` ambiguous in the CLI) and the TypeScript model an interface. `DateOnlySchemaDocumentFilter` turns the shared schema into a `string` with the `date` format, so the C# client has `DateTimeOffset` members and the TypeScript model a string alias.
- The document was exported again, because the Phase 2 commit raised the build height (`0.8.98` at the time). After the rebase on `main` the branch carries a single document, `open.api.v0.9.6.json`, generated once for Phases 2 to 4 (see the rebase note in the Phase 2 review).

### 28. Tests and documentation

- `Cli/test/Commands/KeyValues/`: `KeyValueFormatsTests` (the `.env` grammar and round trip, flat JSON, format detection, the format names, the levels of parsed entries and the secrets left out of `env`, globs, the level parsing and conversion), `KeyValueSetAndGetCommandTests` (the hidden prompt, the warning for a secret argument, `Public` for a new key and no level for an existing one, references, local `hyok` encryption with a disabled recipient skipped, the file source and the source conflict, `--value-only`, local decryption with `--kid`, the API error message), `KeyValueBulkAndDeleteCommandTests` (the request shape without a level, keys-or-prefix, the purge confirmations, the protect level rule, the restore hint and the permanent-delete confirmation, the exit codes of `MtlsRequired`, a version mismatch and a server error), `KeyValueImportExportCommandTests` (an `.env` import with the plan, the glob to the policy's default secret level and the second call, dry run and a declined plan, a `replace` with deletes and the typed view name, the input errors, `env` output with the skipped secrets, `json` with secrets, the file name deciding the format), `KeyValueProjectCommandTests` (the partial policy update, BYOK settings, rotation of `standard` only, the BYOK setup and verification texts, the recipient commands, re-encryption with a skipped key, the audit filters, the usage days). `KeyValueTestDoubles` has the context, pairs, API errors, a file system double and `TestRecipient` with a 3072-bit key pair.
- `RecordingConsole` now also records the documents of `Write`, `WriteImportant` and `WriteHeader` (their children reduced to text), so the tests can assert the important lines; the older command tests still pass with it.
- **Left out:** a test of the hidden prompt itself (the console is a mock, so the test checks that `Password` is asked and its value is sent) and of `--stdin`, which reads the real console input.
- Documentation: `key-values.md` has the CLI section with the synopsis of every command, the rules of the levels, the files and the confirmations, and an example per command; the overview names this review. `Sdk.NSwag/README.md` names the new document version.
