# Phase 1b of Native Key-Value Storage

## Overview

Phase 1b of [Native Key-Value Storage](../2026-10-11%20Native%20Key-Value%20Storage.md) (sections 11–22) delivers the project policy, the `Hsm`, `Byok` and `Hyok` levels, references, the change of a key's level, key rotation with the re-wrap, the secret delivery rules with the durable certificate store and the transport middleware, the audit trail and the usage meters. It adds the project `KeyValues.ClientEncryption` (the JWE helpers the clients will share), the HSM and customer-key providers in `KeyValues.Azure.KeyVault`, two timer functions in the API, and the policy, maintenance, audit and usage services in `Backend.CosmosDb`. The API endpoints (Phase 2), the CLI (Phase 3) and the admin UI (Phase 4) are not part of it.

Every test project that the change touches is green: `Backend.CosmosDb.UnitTests` 292 (27 new), `KeyValues.Azure.KeyVault.IntegrationTests` 13 (7 new, on Lowkey Vault), `Api.Functions.UnitTests` 172 (26 new), `Access.Certificates.UnitTests` 60, `Binding.Language.UnitTests` 103 and `Binding.Object.UnitTests` 194. `dotnet build 42.mono.slnx` succeeds. One Key Vault run failed once with "The SSL connection could not be established" against the emulator container and passed on the rerun; nothing in the code changed between the two runs.

## What Was Done

### 11. Project policy

- `Abstractions.Annotations/src/Model/KeyValues/KeyValuePolicy.cs`: `KeyValuePolicy`, `ProtectionKeyInfo`, `HsmSettings` with `HsmBackend`, `ByokSettings` with `ByokHealth`, `ClientEncryptionRecipient`, `RewrapStatus`. `KeyValuePolicyUpdate.cs` carries the partial update (`AllowedProtections`, `DefaultSecretProtection`, `RequireMtlsForSecretDelivery`, `Hsm`, `Byok`, `ExpectedVersion`), and the recipient create and update models.
- `Backend.Core/src/KeyValues/Policy/`: `IKeyValuePolicyStore` (`GetAsync`, `SetAsync`, `ListAsync`) with `KeyValuePolicyDefaults`, `IKeyValuePolicyService` (`GetAsync`, `UpdateAsync`, `VerifyByokAsync`, `RotateAsync`, `AddRecipientAsync`, `UpdateRecipientAsync`, `RemoveRecipientAsync`, `CountInUseAsync`) and `IKeyValueMaintenanceService` (section 17).
- `Backend.CosmosDb/src/KeyValues/Policy/CosmosKeyValuePolicyStore.cs` keeps the policy on `AccessPointEntity.KeyValues` (the `core` container, partition `access`, id `apt.{org}.{project}`), cached for a minute, written with `IfMatchEtag`; a missing access point is `404`. `CosmosKeyValuePolicyService.cs` enforces the rules: `Public` is never removed, the default secret level must be allowed, `Hsm` needs the HSM provider and creates the project's key, `Byok` needs a verified customer key (`409 ByokNotConfigured`), `Hyok` needs an enabled recipient, and disabling a level that keys still carry (active or deleted, counted per view with one cross-partition `GROUP BY c.ViewName` over the catalog items) is `409 ProtectionInUse` with the counts in `Details`.
- **Deviation:** the policy has its own `Version`, and an update may send `ExpectedVersion`; a stale one is `409 PolicyVersionMismatch`. The ETag protects the write itself, the version gives the clients something to show and compare.
- **Deviation:** the Standard key is also recorded on the policy (`Standard` as `ProtectionKeyInfo`), filled by the daily check (section 17), so the key names stay derived as in Phase 1a and the policy only reports them.
- `CosmosKeyValueService` reads the policy before every write and `ProtectAsync`, so a level the policy does not allow is `409 ProtectionNotAllowed` with the allowed list in the message.

### 12. The `Hsm` level

- One class `KeyVaultKeyProvider` (`KeyValues.Azure.KeyVault/src/KeyVaultKeyProvider.cs`) serves `Standard` and `Hsm`; `KeyVaultStandardKeyProvider` of Phase 1a is removed. The HSM instance uses `AzureKeyVaults:{Hsm:VaultName}` (`premium` by default) and creates RSA-HSM keys (`CreateRsaKeyOptions(name, hardwareProtected: true)`), or the Managed HSM named by `KeyValues:Protection:Hsm:OrganizationManagedHsms:{organization}` (`IHsmBackendProvider.GetBackend` returns `ManagedHsm` for such an organization). The key name is the derived one of Phase 1a, so the Standard and the HSM key of a project share a name in two different vaults.
- **Deviation:** `IKeyEncryptionProvider` now takes the `KeyValuePolicy` on every call (`EnsureKeyAsync`, `WrapAsync`, `UnwrapAsync`, `GetKeyInfoAsync`, `RotateAsync`), as the Phase 1a review announced, because the customer-key provider reads `Byok` from it. `IHsmBackendProvider` adds `Backend` and `HardwareProtected`; `ICustomerKeyProvider` adds `VerifyAsync`.
- A rotation policy (`RotationInterval`) is set on create, best effort: Lowkey Vault answers it, a vault without the permission only logs a warning.
- **Emulator:** Lowkey Vault has no HSM-protected keys, so with `KeyValues:Protection:Emulator = true` the HSM instance creates software keys and still reports the backend. The Managed HSM pool itself was not available for this phase; the organization mapping is tested through the configuration only, and the manual smoke test against real Azure of decision D10 (Premium vault, Managed HSM, a second tenant for BYOK) is still owed and is noted under "Left for the next phases".
- **Left out:** the Storyteller correlation id is not sent to Key Vault as `x-ms-client-request-id`. The Azure SDK stamps its own id per call; matching the two logs needs a per-call pipeline policy that reads the ambient caller, which is small but was not done.

### 13. The `Byok` level

- `KeyValues.Azure.KeyVault/src/CustomerKeyProvider.cs` holds one `ClientAssertionCredential` per customer tenant: the assertion is the user-assigned managed identity's token for `api://AzureADTokenExchange/.default` (`ManagedIdentityCredential(ManagedIdentityClientId)`), and the multi-tenant application is `KeyValues:Protection:Byok:ClientId`. In emulator mode the dummy credential of Phase 1a is used instead, so Lowkey Vault plays the customer's vault.
- `VerifyAsync` reads the key (enabled, RSA of at least 2048 bits, `wrapKey` and `unwrapKey` among the operations) and runs a wrap and unwrap round trip of 32 random bytes; the result carries `CurrentKeyVersion`, and the policy service records `VerifiedAt`, `CurrentKeyVersion` and `Health = Healthy`, or fails with `424 CustomerKeyInvalid`. A policy update that changes `KeyUri` or `TenantId` clears the verification and is refused while `Byok` is allowed (`409 ProtectionInUse`).
- A vault answer of 401, 403 or 404 is `CustomerKeyUnavailableException` (`424 CustomerKeyUnavailable`, with the status in the detail); a 429 is `503 KeyEncryptionUnavailable` with `Retry-After`, as for the other levels. The daily check records `Health = Unavailable` with `LastError` and writes `ByokUnavailable` once per transition; a later success sets `Healthy` again.
- **Emulator:** the unwrap uses a `CryptographyClient` on the versioned key id of the envelope, because Lowkey Vault has no versionless unwrap route. That is also the right behaviour for a rotated customer key, so it stays in production.
- `GetByokSetup` is not an API yet; the consent URL and the role name are in `KeyValueOptions.Protection.Byok` (`RequiredRole`) and in the documentation, for Phase 2 to expose.

### 14. The `Hyok` level

- The new project `KeyValues.ClientEncryption` (BCL only, packable, added to `42.mono.slnx`): `JweDocument` (parse and serialize the General JSON Serialization, with `Enc`, `Place`, `ContentType` and the `JweRecipient` list), `ClientEncryptionRecipientKey` with `RsaPublicJwk` (PEM or JWK in, JWK out, `MinimumModulusBits = 3072`), `ClientSecretEncryptor.Encrypt(value, recipients, place, contentType)` and `ClientSecretDecryptor.Decrypt(jwe, recipientId, privateKey)`. `Backend.Core` references it for the validation.
- `Backend.Core/src/KeyValues/Protection/ClientEncryptedValueValidator.cs` checks a document without decrypting it: the JSON and the protected header parse, `enc` is `A256GCM`, `2s` equals the target place, every recipient uses `RSA-OAEP-256` and names an enabled recipient of the project (`400 InvalidClientEncryptedValue`, `400 UnknownRecipient`), at most 49,152 characters. The recipient ids are kept in `StoredValue.Recipients`.
- Recipients live on the policy: at most `MaxRecipients` (20), ids `[A-Za-z0-9_-]{1,64}` (generated when missing), `409 RecipientExists`, `404 RecipientNotFound`, `400 RecipientInvalid` for a short or non-RSA key; the last enabled recipient cannot be disabled or removed while `Hyok` is allowed. Each change writes `RecipientAdded`, `RecipientChanged` or `RecipientRemoved`.
- A reveal returns the document; a diff of `Hyok` versions is `400 NotSupportedForProtection`; `ProtectAsync` refuses the level (section 16); the import compares documents as text.
- **Deviation:** `RecipientChanged` was added to the audit operations, for enable and disable and renames.

### 15. Reference only

- `Backend.Core/src/KeyValues/SecretReferences.cs` validates both content types on write: `https://{vault}.vault.azure.net/secrets/{name}[/{version}]` or `kv://{vault}/{name}[/{version}]` for `application/vnd.2s.secret-reference`, and App Configuration's `{ "uri": … }` for its content type; anything else is `400 InvalidSecretReference`. A reference content type on a secret level is refused with the same code, because the platform never resolves a reference. `IsReference` is set on the summary and the pair.

### 16. Changing the protection of a key

- `CosmosKeyValueService.ProtectAsync` takes keys or a prefix and writes a new version under the target level from the decrypted current value; the outcomes are `Done`, `Unchanged` (already at the level), `NotFound`, `Forbidden` (no secret rights), `NotAllowed` (`Public` or `Hyok` on either side, with the message of `ReprotectNotPossible`), `Failed`. A target the policy does not allow fails the whole call with `409 ProtectionNotAllowed`. The audit records `Reprotect` with the old and the new level.

### 17. Key rotation and re-wrap

- `IKeyValuePolicyService.RotateAsync` rotates the Standard or HSM key through the provider (`RotateAsync` creates a new key version), records the new `ProtectionKeyInfo`, starts a `RewrapStatus` on the policy and writes `Rotate`. `Byok` cannot be rotated by the platform (`400`).
- `Backend.CosmosDb/src/KeyValues/Maintenance/CosmosKeyValueMaintenanceService.cs`:
  - `RewrapAsync` pages through the `kv.` and `kvv.` items of every `{project}.kv.*` partition whose `Content.Encrypted.KeyId` is not the current version of the level, unwraps with the old version and wraps with the new one, and patches `Content.Encrypted` with `IfMatchEtag`, at most `MaxConcurrentKeyOperations` in parallel. The same patch sets `ttl` to the item's remaining lifetime (history items from `VersionRetention`, deleted catalog items from `DeletedRetention`), so the expiry stays within a second. An item that changed meanwhile is skipped and picked up by the next run. Progress (`Processed`, `Remaining`, `CompletedAt`, `LastError`) is written to the policy after every page, which is what lets an interrupted run resume.
  - `CheckKeysAsync` ensures the free Standard key and records it, reads the current HSM key version only when the HSM key is already known (an HSM key costs money, so it is never created by the check), verifies the customer key and records its health, and starts a re-wrap when a current version differs from the recorded one.
  - `RunAsync` goes through every project with a stored policy: the check at most once per 20 hours, then the pending re-wrap.
- `Api.Functions/src/Timers/KeyValueProtectionTimer.cs` runs `RunAsync` hourly (`0 15 * * * *`). Timer triggers need `AzureWebJobsStorage`; without it the host keeps serving HTTP and only the timer listeners fail, which is the local experience without Azurite.
- **Not tested separately:** an interrupted re-wrap. The resume follows from the persisted progress and the "not the current version" query, and the completed-then-rerun case is tested (`Processed = 0`).

### 18. Secret delivery

- `Api.Functions/src/Security/HttpRequestDataExtensions.cs`: `SecretRights(Caller, IsWithheldByMtls)` and `GetSecretRightsAsync(accessService, policyStore, organization, project)`. A user gets secrets with `ContributorWithSecrets` or the scope `Configuration.Secrets`; a machine needs the scope and, when the policy says so, `PresentingCertificateThumbprint` in the invocation; otherwise the secrets are withheld. The channel is `User`, `MachineMtls` or `MachineToken`, and the Functions invocation id is the correlation id.
- **Deviation:** `SecretRights.AsAmbient()` sets `KeyValueCallerContext.Current` and the handler must call it. An `AsyncLocal` set inside the awaited `GetSecretRightsAsync` does not reach the handler's later calls, so the binding reads would have run without a caller.
- `V1/ConfigurationHttp.cs`: `GetConfigurationResolved` takes the rights, leaves the secrets unbound when withheld, sends `X-2S-Secrets-Withheld: mtls-required` and marks the response `Cache-Control: no-store` when secrets were delivered. The same rule now covers the raw vault bindings, as the spec announced. `403 MtlsRequired` for explicit requests (reveal, export) comes with the key-value endpoints in Phase 2; the exception and the mapping exist.
- `Backend.CosmosDb/src/Accessing/CosmosClientCertificateStore.cs` with `Entities/Access/MachineCertificateEntity.cs`: partition `{project}.access`, id `mcert.{THUMBPRINT}`, `ttl` until `NotAfter` + 30 days, point read by thumbprint, single-partition query by machine access id, hits cached for 5 minutes and misses for 30 seconds, `RevokeAsync` deletes and evicts. `AddCosmosDbAnnotations` registers it as `IClientCertificateStore`, replacing the in-memory store of `AddCertificateMachineAccess`.
- `Api.Functions/src/Security/TransportSecurityMiddleware.cs`, placed after `ExceptionHandlingMiddleware`: `400 HttpsRequired` outside Development when neither the scheme nor `X-Forwarded-Proto` is `https`, and `Strict-Transport-Security: max-age=31536000; includeSubDomains` on every HTTPS response. Private networking is a deployment matter and is documented only.
- **Deviation:** `KeyValueChannel` moved from `Backend.Core` to `Abstractions.Annotations`, because the audit event carries it.
- **Left out:** the recording-logger test that searches the output of every endpoint for a plaintext belongs to Phase 2, when the endpoints exist.

### 19. Audit trail

- `Abstractions.Annotations/src/Model/KeyValues/KeyValueAudit.cs`: `KeyValueAuditEvent`, `KeyValueAuditOperation` (the spec's list plus `Import` and `RecipientChanged`), `KeyValueAuditQuery` and `KeyValueAuditPage`. `Backend.Core/src/KeyValues/Audit/IKeyValueAuditLog.cs`; `Backend.CosmosDb/src/KeyValues/Audit/CosmosKeyValueAuditLog.cs` writes to partition `{project}.audit`, id `kva.{yyyyMMddHHmmssfff}.{guid:N}`, `ttl` = `AuditRetention` (400 days), and queries newest first with view, key, operation and time filters, paged by continuation token.
- `CosmosKeyValueService` writes one event for every secret-related operation (create, update, delete, restore, permanent delete, purge, reprotect, reveal, export with secrets, import) and nothing for public pairs. Binding reads of secrets go through `KeyValueUsageRecorder.RecordBindingRead(actor, key, hour)` and leave as one `BindingRead` event with `Count` at the next flush. A purge leaves the events in place.

### 20. Usage metering

- `Abstractions.Annotations/src/Model/KeyValues/KeyValueUsage.cs`: `KeyValueUsageMeters` (the names of section 20.1), `KeyValueUsageDay`, `KeyValueUsageReport`. `Backend.Core/src/KeyValues/Usage/IKeyValueUsage.cs`: `IKeyValueUsageRecorder` with the in-memory `KeyValueUsageRecorder`, `IKeyValueUsageStore`, `IKeyValueUsageService`.
- `Backend.CosmosDb/src/KeyValues/Usage/`: `KeyValueUsageFlushService` (hosted service, every `Usage:FlushInterval` = 60 seconds and on shutdown, one `PatchItemAsync` with `Increment` operations per project on `kvu.{yyyy-MM-dd}` in partition `{project}.usage`, created when missing, `ttl` = `Usage:Retention`), `CosmosKeyValueUsageStore` (the day documents and the snapshot gauges) and `CosmosKeyValueUsageService` (the report over at most 400 days: counters summed, gauges averaged, so a calendar month gives key-months; `EstimatedCharges` when `KeyValues:Pricing` is configured, with `reads` priced per 10,000 of `reads.binding` plus `reads.api`).
- `Api.Functions/src/Timers/KeyValueUsageSnapshotTimer.cs` (daily at 00:10 UTC, `0 10 0 * * *`) enumerates the `org.*` containers and runs the two aggregate queries per container (catalog items per project, level and reference content type; version items per project), writing the gauges into the previous day.
- **Left out:** `hsm.keyVersions` has its meter name, but no snapshot fills it. Counting the key versions used in the last 30 days needs the Key Vault key versions and their dates per project; it is informational for the HSM project fee and can follow with Phase 2.

### Shared changes

- `Backend.Core`: `FailedDependencyException` (424), `PreconditionFailedException` (412), `FeatureNotConfiguredException` (501) and `ServiceUnavailableException` with `RetryAfter` (503) complete the exception set; `StorytellerException` gained an inner-exception constructor; `ErrorCodes` lists every code of the area; `KeyValueErrors` has the factories; `KeyValueCaller` carries `Channel` and `CorrelationId` and has `System()` for the timers.
- `Api.Functions`: `ErrorResponseMapping` maps 400/403/404/409/412/424/501/503, `ExceptionHandlingMiddleware` sends `Retry-After` for 503, `ErrorResponse.Details` carries structured details (the failing import items, the in-use counts). **Deviation:** the spec places these mappings in Phase 2; they are needed by the middleware tests here and were done now. `HttpFunctionDefinition` is `internal` instead of `private`, so the middleware tests can build one.
- `KeyValueOptions`: `AuditRetention`, `MaxRecipients`, `Protection.Hsm`, `Protection.OrganizationManagedHsms`, `Protection.Byok`, `Usage`, `Pricing`. `KeyValueProtectionEntryPoint.AddKeyVaultKeyProtection` registers the Standard provider when its vault is configured, the HSM provider when the Premium vault or a Managed HSM is configured, and the customer-key provider when `Byok:ClientId` is set or the emulator is on.
- `Backend.CosmosDb/src/EntryPoint.cs` registers the policy store and service, the maintenance service, the audit log, the usage recorder, store and service, and the Cosmos certificate store; `Program.cs` of the API adds the transport middleware, the usage flush service and the two timers (`Microsoft.Azure.Functions.Worker.Extensions.Timer`).
