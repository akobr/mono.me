# Phase 3 of Shared Organization Container

## Overview

Phase 3 of the spec [Shared Organization Container](../2026-11-09%20Shared%20Organization%20Container.md) (424-230) covers section 8 and the classic suite of section 10: the Cosmos DB tests and the Aspire host on the vNext emulator, the trait of the tests that need an emulator like the service, a request-charge test, and the workflow `storyteller-cosmos.yml`. It is the commit `test(platform): run the Cosmos DB suites and the Aspire host on the vNext emulator`.

## What Was Done

### 8. The vNext emulator for development and tests

- **Test fixtures.** `CosmosTestEmulator` (one copy in `Backend.CosmosDb/test`, one in `Access.Certificates/testint`; the projects share no code) picks the emulator: the local Windows emulator without `STORYTELLER_TESTS_USE_CONTAINER`, otherwise `STORYTELLER_TESTS_EMULATOR` = `vnext` (default) or `classic`. vNext runs from a generic `ContainerBuilder` (image `vnext-latest`, `--protocol https`, ports 8081 and 8080, a wait for `GET /ready` on 8080, reuse label `<module>-vnext`), as the spec planned after reading Testcontainers' `CosmosDbBuilder`; classic keeps the earlier `CosmosDbBuilder` configuration. `ITestContext.DbContainer` became `ITestContext.Emulator` (`Kind`, `IsLikeTheService`). The cleanup of both fixtures deletes the database `42.Platform.2S` by name (tolerating `404`), not every database of the emulator.
- **Results on vNext.** `Backend.CosmosDb/test` ran in one go (766 tests, about 5 minutes, no chunks and no restart of the emulator), `Access.Certificates/testint` in 21 seconds (73 of 73). Three tests failed on vNext for reasons of the emulator, none of the layout:
  - `KeyValueEndToEndTests.Secret_WrittenWithTheVaultKey_RoundTripsThroughCosmos` matched `"Algorithm":"RSA-OAEP-256"` as text; vNext returns the stored document formatted. It now parses the JSON and runs everywhere.
  - `CosmosAnnotationAuditTests.Audit_IsTrimmedToItsSizeLimit` checks the stored size of the audit item, which vNext returns formatted (larger); `CosmosKeyValueServiceTests.HistoryVersion_ExpiresAfterTheVersionRetention` waits for the TTL expiry of version items, which vNext did not do within a minute. Both carry the trait `Emulator=Classic` and skip themselves on vNext (`Assert.SkipUnless(Context.Emulator.IsLikeTheService, ...)`).
- **Request charges.** `RequestChargeTests` (trait `Emulator=Classic`, skipped on vNext) seeds two organizations with the same partitions and checks that a point read with the full key costs at most 1.5 RU and that a query over one organization with the predicate and the prefix stays within three times a single-partition query and returns only its organization's items. Green on the classic emulator.
- The trait filters work with xUnit v3 on Microsoft.Testing.Platform: `--filter-trait "Emulator=Classic"` lists the four classic tests, `--filter-not-trait "Emulator=Classic"` the other 764.
- **Aspire.** `AppHost.cs` runs `RunAsEmulator` (the vNext emulator in `Aspire.Hosting.Azure.CosmosDB` 13.6.4) with the persistent lifetime, the new volume `platform-cosmos-vnext-data` and `WithDataExplorer()`; the comment about the stored procedures is gone; the local mode is unchanged. The host builds; it was **not run** end to end in this change (the emulator, the API and DbCreator against it are untested through Aspire; the same emulator and DbCreator ran green through the test fixtures).
- **CI.** `.github/workflows/storyteller-cosmos.yml` (`workflow_dispatch`, `workflow_call`): a vNext job runs both suites with `--filter-not-trait "Emulator=Classic"`, a classic job runs both suites whole. **Deviation:** the spec had the classic job run only the trait; the whole suites run there, so an `ORDER BY` on an excluded path or another indexing difference of the service fails in CI too. The workflow was not run: a `workflow_dispatch` workflow runs once it is on the default branch.
