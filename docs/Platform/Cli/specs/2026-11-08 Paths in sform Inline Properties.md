# Paths in sform Inline Properties

Linear [424-213](https://linear.app/424fun/issue/424-213/support-dot-paths-in-sform-inline-properties-x-ab1-for-nested). The decisions of the issue (the bracket form, array indexes, an error for a path that crosses a value, no compatibility concern) are the owner's; this spec adds what the issue leaves open. Three independent reviews of a first draft (the grammar, the semantics, the documentation and shells) shaped sections 1, 3, 4 and 5.

## Problem

`sform story config set` and `sform story template set` take inline properties with `-x|--properties name=value`. The name is used literally as a top-level key, so `-x a.b=1` stores a property named `"a.b"`, not `{ "a": { "b": 1 } }`.

A nested value can only be set by importing a JSON file (`-i`), or with `config edit` / `config patch`. Changing one nested value from the command line or a CI script is awkward, and a dotted name such as the .NET logging key `Microsoft.AspNetCore` cannot be told apart from a path.

## Current State

- **The option.** `ConfigSetCommand` (`src/Platform/Cli/src/Commands/Configuration/ConfigSetCommand.cs:40`) and `TemplateSetCommand` (`src/Platform/Cli/src/Commands/Templates/TemplateSetCommand.cs:35`) declare `-x|--properties` as `CommandOptionType.MultipleValue`, with the help "Specify inline properties to be set on the configuration." (or "on the template.").
- **The builder.** `JsonInputBuilder.BuildAsync` (`src/Platform/Cli/src/Commands/JsonInputBuilder.cs`) merges the `-i` file into an empty `JObject`, then builds a second `JObject` from the inline properties and merges it over the first, both with `MergeArrayHandling.Union`, `MergeNullValueHandling.Ignore` and ordinal names. Each inline property is split at its first `=` (line 66); a property without `=` fails with "The inline property '…' is not in the correct format.", which echoes the whole argument. The value goes through `PropertyValueParser.ParseValue` (bool, long, double, ISO 8601 date, time span, else string) into a `JValue` (line 75). Errors are written with `WriteImportant` (an Alba document on standard output) and thrown as `WrongInputException` (exit code `2`). The `schema … set` commands call the builder without inline properties.
- **The merge on the server.** Without `--replace`, `SetConfiguration` and `SetTemplate` merge the built document into a copy of the stored one (`JsonExtensions.MergeInto` in `Backend.CosmosDb`, called from `CosmosConfigurationService` and `CosmosConfigurationTemplateService`): objects merge, arrays are unioned (an item equal to an existing one, by deep equality, is skipped), `null` never erases, and a value of another kind replaces the stored one. With `--replace`, the CLI reads the stored content and sends a JSON Patch to the built document, so the document replaces the content.
- **The path printer.** `JsonPaths` in the ConfigurationFormats library (`src/Libraries/Platform/Storyteller/ConfigurationFormats/src/JsonPaths.cs`) prints the paths of format errors: `$` for the root, `.name` for a name of ASCII letters, digits, `_` and `-` that starts with an ASCII letter or `_`, `['name']` for any other name, `[0]` for an item. In a bracketed name it escapes `\` and `'` with a backslash, the C0 controls and DEL as `\n`, `\r`, `\t` or `\uXXXX` (upper-case hex), and `#` as `\u0023`; C1 controls, U+2028 and U+2029 are kept (`docs/Platform/Storyteller/configuration-formats.md`, "Rules shared by every format"). Nothing parses that syntax. `sform` already references the library, which is also a published NuGet package gated by the conformance workflow.
- **`DocumentSegment`** (same library) is one step of a path: a name, or an index when `Name` is `null`.
- **Plain output.** `PlainOutputExtensions.WriteErrorLine` writes a message as one plain line on standard error: control characters, U+2028 and U+2029 become spaces, `#` becomes `\u0023`, and a leading `::` is defused.
- **Release notes** are generated by `mrepo` from the subjects of the commits (`ReleaseHelper.BuildReleaseNotes`); a commit whose message contains the text "BREAKING CHANGE" anywhere is a major change (`ConventionalParser`).
- **Tests.** No test covers `JsonInputBuilder`. `JsonPathsTests` covers the printer.
- **Documentation.** `docs/Platform/Storyteller/templating.md` (section "CLI") shows `-x|--properties k=v`. `docs/42for.net/cli/sform.md` describes reading a configuration but not writing one, and warns where an option is newer than the `sform` on NuGet. `docs/Platform/Storyteller/configuration-formats.md` lists the library's members.

## Proposed Changes

### 1. The path syntax

The name of an inline property is a path in the syntax `JsonPaths` prints:

```text
path  := '$' step*  |  first step*
first := name  |  bracket
step  := '.' name  |  bracket
name  := [A-Za-z_][A-Za-z0-9_-]*
bracket := '[' index ']'  |  '[' "'" quoted "'" ']'
index := '0'  |  [1-9][0-9]*            (ASCII digits, at most int.MaxValue)
```

| Step | Example |
| --- | --- |
| A plain name | `db.port` |
| Any other name, in quotes | `Logging.LogLevel['Microsoft.AspNetCore']`, `['$schema']`, `['my key']` |
| An array item | `hosts[0]`, `list[1].name` |

- **The first step needs no dot**, but only without `$`: `db.port`, `['my.key'].x`. With the root, every step keeps its `.` or `[` as printed: `$.db.port`, `$['my.key'].x`. After `$` only `.`, `[` or the end of the path may follow; a name character or another `$` right after it is an error whose message says that a name starting with `$` is written `['$name']`. A leading `.` without `$` is an error.
- **Inside the quotes**, `\'` and `\\` escape the quote and the backslash, as the issue decides. **Deviation from the issue:** the parser also reads `\n`, `\r`, `\t` and `\uXXXX` (hex digits in any case), which the printer writes for control characters and for `#`. Without them a printed path such as `$['C\u0023']` could not be pasted back. A literal backslash is therefore always written `\\`: `['C:\temp']` reads a tab, and `['C:\x']` is an error. Any other character after a backslash is an error, which keeps the other escapes free. A raw character that the printer would escape (a control character, a `#`) is accepted.
- **A quoted name may hold anything else**, `=`, `.`, `[`, `]`, spaces and `"` included. The empty name `['']` parses, as the printer prints it; `sform` refuses it (section 3).
- **Not accepted:** Spring's `.[name]`, double-quoted names, `:` as a separator, whitespace around steps, a sign, a leading zero or a non-ASCII digit in an index.

The argument is read as a path, then `=`, then the value: the rest of the argument as written, through `PropertyValueParser.ParseValue` as now. So `-x "['a=b']=c=d"` sets the name `a=b` to `c=d`.

### 2. The parser in the ConfigurationFormats library

Next to the printer, so the printed and the parsed syntax cannot drift:

```csharp
public static class JsonPaths
{
    // existing: Root, Property(parent, name), Item(parent, index)

    // $ followed by every step, as Property and Item print it. A segment with a Name is a property whatever its Index;
    // an index step with a negative index throws ArgumentOutOfRangeException.
    public static string Of(IEnumerable<DocumentSegment> segments);

    // A whole path (section 1). Throws JsonPathFormatException.
    public static IReadOnlyList<DocumentSegment> Parse(string path);

    // A path at the start of text; it stops before the first character that cannot continue the path (for example
    // '='), and length is the number of characters read. Throws JsonPathFormatException when no path starts at the
    // first character, and for a step that is not complete or not valid.
    public static IReadOnlyList<DocumentSegment> ParsePrefix(string text, out int length);
}

// A text that is not a path in the syntax of JsonPaths.
public sealed class JsonPathFormatException : FormatException
{
    // The index of the character where the path is wrong; the length of the text when it ends too early.
    public int Position { get; }
}
```

- **The message** is a sentence that says what was expected (for example "After '.', a name of ASCII letters, digits, '_' and '-' that starts with an ASCII letter or '_' is expected; write any other name as ['name']."), never the text itself. The caller decides what to show.
- **`$` alone** parses to no steps. An empty text is an error at `0`.
- **Generic.** The parser does not know that a configuration is an object: `[0]` as the first step parses, and so does `['']`. The checks belong to `sform` (section 3).
- **The round trip** holds for segments made with `DocumentSegment.Property` and `DocumentSegment.Item`: `Parse(Of(steps))` gives the steps back, and `Of(Parse(path))` gives back every path the printer prints.
- **No conformance vectors.** The TypeScript SDK prints paths but does not parse them, so the parser is tested in .NET only; its tests parse every error path of the embedded conformance vectors (section 6). Vectors can follow when a second language parses.

### 3. Inline properties in `sform`

A new `InlineProperties` (`src/Platform/Cli/src/Commands/InlineProperties.cs`) applies the `-x` values to the built document, one by one in command-line order:

```csharp
public static class InlineProperties
{
    // Writes the value of every path=value into document; throws WrongInputException naming the path.
    public static void Apply(JObject document, IReadOnlyList<string> inlineProperties);
}
```

`JsonInputBuilder.BuildAsync` keeps the file merge, then calls `InlineProperties.Apply` instead of building and merging the second document.

For one value, after parsing (section 1):

1. **A path of `$` alone**, a path that starts with an index, and a path with an empty name are errors. The document is an object, and the provider refuses an empty name (`empty-name`). An empty name is also what a shell leaves of `['$binding']` in double quotes, so its message says so.
2. **Each step before the last** must lead to a container:
   - an absent property, an index equal to the array's length, or a `null` creates an empty object, or an empty array when the next step is an index. A `null` counts as absent, as it does everywhere in a configuration (it makes no key and never erases in a merge);
   - an existing object or array is entered when the next step fits it: a name needs an object, an index an array;
   - anything else is an error that names the path to the value: a string, number, boolean, date or time span is crossed (`-x a=1 -x a.b=2`), or an object is used as an array, or the other way round. A value of the `-i` file counts the same as one of an earlier `-x`.
3. **The last step** writes the value: a name sets the property, replacing whatever it held (a scalar, an object or an array, as the merge did); an index replaces an existing item, or appends when it equals the array's length.
4. **An index past the end** (greater than the length) is an error that names the path and the length; no gap is filled with `null`. The length is that of the array after the `-i` file and the earlier `-x` values, so `-x "hosts[0]=a" -x "hosts[1]=b"` works on an empty array and the reverse order fails.

**The checks see the built document only.** Without `--replace`, the API merges that document into the stored content, with its own rules:

- an index addresses the built array, not the stored one, and arrays are unioned: `config set app -x "hosts[0]=x"` adds `x` to a stored `hosts`, and `-x "list[0].name=n"` adds the item `{ "name": "n" }` rather than renaming the stored first item. An `-i` file with an edited item keeps the stored item and adds the edited copy;
- a value of another kind replaces the stored one without an error: `-x db.port=5432` over a stored string `db` stores `{ "db": { "port": 5432 } }`.

`--replace` (with the whole document in `-i`), `config edit` and `config patch` change stored items in place. The documentation says so (section 5); checks against the stored content are out of scope (section 7).

**Values** are typed by `PropertyValueParser` as now. For a plain name (section 1), the old merge and the new write give the same document. Every other name now needs the bracket form, where it was written literally before: a dot, a space, `:`, `$`, a leading digit or `-`, a non-ASCII letter, `#`, `/`, the empty name. `-x "['a.b']=1"` keeps the old meaning of `-x a.b=1`.

### 4. Errors

Every error is a `WrongInputException` (exit code `2`). Its message names the inline property by its position among the `-x` values. It names the path in the printer's form where the path is known to be a name, and never the value.

`JsonInputBuilder` writes its messages with `WriteErrorLine`, one plain line on standard error, instead of `WriteImportant`: a long message is not wrapped into lines that could start with `::`, and a C1 control or a line separator of a name becomes a space. The message of a missing `-i` file moves there too, so the builder writes one way.

| Input | Message |
| --- | --- |
| `a..b=1` (2nd of 3) | `The inline property 2 of 3 has a wrong path at character 3. After '.', a name of ASCII letters, digits, '_' and '-' that starts with an ASCII letter or '_' is expected; write any other name as ['name'].` |
| `a[b.c]=1` | `… has a wrong path at character 3. After '[', an index (digits) or a quoted name ('name') is expected. Quote the whole argument: a shell removes the quotes of ['name'] otherwise.` |
| `$schema=x` | `… has a wrong path at character 2. After $, '.', '[' or the end of the path is expected; a name that starts with $ is written ['$name'].` |
| `a.b` | `… has no '=' after its path, at character 4. Write it as path=value; write a name with other characters than ASCII letters, digits, '_' and '-' as ['name'].` |
| `a:b=1` | `… has no '=' after its path, at character 2. Write it as path=value; ':' does not separate names: write a.b, or ['a:b'] for a name with a colon.` |
| `$=1` | `… names no property: its path is $.` |
| `[0]=1` | `… starts with an array index, $[0], but the document is an object.` |
| `a['']=1` | `… cannot set $.a['']: a name is empty, which a configuration cannot hold. A shell may have expanded a $name inside double quotes; write \$ there, or use single quotes.` |
| `a=1`, then `a.b=2` | `… cannot set $.a.b: $.a is a number, not an object.` |
| `a.b=1`, then `a[0]=2` | `… cannot set $.a[0]: $.a is an object, not an array.` |
| `a[0]=1`, then `a.b=2` | `… cannot set $.a.b: $.a is an array, not an object.` |
| `hosts[3]=x` over `["a"]` | `… cannot set $.hosts[3]: $.hosts has 1 item, so its index can be at most 1.` |

- **Characters** are counted from 1 (`Position + 1`), in UTF-16 code units.
- **No '='** names no path. An argument that is only a name, for example a token passed without `name=` (`-x "$API_KEY"`), would otherwise be printed.
- **The old message** echoed the whole argument, value included. None of the new ones does.

### 5. Help and documentation

- **The help of `-x`** on both commands: `Specify inline properties as path=value, for example -x "db.port=5432" -x "hosts[0]=a" -x "Logging.LogLevel['Microsoft.AspNetCore']=Warning"; quote each one.`

  - **shells:** quote every argument; in bash and zsh use double quotes, write `\$` for a `$` of a name and `\\\\` for a backslash, and drop the leading `$` of a printed path (`"$[…"` is arithmetic expansion there); zsh stops on an unquoted `hosts[0]=a` (a glob); in PowerShell a `$name` inside double quotes is a variable, so use single quotes with `''` for a quote; in a GitHub Actions workflow, use a `run: |` block, where `#` and `: ` do not end the line;

### 6. Tests

- **`JsonPathsParseTests`** (ConfigurationFormats tests):
  - the forms of section 1, with and without `$`;
  - every escape, hex digits in both cases, raw `=`, `.`, `[`, `]`, `#` and controls inside the quotes, the empty name, `['C:\temp']` as a tab;
  - errors with their `Position`: an empty text, `.db`, `$db`, `$$`, `$schema`, a trailing `.`, `..`, `.['x']`, `.[0]`, an unclosed quote or bracket, an unknown escape (`['C:\x']`), a short `\u`, `\U`, a leading zero, a non-ASCII digit, an index over `int.MaxValue`, a non-ASCII plain name, whitespace;
  - messages that never hold the text;
  - `ParsePrefix` stopping before `=`, also after a quoted name that holds `=`, and throwing at `0` when nothing starts;
  - `Of` with a negative index;
  - **round trip:** the names of `JsonPathsTests`, a seeded random set of step lists (every character class the printer treats differently, surrogates included), and every error path of the embedded conformance vectors.
- **`InlinePropertiesTests`** (CLI tests), through `JsonInputBuilder.BuildAsync` with a `MockFileSystem`:
  - `a.b=1`; a shared prefix merging into one object; quoted dotted names and names with `=`; `$`-led paths; values typed as before;
  - arrays: append in order, replace an item, `list[1].name` into an existing item, past the end, the reverse order;
  - the `-i` file: inline values written over it, an item of its array replaced, a crossed scalar of the file, a `null` of the file replaced by an object;
  - every row of section 4, with the message on standard error as one line and the exit code `2`; no value in any message, also for an argument without `=`;
  - a plain name gives the same document as the old merge; names that were literal before (`$schema=`, `my key=`, `2fa=`, `a:b=`, a non-ASCII name) now fail;
  - the message of a missing `-i` file on standard error.
- **`ConfigSetCommand`**: the API receives the nested document; a wrong path sends nothing.

### 7. Out of scope

- `-c|--custom-properties` of `sform story set`, which sets annotation values, keeps its literal names.
- A `:` alias, Spring's `.[name]`, removing a property from the command line.
- Checks against the stored content: index semantics on the server, and a stored value of another kind that a path crosses.
