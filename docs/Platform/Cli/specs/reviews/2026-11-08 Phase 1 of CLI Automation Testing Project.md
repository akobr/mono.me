# Phase 1 of CLI Automation Testing Project

Linear: [424-215](https://linear.app/424fun/issue/424-215/create-cli-automation-testing-project-sform-against-a-real-backend).

## Overview

Phase 1 of [CLI Automation Testing Project](../../../Cli.AutomationTests/specs/2026-11-08%20CLI%20Automation%20Testing%20Project.md), sections 1.1 to 1.6: the changes in `sform` (`src/Platform/Cli/src`) that let a test run the real executable without a terminal, with its own state folder per user, on a Linux agent without a keyring, and read the device code as a contract. One `CliPaths` service now resolves every file `sform` reads or writes, and `SFORM_HOME` moves all of them (the protected AuthKit entry of Keychain and libsecret is named after it); `SFORM_TOKEN_STORE=file` keeps the session as a plain file there; `sform account -o|--organization` picks the organization of a device-code sign-in and is checked against a stored session; every prompt fails fast on redirected input through one helper, and standard input is read only where an option asks for it; `SFORM_DEVICE_CODE_OUTPUT=json` adds a JSON line on standard error before any other output; `-b` honours `SFORM_BROWSER` and the conventional `BROWSER`. A code review of the phase added what phase 3 needed and was missing: the output no longer crashes without a console, `SFORM_<section>__<key>` variables set the configuration of a run (`SFORM_general__baseUrl`), a build from source honours `DOTNET_ENVIRONMENT`, and an unreachable API ends with `3` instead of a crash. Unit tests in `Cli.UnitTests` cover all of it, three of them starting the built `sform` out of process with every standard stream redirected (1062 tests before, 1219 after, all green). User docs: `docs/42for.net/cli/sform.md`.

Deviations from the plan, in short (details in the sections):
- The edit commands (`config edit`, `template edit`, `schema type|annotation|descendant edit`) got a new `-y|--yes`, and `sform account machine renew` a new `--password-stdin`: without them their confirmation, or the certificate password, needs a terminal (§1.4). Six new options in the command tree.
- Two exit codes: a prompt for a value (`-o`, `-p`, the value of a secret, the certificate password, `--restore-deleted`/`--recreate`) ends with `ERROR_WRONG_INPUT` (2); a confirmation, or a command that only works in a terminal, with `WARNING_INTERACTION_NEEDED` (43) (§1.4).
- `sform account`: a declined sign-in now ends with 44 and a sign-in service failure with 3 (both were 2); the catalogue needs the first (§1.3).
- `-e` of the `get` commands rewrites an existing file without asking on redirected input (the prompt's default) instead of failing (§1.4).
- `sform account set -p` now checks the format `<organizationName>.<projectName>` before any call (a key without a dot crashed it before).
- Beyond §1, found by the review and needed by phase 3: `SformConsole` (output without a console, §1.7), the `SFORM_` configuration variables and `DOTNET_ENVIRONMENT` (§1.8), and exit 3 for an unreachable API (§1.9).

## What Was Done

### 1.1 State directory override (`SFORM_HOME`, `CliPaths`)

- New `Configuration/CliPaths.cs` (sealed, `IFileSystem`-based), resolved once in `Program.Main` by `Program.ResolvePaths` and handed to `Startup` through the properties of the host builder (`builder.Properties[typeof(CliPaths)]`; `Startup` takes `IDictionary<object, object>` and falls back to `CliPaths.FromEnvironment` when started without `Program`). Registered as a singleton by the new `Startup.ConfigureStatePaths`.
  - `ApplicationDirectory`: `AppContext.BaseDirectory` (was `Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location)`, the same folder for a tool or a build; `AppContext.BaseDirectory` also works single-file). Holds `app.config.json`, always.
  - `StateDirectory`: `access.default.json`, `editor.config.json`, `auth.discovery.json` and the log files. `SFORM_HOME`, else `ApplicationDirectory` (unchanged default).
  - `UserDirectory`: the AuthKit session, the Entra ID MSAL cache and `telemetry.json`. `SFORM_HOME`, else `MsalCacheHelper.UserRootDirectory/.42for.net` (unchanged default). Lazy: with `SFORM_HOME` the user profile is never read (a test pins it).
  - `AccessDefaultFile`, `EditorConfigFile`, `AuthDiscoveryFile`, `GetLogFilePath(configured)` (relative to the state directory unless absolute; `logs/cli.log` by default), `GetDailyLogFilePath(configured, day)` (the file the crash message names), `EnsureDirectoryOf(file)`.
- Every place that computed a path now uses it:
  - `AccountSetCommand.CreateAccessDefaultConfigFile(options, fileSystem, paths)` (also used by `AccountRegisterCommand` and `AccessPointCreateCommand`, which inject `CliPaths`), creating the folder first.
  - `EditorService(IFileSystem, CliPaths)`: `SaveEditorOptions` writes `paths.EditorConfigFile`.
  - `AuthenticationConfigurationResolver` takes `CliPaths` (the cache in `StateDirectory`) and creates the folder before writing `auth.discovery.json`.
  - `LoggingOptions` is a plain options class now; `Startup.ConfigureLogging` writes to `Paths.GetLogFilePath(logging.logFilePath)` (the old fallback `"logs/cli.log"` was relative to the current directory), and the crash message of `Program` names `GetDailyLogFilePath`.
  - `ProtectedTokenStore(IFileSystem, TokenStorage)`, `EntraIdAuthenticationService(IFileSystem, ResolvedAuthentication, TokenStorage)` and `InstallationIdStore(IFileSystem, CliPaths)`; `CommandTelemetry.Create` gets `CliPaths`.
- `Startup.ConfigureApplication` now calls `Startup.AddConfigurationFiles(builder, paths)`: `app.config.json` stays relative (the host's base path, next to the assembly); `access.default.json` and `editor.config.json` are added by their absolute paths in the state directory. A missing `SFORM_HOME` loads as empty (`AddJsonFile` resolves the nearest existing parent); a test with real files pins both.
- Rules of `SFORM_HOME`, decided and documented: blank means unset; it must be fully qualified (`Path.IsPathFullyQualified`), and a relative value, or a path to an existing file, is an input error: `Program.Main` writes `! SFORM_HOME must be an absolute path, and 'state' is relative.` to standard error and returns `ERROR_WRONG_INPUT` before the host is built, so nothing is read or written in the default folders (falling back would mix the state `SFORM_HOME` keeps apart). The value is trimmed and normalised (`GetFullPath`, trailing separator removed). A folder that does not exist is created by the first write, not at start.
- The protected AuthKit session on macOS and Linux is not a file in the directory: the Keychain item and the libsecret entry are found by their names, and only a placeholder lives in the folder. With fixed names, every `SFORM_HOME` shared one session (and their per-directory locks did not protect its rotating refresh token). `TokenStorage` got `IsHome` (registered as `paths.IsHomeSet`) and `HomeKey`, the first 16 hex digits of the SHA-256 of the directory; `ProtectedTokenStore.CreateProperties(TokenStorage)` (internal, tested) names the Keychain account `authkit-<HomeKey>`, the libsecret attribute `ProductGroup` `sform-<HomeKey>` and the label after the folder. Without `SFORM_HOME` the names stay `authkit` and `sform`, so existing sessions survive. The Entra ID MSAL cache keeps its library defaults on macOS and Linux (not changed here); there, separate sessions per folder need `SFORM_TOKEN_STORE=file`, as the docs say.
- `CliPaths.EnsureDirectoryOf` uses the file system `CliPaths` was created with (the real one in `Program`), not the container's; in a `DEBUG` build without `TESTING` (the read-only diagnostic file system) it would still create the folder. No such configuration is built today.
- The note the spec asks for: a global tool install benefits too, as `SFORM_HOME` takes the default project out of the shared tool folder; moving the defaults for everyone is 424-218 (below), out of scope here.

### 1.2 File token store (`SFORM_TOKEN_STORE=file`)

- New `Configuration/SformVariables.cs` (the names `SFORM_HOME`, `SFORM_TOKEN_STORE`, `SFORM_DEVICE_CODE_OUTPUT`, `SFORM_BROWSER`, `BROWSER`, `COLUMNS`, `DOTNET_ENVIRONMENT`, the configuration prefix `SFORM_` and the values `file`, `json`) and `Configuration/SformEnvironment.cs`, read once by `SformEnvironment.FromEnvironment(Func<string, string?>, CliPaths)`, the shape of `MachineSignInSettings.FromEnvironment`, so tests inject the variables instead of setting them on the process.
- `IsFileTokenStore` is true only for `file` (any case, trimmed) together with `SFORM_HOME`. Without `SFORM_HOME` the variable is **ignored with a warning** (decision), and so is any other value. `TokenStoreNotice` is the line `sform account` prints (user path only, like the deprecated-variable lines; other commands stay quiet): "The session is kept unencrypted in `<SFORM_HOME>` (SFORM_TOKEN_STORE=file); keep the folder private.", "SFORM_TOKEN_STORE=file is ignored without SFORM_HOME; the session is kept in the protected store.", or "SFORM_TOKEN_STORE=plain is ignored: the only value is file, together with SFORM_HOME.".
- New `Authentication/TokenStorage.cs` record (`Directory`, `IsUnprotected`, `IsHome`), registered by a factory (so the user profile is read on first use only). The unprotected storage is the library's own: `StorageCreationPropertiesBuilder.WithUnprotectedFile()` for both the AuthKit session (`ProtectedTokenStore`) and the MSAL cache (`EntraIdAuthenticationService`); MSAL writes those files owner-only. The plain files are named `authkit.cache.plaintext` and `msal.cache.plaintext` (as the existing `DEBUG && !TESTING` branch did, now folded into the same flag), so an encrypted file is never read as plain. The Entra service creates its folder before `MsalCacheHelper.CreateAsync`.
- `AuthenticationServiceSelector` takes `TokenStorage` and passes it to the Entra ID service.

### 1.3 Non-interactive organization (`sform account -o|--organization`)

- `IAuthenticationService.LoginWithDeviceCodeAsync` has a new optional `string? organizationId` (before the cancellation token), passed through `AuthenticationServiceSelector`; `MachineAuthenticationService` ignores it (it refuses a device code anyway).
- `AuthKitAuthenticationService`:
  - a user in several organizations (`organization_selection_required`): `-o` is matched against the offered ids (ordinal, case-insensitive) and sent with the selection grant; the selector callback is not asked. An id not offered fails with `AuthenticationFailureReason.Configuration`: "You are not a member of the organization 'org_99'. Your organizations: org_a (Alpha), org_b (Beta).", and no session is stored;
  - a user in one organization (or none): WorkOS answers the device code with a session straight away, so the `organization_id` of that session must equal `-o`; otherwise the same failure ("… WorkOS signed you in to your only organization, 'org_01'." or "… without an organization."), checked before `SaveAsync`, so nothing is stored (catalogue SGN-DEV-07).
  - `-o` takes the **WorkOS organization id** only. A name cannot be matched in the one-organization case (WorkOS returns only the id), so names are not accepted anywhere, to keep one rule. The WorkOS organization is not the 2S organization of `-p <organization>.<project>` (the backend keeps them apart, e.g. `AuthKitOptions.MachineOrganizationId`); see the catalogue notes below.
- `SignedInUser` has a new optional `OrganizationId`, the organization of the AuthKit session (null for Entra ID and machines). `AccountCommand` checks `-o` against a **stored session** too: the same organization goes on; another one, or none, ends with `ERROR_WRONG_INPUT` before any call, "You are signed in as ada@example.com to the organization 'org_01', and -o|--organization asks for 'org_02'." (or "… without an organization, …") and "Sign out with sform account logout, then sign in with -o.". On an Entra ID deployment a stored session has no organization, so `-o` ends with `2` in both branches; the message of the stored-session branch is the generic one, the provider's refusal comes on the next sign-in.
- `EntraIdAuthenticationService` refuses `-o` on a new sign-in (`Configuration`, before MSAL starts): Entra ID has no organizations to pick.
- `AccountCommand`: the `-o|--organization` option (trimmed; blank is unset); the organization selector calls `EnsureInteractiveValue` before `Console.Select`, so on redirected input it writes to standard error

  ```
  ! sform cannot ask for the organization to sign in to: the input is redirected.
    You belong to several organizations; pass one with -o|--organization <id>:
      org_01  Acme
      org_02  Contoso
  ```

  and ends with `ERROR_WRONG_INPUT` (catalogue SGN-DEV-06). The organizations are known only after the code is confirmed, so the test confirms first, as the catalogue describes.
- `ReportSignInFailure` returns by reason: `Denied` 44 (catalogue SGN-DEV-05, was 2), `Configuration` 2 with the message (the `-o` failure), `ServiceError` 3 (was 2; consistent with `ExitCodes.ERROR_SERVICE_FAILURE`, `Program` and the machine path), `Cancelled` and `Expired` 2 as before.
- `sform account set`: without `-p` on redirected input, `EnsureInteractiveValue` stops before any call with `ERROR_WRONG_INPUT` and names `-p|--projectKey <organizationName>.<projectName>` on standard error (catalogue ACC-SET-03). A `-p` without a dot, starting or ending with one, is now `ERROR_WRONG_INPUT` before any call (it crashed on `projectKey[..-1]`).

### 1.4 No hangs on redirected input

- One helper, `Output/InteractiveInputExtensions.cs`: `IsInteractive()` (`Console.Console.IsInputRedirected` of the McMaster console the CLI already wraps; a console without an inner console counts as interactive, as before), `EnsureInteractive(question, hints…)` (43) and `EnsureInteractiveValue(question, hints…)` (2). On redirected input they write `! sform cannot ask for <question>: the input is redirected.` and each hint as an indented line to standard error (through the existing `PlainOutputExtensions.WriteErrorLine`), then throw the new `Output/Exceptions/InteractionNeededException` (an `OutputException`). `BaseContextCommand` already turns an `OutputException` into its exit code; `Program.RunAsync` now does the same for the commands outside it (it reported "Total mayhem" with exit 1 before).
- Exit codes (decision): a value an option supplies is `ERROR_WRONG_INPUT`, as when it is missing on the command line (the spec's `-o`/`-p`, and the existing precedent of `story set`); a confirmation that `-y|--yes` skips, or a command that only works in a terminal, is `WARNING_INTERACTION_NEEDED`, the code `ExitCodes` has for exactly this. The catalogue only asks for "non-zero, names the option" (GEN-CLI-03), 2 for ACC-SET-03 and SGN-DEV-06.
- Where the check sits (decision, after the review): **right before the prompt**, so the checks before it (a missing file, an unknown key, nothing to change) keep the exit codes they had, also without a terminal; the run still never blocks. Two exceptions stop before any call: a prompt that is certain from the command line alone (`account set` without `-p`, the access point commands, the commands that need a terminal), and a confirmation after an **editor** session (the edit commands, `config patch` without `-i`), where the edit would be lost to a question nobody can answer. - The edit commands had no option to skip their confirmation, and the catalogue's mode E cases run them without a terminal, so each got `-y|--yes` ("Save the edited … without asking for confirmation."), passed as `confirm: !Yes`.
- `machine renew -c` first read the password from the first line of standard input whenever the input was redirected. The review rejected that: in a `while read` loop it consumed the next line, and on a pipe that never ends it waited forever. Now standard input is read only with the new `--password-stdin` ("Read the password of the -c certificate from the first line of the standard input (an empty line for none) instead of asking."), and only its first line; without it, a redirected input stops with 2 and names the option; `--password-stdin` without `-c` is 2. Standard input is thus read only where an option asks for it (`kv set --stdin`, `machine renew --password-stdin`).
- Tests: `Commands/RedirectedInputTests.cs`, one or more per command above with strict API mocks (no call happens before the stop, or only the calls before the prompt) and the exact standard error, including the outcomes that keep their codes without a terminal (`kv import` with nothing to change or a missing file, `config patch -i` with an empty patch or a missing configuration, `story delete --permanent` of an unknown key) and `machine renew` (the first line only, the next line left unread; no read without the option); `Services/EditorServiceTests.cs` for the editor (invalid JSON gives 2 without a retry, changes stop at the confirmation with 43, `confirm: false` returns the document, no change is 42), through a new internal `EditorService` constructor that takes the editor as a function; the organization cases in `AccountCommandSignInTests` and the updated `StorytellerSetCommandTests`. `RecordingConsole.UseInnerConsole(redirectedInput, input)` records standard error and scripts standard input.

### 1.5 Machine-readable device code (`SFORM_DEVICE_CODE_OUTPUT=json`)

- `SformEnvironment.IsDeviceCodeJson`: only `json`, any case, trimmed.
- `DeviceCodePrompt.ToJsonLine()`: `{"userCode":…,"verificationUri":…,"verificationUriComplete":…,"expiresIn":<whole seconds>}`, those four camelCase names in that order, `verificationUriComplete` `null` when the provider has none (Entra ID), `expiresIn` rounded and never negative, `&` and `+` unescaped (relaxed encoder).
- `AccountCommand.ShowSignInPromptAsync` writes the line to the inner console's standard error **first**, before the header and the text prompt (unchanged), and flushes it at once (it came after the text before the review; a program now reads the contract before any themed output). Without the variable nothing is written to standard error (a test pins it, and one pins the order).

### 1.6 Browser command (`SFORM_BROWSER`, `BROWSER`)

- New `Services/IBrowserLauncher.cs` and `Services/BrowserLauncher.cs` (registered in `Startup`; `AccountCommand` injects it and `SformEnvironment`). No shell in any case; the process is not awaited. `BrowserLauncher.CreateStartInfos(address)` (internal) lists the starts to try in order, and `TryOpen` takes the first that starts:
  - `SFORM_BROWSER`: `ProcessStartInfo(program) { UseShellExecute = false }` with the address as the only entry of `ArgumentList`. The value is the program alone (a name on the `PATH` or a path, spaces allowed), never split into arguments; a program that needs arguments goes into a script. No fallback: a program that cannot start is reported (catalogue SGN-DEV-04 (b)).
  - `BROWSER` (when `SFORM_BROWSER` is unset): read by the convention other tools follow (`sensible-browser`, Python's `webbrowser`), as the review asked, because other tools set it in that format: entries separated by `Path.PathSeparator`; an entry with `%s` is a command line (split at white space, quotes keep a part together) whose `%s` becomes the address; any other entry is a program that gets the address as its only argument. The entries are tried in order, then the shell's default browser, so a `BROWSER` meant for another tool never makes `-b` worse than before.
  - neither: the shell-executed address as before.
- When nothing starts (`Win32Exception`, `InvalidOperationException`, `PlatformNotSupportedException`), `sform` prints exactly "The browser could not be opened, please open the address manually." and the sign-in goes on (catalogue SGN-DEV-04). The opened address is `verificationUriComplete`, else `verificationUri`.

### 1.7 Output without a console (`SformConsole`, found by the review)

- On Windows, `Console.BufferWidth` throws "The handle is invalid" when no standard handle is a console, which is how the runner of §3.1 starts `sform` (input, output and error redirected). The toolkit's `ExtendedConsole` renders every document (`Write`, `WriteLine`, `WriteHeader`, `WriteImportant`, tables) with Alba.CsConsoleFormat at that width, so every themed line crashed with exit 1 before anything a test could read: the device code prompt, the machine `account` summary (SGN-MSI-01), even `account set -p bad`. Reproduced out of process, older than this phase.
- The fix belongs in the toolkit (`src/Libraries/CLI/Toolkit`, outside this phase's area), so `sform` registers its own `Output/SformConsole.cs` as `IExtendedConsole`: it wraps the toolkit's `ExtendedConsole` and hands every call to it while a console exists (no change in a terminal or with only some streams redirected). Without one (the width throws, or is 0, as it can be on Linux and macOS without a terminal), a document is rendered to text (`ConsoleRenderer.RenderDocumentToText` with a `TextRenderTarget`) at `COLUMNS` characters (at least 20), else 250, and each row is written as a line without its trailing spaces; the last row is not ended, as on a console, where the toolkit's line end follows. Tables are built as the toolkit builds them (the grid code is duplicated, as the toolkit's `WriteTable` renders internally). Prompts and progress bars stay the toolkit's. Once the toolkit renders with a fallback width, this class can go.
- Tests: `Output/SformConsoleTests.cs` (lines, header and important lines, no wrapping of a long address at the default width, `COLUMNS`, tables, `Write` that continues a line, the console detection) and `ProgramProcessTests.cs`, which starts the built `sform` (next to the tests through the project reference) with all three streams redirected: `account set -p bad` (2 and its message), a machine `account` with an API key (the header and the summary, no secret in the output), and an unreachable API (§1.9).

### 1.8 Configuration from the environment and `DOTNET_ENVIRONMENT` (the open issues of the first round)

- `Startup.AddEnvironmentVariables(builder)` adds the variables with the prefix `SFORM_` **last** in `ConfigureApplication` (after the JSON files and the user secrets), so `SFORM_<section>__<key>` wins over every file: `SFORM_general__baseUrl` sets the API of a run, as spec §3.1 assumes. The variables of `sform` itself (`SFORM_HOME`, …) have no double underscore and become top-level keys nothing reads. `general.baseUrl` of a machine still comes from `STORYTELLER_ENDPOINT` (the `PostConfigure` wins). Tested with a section of its own, so the variable cannot reach other tests.
- `Program.ResolveEnvironmentName(getVariable, isSourceBuild)`: a build from source (Debug) runs as `Development` unless `DOTNET_ENVIRONMENT` names another environment, so the runner turns the CLI's user secrets off with `DOTNET_ENVIRONMENT=Production`; a release build always runs as `Production` (decision: an installed `sform` must not load the author's user secrets, which may point at a local API, where a shell sets `DOTNET_ENVIRONMENT=Development` for other tools). The environment name is also a property of the telemetry event.

### 1.9 An unreachable API (catalogue GEN-CLI-04, found by the review)

- A refused connection of the SDK is an `HttpRequestException`, which `Program.RunAsync` did not map: `story -p …` against a closed port crashed with 1 ("Total mayhem"), verified out of process. `Program.RunAsync` now ends an `HttpRequestException`, and a `TaskCanceledException` of an `HttpClient` timeout, with `ERROR_SERVICE_FAILURE` (3): "! The 2S platform could not be reached: <reason>" and "  The API is <base URL> (general.baseUrl, SFORM_general__baseUrl, or STORYTELLER_ENDPOINT for a machine); check the address and the network." (the base URL is read from `IOptions<GeneralOptions>` when the host starts). The warning logged names neither the arguments nor the request. `config get` handles these exceptions itself and keeps its codes.

### Overlap with 424-218 (user settings file)

The plan "sform account settings and User Preferences File" (Linear 424-218, `docs/Platform/Cli/specs/2026-11-08 sform account settings and User Preferences File.md` on branch `feat/424-218`, not yet in `main`) moves the editor and the default project into `sform.settings.json` in the `.42for.net` folder. It should build on `CliPaths` instead of a second `UserSettingsLocation`:
- its settings file is `Path.Combine(paths.UserDirectory, "sform.settings.json")`; its legacy files are `paths.AccessDefaultFile` and `paths.EditorConfigFile` (the state directory); with `SFORM_HOME` both are in `SFORM_HOME`, so the automation tests keep one folder per user;
- `Startup.AddConfigurationFiles` is the one place to add the user file after the legacy ones (the `SFORM_` variables stay last, in `ConfigureApplication`);
- `AccountSetCommand.CreateAccessDefaultConfigFile(…, CliPaths)` and `EditorService.SaveEditorOptions` (both now on `CliPaths`) are the methods it replaces with `IUserSettingsStore`;
- its `IEnvironmentVariables` seam can be the `Func<string, string?>` shape used here (`SformEnvironment.FromEnvironment`, `MachineSignInSettings.FromEnvironment`);
- its `account settings editor` without an argument on redirected input can use `EnsureInteractiveValue` (2, as it plans), and the hint of `EditorService.SetupEditorPreference` should then name the settings file instead of `editor.config.json`.

### Catalogue expectations the CLI does not meet (for the catalogue or later phases)

- **`-o <org>`** (SGN-DEV-01, 03, 04, 05, SGN-OUT-01, spec §3.2 and §3.4): in the catalogue `<org>` is the 2S organization name (the one of `-p <org>.<project>` and `Target:Organization`), but `-o` takes the **WorkOS organization id** (decision above).
