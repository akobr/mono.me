# Phase 3 of CLI Automation Testing Project

Linear: [424-215](https://linear.app/424fun/issue/424-215/create-cli-automation-testing-project-sform-against-a-real-backend).

## Overview

Phase 3 is the third row of section 7 of [CLI Automation Testing Project](../2026-11-08%20CLI%20Automation%20Testing%20Project.md): the project `src/Platform/Cli.AutomationTests/src` (`42.Platform.Cli.AutomationTests`, TUnit) of section 3 with its infrastructure (the runner of section 3.1 with a pseudo terminal, the device code sign-in of section 3.2, the machines of section 3.3, the target check of section 3.4, the settings of section 3.6), the 12 Elementary cases of the catalogue ([test-cases.md](../../test-cases.md)), self tests of the machinery that need no target, and the docs ([automation-tests.md](../../automation-tests.md), the project's `README.md`). It builds on phase 1 (the CLI's `SFORM_HOME`, `SFORM_TOKEN_STORE=file`, `-o`, no hangs, the device code as JSON; [review](../../../Cli/specs/reviews/2026-11-08%20Phase%201%20of%20CLI%20Automation%20Testing%20Project.md)) and phase 2 (`AutomationTest`, `OpenBrowserAsync`, `AddSecret`, the shared library; [review](../../../../Libraries/Testing/UI.Automation/specs/reviews/2026-11-08%20Phase%202%20of%20CLI%20Automation%20Testing%20Project.md)). No change was needed in `src/Platform/Cli`, `src/Libraries/Testing` or `src/Platform/Automation.Shared`.

| Run | Result |
|---|---|
| `dotnet build src/Platform/Cli.AutomationTests/src` | 0 errors, 0 warnings (builds `src/Platform/Cli/src` through the project reference) |
| `dotnet test --project src/Platform/Cli.AutomationTests/src` (no target, Windows 11) | 51 tests: 39 self tests passed, 12 Elementary tests skipped with the README hint, exit 0 (after the review's fixes, [below](#review-of-the-phase)) |

The Elementary tests were **not run against a target**: there was no local API (Aspire) and no AuthKit pool for the CLI. What that leaves unverified, and how the first real run verifies it, is at the end.

### 3.1 Running `sform`

- **`SformRunner`** (`RunAsync(arguments, SformRunOptions)`, `StartAsync(…)`), configured per test by `SformRunnerOptions` (locator, `Cli:TimeoutMs`, `Target:BaseUrl`, default home and working directory, the scope's `Redact`, `AddSecret` and `AttachTextAsync`, the test's cancellation, the session's `IFileSystem`). It starts `dotnet <dll>` (the host from `DOTNET_HOST_PATH`, the current process, `DOTNET_ROOT`, `%ProgramFiles%\dotnet` or the `PATH`: `DotnetHost`) or the executable of `Cli:Path`, with `ProcessStartInfo.ArgumentList`.
- **The environment is built from scratch** (`SformProcessEnvironment.Build`): a whitelist of the machine's variables (`PATH`, `PATHEXT`, `SystemRoot`, `SystemDrive`, `windir`, `ComSpec`, `TEMP`, `TMP`, `TMPDIR`, `USERPROFILE`, `HOME`, `HOMEDRIVE`/`HOMEPATH`, `USERNAME`/`USER`/`LOGNAME`, `LOCALAPPDATA`, `APPDATA`, `ProgramData`, `ProgramFiles*`, `CommonProgramFiles*`, `DOTNET_ROOT*`, `DOTNET_CLI_HOME`, `DOTNET_HOST_PATH`, `NUGET_PACKAGES`, `LANG`, `LANGUAGE`, `LC_*`, `TZ`, `SSL_CERT_*`, the proxy variables), then `DOTNET_ENVIRONMENT=Production`, `SFORM_TELEMETRY_OPTOUT=1`, `DO_NOT_TRACK=1`, `NO_COLOR=1`, `COLUMNS=1000` (phase 1's suggestion; above the 250 asked), `DOTNET_NOLOGO=1`, `DOTNET_CLI_TELEMETRY_OPTOUT=1`, `DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1`, `SFORM_HOME` (always, also for machines), `SFORM_TOKEN_STORE=file`, for a user's run `SFORM_general__baseUrl`, for a machine its `STORYTELLER_*`, in a terminal `TERM`, `COLUMNS`, `LINES`, and last the run's `SformRunOptions.Environment` (`null` removes), and `CLI_AUTOMATION_PROCESS_TAG` (the run's `ProcessJob`). `SFORM_HOME` is set again after the run's own variables, so no variable removes it; `SformRunOptions.WithoutHome` leaves it out (GEN-CLI-06), with `HOME` and the `XDG_*` folders pointed at an empty folder of the test off Windows (on Windows sform finds the user's folder through the known-folder API, so such a run reads the real profile and is to be killed after its first line, as the case says).
- **`SformRunOptions`** (a record): `Environment`, `Input`, `Timeout`, `WorkingDirectory`, `Home`, `Machine`, `Terminal`, `TerminalColumns`/`TerminalRows` (250 × 50), `BaseUrl`, `Secrets`, `SecretsOf` (the secrets a test learns from the run's output, registered before the run is attached), `WithoutHome`, `RenewExpiredSession`, `Label`.
- **Standard input**: `Input` is written, then the input is closed (at once without it).
- **Timeout**: the run's lifetime token kills the process tree (`Process.Kill(entireProcessTree: true)` and the run's `ProcessJob`, or `TerminateProcess` of the pseudo console's child) and `WaitForExitAsync` throws an `SformTimeoutException` with the redacted output so far, after the run was attached.
- **What sform leaves running** (`RedirectedChild`, `ProcessJob`): a process sform started that outlives it and inherited its streams kept the run open for ever, as `Kill(entireProcessTree)` walks the tree only from a living parent. Each redirected run is in a `ProcessJob`: a job object with kill-on-close on Windows (joined right after the start), the inherited variable `CLI_AUTOMATION_PROCESS_TAG` elsewhere (the processes whose `/proc/<pid>/environ` holds it). Three seconds after sform ended with its streams still open, the job's processes are killed; two seconds later the reading is cancelled and the run ends with a note on its standard error. The job also ends with the run.
- **Encodings** (`ConsoleEncodings`, `ConsoleOutputDecoder`): on Windows a .NET child with redirected streams gets a hidden console of its own, and writes and reads them in its OEM code page (437 here), except where sform switches its output to UTF-8 (`config --format`/`--content-only`). The runner reads valid UTF-8 as UTF-8 and any other byte in the OEM code page (`GetOEMCP`), and writes the input in the OEM code page; a character the code page lacks is lost on sform's side (its best fit or `?`), which only a CLI change fixes. Elsewhere UTF-8.
- **`SformResult`**: `ExitCode`, `RawExitCode`, `Exit` (`CliExit?`), `StdOut`/`StdErr` as written, `PlainStdOut`/`PlainStdErr`/`Lines`/`ErrorLines` without escape sequences (`AnsiText.Plain`: colours, OSC titles, charset selections removed; a cursor-forward and an erase of characters become spaces, a cursor position or a cursor down a line break, CR LF and a lone CR a line break) and the standard output with WriteJson's folds joined (`WrappedJson`, below), `Timeline` and `Output` (the lines of both streams in arrival order), `Duration`, `IsTerminal`, `WorkingDirectory`, `Home`. Assertions that throw an `SformAssertionException` with the command line, the exit code, what they looked for and the output, all redacted, and return the result: `ShouldSucceed`, `ShouldExitWith(CliExit|int)`, `ShouldExitWithAnyOf`, `ShouldFail` (non-zero, not a crash), `ShouldContain`/`ShouldNotContain`/`ShouldMatch`/`ShouldHaveLine` on a stream, `Fail(what)`; `ShouldSucceed`, `ShouldExitWith` and `ShouldFail` also on the task (`await Sform(…).ShouldSucceed()`). No assertion library was added (TUnit's `Assert.That` for the rest; Shouldly is not referenced).
- **Exit codes**: on Linux and macOS an exit status is a byte, so sform's -1 arrives as 255 (also through `script -e`); `SformResult.ExitCodeOf` reads 255 back as -1 off Windows (sform defines no 255), and `RawExitCode` keeps what the system reported.
- **JSON** (phase 1's note that the read commands colour their JSON and number its lines): `JsonNode()` takes the whole plain standard output when it is a document (`--content-only`, `--value-only`, `--format json`, `--json`), else the first block of numbered lines (`SformResult.NumberedBlocks`: the ` n │ ` gutter of `WriteJson` and `WriteNumberedText` removed, the colours gone), else the first balanced `{…}`/`[…]`; `Json<T>()` deserializes it with web defaults (sform writes PascalCase). Decision: read the CLI's output as it is instead of changing the CLI.
- **WriteJson's 80 columns** (`WrappedJson`): `WriteJson` renders through a Spectre console over a `StringWriter`, whose width is 80 whatever `COLUMNS` says (checked with Spectre.Console.Json 0.57.2: `Profile.Width` 80 with `COLUMNS=1000`). A token that does not fit moves to the next line, a string wraps at its spaces (dropping the space at the start of the new line, or keeping it at the end of the full one), and a token longer than 80 is folded into lines of 80 inside its string: a created machine's API key (`2s.` + 76 characters + `.` + the secret), a unit key of about 85 characters. `WrappedJson.Join` replaces a numbered block that is no JSON as printed but is JSON with its folds joined: a line that ends inside a string goes on without a separator when it is a fold (80 columns, no white space) or ends with white space, else with one space; everything else stays as printed. `PlainStdOut` is joined, so `JsonNode()`, `ShouldContain(key)`, `SecretScanner` and the redaction of the attachment and the messages see the key whole; `AnsiText.Plain(StdOut)` is the text as printed.
- **`CliExit`** mirrors `ExitCodes.cs` (`InputParsing` -1 … `PartialResult` 45).
- **`SformProcess`** (streaming): `WaitForLineAsync(stream, predicate, timeout)`, `WaitForLineOrExitAsync` (null when sform ended without the line), `ExpectAsync(text|Regex, timeout)` (on the plain screen after the previous expectation; white space in a text matches any white space or none, because a pseudo terminal's renderer may move the cursor instead of writing spaces; an unfinished escape sequence at the end is not read yet, `AnsiText.CompletePrefixLength`), `SendAsync`, `SendLineAsync`, `SendKeyAsync(TerminalKey, times)`, `WriteAsync`, `CloseInput`, `WaitForExitAsync(timeout?)`, `KillAsync`, `Completion` (never throws), `Screen`, `StdOut`, `StdErr`, `LinesOf`, `HasExited`. Each wait has 30 s by default; a wait that times out, or sform that ends first, fails with what it wrote. A running process is killed and attached when the test disposes it, at the end of the test at the latest.
- **Terminal mode** (`SformRunOptions.Terminal`, mode T), without a package:
  - Windows: `ConPtyChild`, a ConPTY pseudo console through P/Invoke (`CreatePipe`, `CreatePseudoConsole`, `InitializeProcThreadAttributeList`/`UpdateProcThreadAttribute` with `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`, `CreateProcessW` with `EXTENDED_STARTUPINFO_PRESENT | CREATE_UNICODE_ENVIRONMENT`, the environment block sorted, the command line quoted by .NET's rules, `CommandLines.Windows`). The child gets `STARTF_USESTDHANDLES` with no handles, so a test host whose own streams are redirected (`dotnet test`) does not hand them down; the output pipe is read all the time on its own thread; once the process ended, `ClosePseudoConsole` flushes the last frame and ends the pipe.
  - Linux: `ScriptChild`, util-linux `script -q -e -f -c "stty cols … rows …; exec '<arg>' …" /dev/null` (every argument single-quoted, `CommandLines.PosixShell`), `SHELL=/bin/sh`, `TERM=xterm-256color`.
  - macOS: not supported; `TerminalSupport.Reason` says why, and `[Terminal]` tests skip with it. Deviation from the spec's "openpty on Linux and macOS": no P/Invoke of `openpty`/`fork` from .NET (a forked .NET process cannot run managed code safely), and BSD `script` takes other options; macOS can follow with its own branch.
  - Keys: `TerminalKey` (`Enter` CR, `Tab`, `Space`, `Escape`, `Backspace` DEL, `Delete`, arrows, `Home`, `End`, `PageUp`, `PageDown`, `CtrlC`, `CtrlD`) as an xterm sends them. sform's prompts are Sharprompt's (`Console.Select`, `Input`, `Confirm`, `Password`), not Spectre's as the task assumed; the self test answers a Sharprompt selection and two inputs.
- **Attachments**: each run is `sform-<n>.txt` (command line, label, working directory, `SFORM_HOME`, the variable names, terminal or not, exit code, duration, both streams in plain text, the standard output with WriteJson's folds joined and a note when it was) through `TestScope.AttachTextAsync`. Before it, `SecretScanner` registers what sform printed once (`"AccessKey"`, `"ClientSecret"`, `"CertificatePassword"`, `"AccessToken"`, `"RefreshToken"` of the JSON, the lines `Client secret:` and `Certificate password:`, any `2s.<…>.<…>` key, the values of `::add-mask::` lines with `%25`, `%0D`, `%0A` undone) with `TestScope.AddSecret`, then what `SformRunOptions.SecretsOf` returns; `SformRunOptions.Secrets` and a machine's secrets are registered before the run starts. An attachment is never rewritten, so a secret registered after its run does not reach it.

### 3.2 Users: device code with Playwright

- **Homes and working directories** (`SformHome`, `SformHomes`): all under `<temp>/sform-automation/<runId>/`, outside `Execution:ArtifactsPath` (the UI suite's workflow uploads the results directory as a whole). A pool user's home is `homes/<user fingerprint>/`, one per user for the session (keyed by run id and fingerprint), reused by the user's tests and by the target check's user; its `access.default.json` and `editor.config.json` are removed when a test first uses it. Per-test empty homes (`[FreshSignIn]`, `FreshHome()`, each machine run, a run without `SFORM_HOME`) are `homes/tests/<id>/`, removed at the end of the test. A test's working directory is `work/<class>.<method>-<id>/`, removed when the test passes, kept when it does not (or with `Cli:KeepWorkingDirectories`) with `work-files.txt` (its file names and sizes) attached; the target check's is removed after the check. The session files (`*.plaintext`) of every home are deleted when the process exits. Deviation: spec section 3.1 put the working directory under the artifacts and section 4.3 attached its files on failure; they can hold a `.pfx` with its private key, a `GITHUB_ENV` file with resolved secrets or a kv export, so only the list is attached, and a test attaches a file it needs with `AttachFileAsync` (redacted).
- **`DeviceCodeSignIn`** follows the phase 2 amendment (`Target:SignIn None`): `sform account [-o Target:AuthKitOrganizationId]` with `SFORM_DEVICE_CODE_OUTPUT=json`, the first JSON line of stderr parsed (`DeviceCodePrompt`, also `TryParseText` for the text prompt of SGN-DEV-03), `TestScope.OpenBrowserAsync()` (anonymous) at `verificationUriComplete`, then `AuthKitDevicePage.CompleteAsync`, an order-free step machine that, until sform ends, enters the credentials when an `Email` text box shows (`AuthKitHostedPage.EnterCredentialsAsync`, typed), types the user code into a field named like a code, and clicks a button whose name matches `^(Confirm|Continue(?! with)|Approve|Allow|Authori[sz]e|Yes|Accept)` (or, to decline, `^(Deny|Decline|Cancel|Reject|No|Don't allow)`), at most a few times per page. sform signed in is exit 0 or 43 (no default project). A page that does not lead there within three quarters of the run's timeout (at least 30 s), or sform that ends with another code, fails with `… the device page showed: <url without query>: <text>`, plus `device-page-<n>.png` (inputs masked) and `device-page-<n>.txt`.
- **`DeviceCodeOptions`**: `Command` (`account`/`login`/`access`), `Organization` (`null`: the setting; `""`: no `-o`), `OrganizationOption`, `Arguments`, `Environment`, `Decline` (SGN-DEV-05), `ExpectSignedIn` (false: any exit after the approval is returned, for SGN-DEV-06 and SGN-DEV-07, which expect 2), `UseCachedBrowserSession`, `JsonPrompt`, `ApprovalTimeout`; **`DeviceCodeSignInResult`** (`Result`, `Prompt`, `Steps`, `IsSignedIn`, `WasSignedInAlready`).
- **The cached AuthKit session** (`AuthKitSessionCache`): after a successful approval the context's storage state is kept in memory per run and user; a later approval for that user starts a context of its own from it (`scope.Browser.Browser.NewContextAsync(Session.ContextOptions.Create(state))`, closed by the sign-in), so it may skip the credentials. Decision: not the runtime's `StorageStateCache`, which needs a registered sign-in flow (phase 2's decision: none for the CLI); a state AuthKit does not take only costs the credentials again.
- **Session expiry**: a user run that ends with 44 and the CLI's general refusal (`CliTest.GeneralRefusal`) runs `sform account` once in the same home; a new device code (the session was gone) is approved and the run goes once more; "already logged in" keeps the first result.
- Passwords are typed only in `OpenBrowserAsync` contexts or the sign-in's own context, never traced; `Execution:Trace` is `Off` in the defaults and documented why.
- **Other pool users** (not in the plan, needed by the catalogue's Reader cases and the grants): `AsAnotherUserAsync(requirement)` leases one with its own home (`SformActor.Sform(…)`, signed in on its first run, `SformActor.AccountIdAsync()`); `ArrangeAsEditorAsync()` gives the leased user when it may edit, else another Editor (also in a `[MachineOnly]` test, which leases nobody), to create what a Reader's case reads in the acting project. A role project of `Target:RoleProjects` has no writer (every pool user holds the role there), so it throws there with what to change. `AsGrantedUserAsync(role)` leases another pool user, reads its account id and grants it the role in a project of the test's own (`GrantAsync`: `account points grant <id> -p <project> -r <role>`, refused for any other project, where the pool's roles are fixed): the "second user" of a P case.

## Catalogue mismatches found

- **CFG-SET-05**: `config set -c|--custom-properties` and `-l|--labels` are parsed but not applied (`ConfigSetCommand`: `// TODO: [P1] add support for custom properties and labels`), so "the model shows them" cannot pass; CFG-GET-01's "labels" of the model cannot be set through sform either (the test checks the content and the version only). A CLI change (or a catalogue change) for phase 5.
- **CFG-GET-01, CFG-GET-02** (and every Reader or Contributor case that reads data it cannot write): the data is arranged by an Editor in the project the role reads; with `Target:RoleProjects` mapping the role to a project where every pool user holds it, nobody can write there. The Elementary Reader cases therefore need a Reader of `Target:Project` (no `Reader` entry in `Target:RoleProjects`), or pre-provisioned data in the role project; ANN-SET-08 works either way.
- **ACC-SET-01** "story lists the annotations of that view": the role is Any (possibly a Reader, who cannot create a marker annotation), so the test checks that `story` without `-p` reads (exit 0, no "sform account set" hint) and the stored default, not which annotations it lists.
- **SGN-DEV-01**: the user name sform prints for an AuthKit user (`SignedInUser.UserName`) is assumed to be the e-mail ("You have been logged in as `<email>`", the header `<name> @ <email>`); unverified.
- **CFG-SET-01**: `-x b.c=true` stores a property named `b.c`, not `{"b":{"c":true}}` (`JsonInputBuilder`); the catalogue's wording fits both, the test checks `b.c`.
- **P cases**: the catalogue now makes every P case an Owner case (81), with a "second user" granted a role in the Pre; the API follows it (`CreateDisposableProjectAsync` acts in the project, `AsGrantedUserAsync`). MCH-LIF-10 (a ContributorWithSecrets refused `-m`) and ACC-PNT-07 (an Administrator cannot grant Owner) are such cases, so the pool needs no ContributorWithSecrets user.
- **GEN-CLI-06** on Windows: the run without `SFORM_HOME` reads the real profile (known-folder API); the catalogue's "stopped after its first line" keeps it short, and `SformRunOptions.WithoutHome` documents it.
- **Long values in WriteJson** (MCH-LIF-03, CFG-GET-02 and any read of a unit key or a long value): folded at 80 columns by the CLI; joined by `WrappedJson`, except that a run of spaces where a text value wrapped comes back as one space. ### CLI defects found (outside phase 3, for a CLI change)

- **WriteJson renders at 80 columns** (`src/Platform/Cli/src/Output/ExtendedConsoleExtensions.cs`, `WriteJson`): the capture console over a `StringWriter` has Spectre's default width, 80, whatever `COLUMNS` says, so long values are folded inside their strings and a person cannot copy a created machine's API key from the terminal in one piece either. Fix: give the capture console the width of the text (e.g. `captureConsole.Profile.Width = int.MaxValue`, or `COLUMNS`). `WrappedJson` then joins nothing.
- **Redirected streams on Windows use the OEM code page**: a .NET program started without a window writes and reads its redirected streams in its hidden console's code page; sform switches to UTF-8 only in `config` with a format (`PlainOutputExtensions.UseUtf8Output`). Fix: set `Console.OutputEncoding` and `Console.InputEncoding` to UTF-8 (without a BOM) at startup when the streams are redirected. The runner's decoding keeps working either way.

Not a defect, but noted for the formatted-output cases: `WriteNumberedText` writes every `#` of a `--format` payload printed with the gutter as `\u0023` on purpose (so a line cannot hold the `##[command]` of GitHub Actions); a case that compares such text uses `--content-only` or undoes it.
