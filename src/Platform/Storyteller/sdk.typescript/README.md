# @42for.net/2splatform.sdk

TypeScript SDK for the Storyteller API of the 2S Platform, generated by [Orval](https://orval.dev) from the OpenAPI document next to this file (`open.api.v*.json`). The C# SDK (`../Sdk.NSwag`) is generated by NSwag from the same document.

| Entry point | Content | Needs |
| --- | --- | --- |
| `@42for.net/2splatform.sdk` | Request functions (`getAccount`, `getAnnotation`, `patchConfiguration`, …), model types, `configureStoryteller`, `StorytellerError`, annotation key, role and paging helpers, the [workload identity federation](#workload-identity-federation) helpers | nothing (global `fetch`) |
| `@42for.net/2splatform.sdk/vue-query` | TanStack Query for Vue composables (`useGetAnnotation`, `useSetMemberRole`, …), query key functions (`getGetAnnotationQueryKey`), `invalidateByPath`, `removeByPath` | `@tanstack/vue-query`, `vue` |
| `@42for.net/2splatform.sdk/zod` | Zod 4 schemas of parameters, bodies and responses (`SetAnnotationBody`, `GetConfigurationsResponse`, …) | `zod` |
| `@42for.net/2splatform.sdk/msw` | MSW handlers with Faker data (`getStorytellerMock()`, `getGetMembersMockHandler(…)`, …) | `msw`, `@faker-js/faker` |

## Usage

Configure the fetcher once; every request function and composable uses it.

```ts
import { configureStoryteller, getAccount, isForbidden } from '@42for.net/2splatform.sdk'

configureStoryteller({
  baseUrl: 'https://api.2s.42for.net/api',
  getAccessToken: ({ forceRefresh }) => authkit.getAccessToken({ forceRefresh }), // bearer for user calls
  onUnauthorized: () => authkit.signIn(), // a 401 survived one token refresh
})

try {
  const account = await getAccount()
} catch (error) {
  if (isForbidden(error)) {
    // authenticated, but the role on the project is too low
  }
}
```

The fetcher (`lib/fetcher.ts`, the Orval mutator):

- prefixes `baseUrl` to the generated `/v1/...` paths,
- adds `Authorization: Bearer …` when `getAccessToken` returns a token, and asks for a token once more after a `401` (with `forceRefresh: true`),
- parses `application/json` and `application/*+json` bodies, returns `application/zip` and `application/octet-stream` bodies as a `Blob` (the archives of view exports), and every other content type as text (PEM certificates, unified diffs),
- throws `StorytellerError` (`status`, `message`, `hint`, `errorCode`, `schemaErrors`) for non-2xx responses, and with `status: 0` for network failures and aborts (`aborted: true`, `isAborted(error)`). For the OAuth error bodies of the token endpoint, `errorCode` is the `error` (`invalid_request`, …) and `message` the `error_description`.

With Vue Query, query keys are the path segments of the request, so cache invalidation can use paths:

```ts
import { useGetConfiguration, usePatchConfiguration, invalidateByPath } from '@42for.net/2splatform.sdk/vue-query'

const configuration = useGetConfiguration(org, project, view, key) // refs, getters or strings
const patch = usePatchConfiguration({
  mutation: {
    onSuccess: () => invalidateByPath(queryClient, `/v1/${org.value}/${project.value}/${view.value}/configuration/${key.value}`),
  },
})
```

In tests, serve the generated handlers and override single operations:

```ts
import { setupServer } from 'msw/node'
import { getStorytellerMock, getGetMembersMockHandler } from '@42for.net/2splatform.sdk/msw'

const server = setupServer(...getStorytellerMock())
server.use(getGetMembersMockHandler([{ AccountId: 'user_01', Role: 'Owner' }]))
```

The handlers match `*/api/v1/…`, so `baseUrl` must end with `/api`.

## Development

The npm package lives in `src/`; the generated code in `src/generated` is committed.

```bash
cd src
npm ci                 # installs from package-lock.json
npm run generate       # Orval from the newest ../open.api.v*.json, then sets the package version
npm run typecheck
npm run lint           # oxlint
npm test               # vitest
npm run build          # tsup → dist/ (ESM + .d.ts per entry point)
```

To generate from a specific document: `SPEC=../open.api.v0.9.0.json npm run generate` (PowerShell: `$env:SPEC='../open.api.v0.9.0.json'; npm run generate`). The package version follows `info.version` of the document (`0.8.91.29486` → `0.8.91`).

Before generation, `scripts/openapi-transformer.mjs` (an Orval input transformer) corrects the document:

- The `application/json-patch+json` bodies of `PatchConfiguration` and `PatchTemplate` are documented as `object`; the transformer replaces them with a required array of `JsonPatchOperation` (`op`, `path`, `from`, `value`).
- `Values` of annotations and configurations is `IReadOnlyDictionary<string, object>` in C#, documented as a map of objects; the transformer widens it to a map of any JSON value, so the Zod schemas accept numbers and strings.
- `GrantUserAccess` and `RevokeUserAccess` are marked deprecated (the members endpoints replace them in browser clients).

Remove a correction once the API documents it itself.

```ts
await patchConfiguration(org, project, view, key, [
  { op: 'test', path: '/retries', value: 3 },     // 412 PatchTestFailed when the value changed meanwhile
  { op: 'replace', path: '/retries', value: 5 },
])
```

A new API version:

1. Export the OpenAPI document into `open.api.v{version}.json` here and in `../Sdk.NSwag`. The API test `OpenApiExportTests` renders it with the engine of the Functions host, so no host has to run: `STORYTELLER_OPENAPI_EXPORT=<path> dotnet test ../Api.Functions/test --filter "FullyQualifiedName~OpenApiExportTests"` (the running host serves the same document at `/api/openapi/v3.json`). Remove the superseded `open.api.v*.json` here; `../Sdk.NSwag` keeps its history.
2. `npm run generate`, review the diff of `src/generated`, run the tests, commit.
3. A new tag (a new folder under `src/generated/vue-query`) also goes into `src/msw.ts` by hand: its `get<Tag>Mock()` into `getStorytellerMock()`, and an `export *` of its `.msw` file. `test/msw.test.ts` fails until it is there. The other entries pick a new tag up through the generated `index.ts` files.

`dotnet build` builds `sdk.typescript.esproj` without Node. Pass `-p:BuildJavaScript=true` to also run `npm install` and `npm run build`.

Notes:

- Node 22.18 or newer (Orval 8). Node 24 LTS is pinned in `src/.nvmrc`.
- TypeScript is held at 6.0, because tsup's declaration build and typedoc (an Orval peer) do not support TypeScript 7 yet.
- npm 10.9.2 can crash with `Cannot read properties of null (reading 'edgesOut')` when it resolves this dependency set without a lockfile. `npm ci` from the committed `package-lock.json` is not affected; newer npm versions are not affected either.

## Key/value pairs

The root entry has the generated functions of the `key-values` tag (`getKeyValues`, `getKeyValue`, `setKeyValue`, `deleteKeyValue`, `restoreKeyValues`, `purgeKeyValues`, `protectKeyValues`, the versions and diffs, `exportKeyValues`, `importKeyValues`, the policy, recipients, `getKeyValueAudit` and `getKeyValueUsage`), their Vue Query composables under `./vue-query`, Zod schemas under `./zod` and MSW handlers under `./msw`, plus the helpers of `lib/key-values.ts`:

| Helper | Purpose |
| --- | --- |
| `isValidKeyValueKey`, `normalizeKeyValueKey`, `isSecretProtection` | The key rules of the API (dot-separated segments, 128 characters, case-insensitive) and the levels |
| `parseDotEnv`, `serializeDotEnv`, `toEnvKey`, `fromEnvKey` | `.env` text with `#` comments, `export`, quoted values and escapes; `db.password` ↔ `DB__PASSWORD` |
| `flattenJson`, `unflattenJson`, `toFlatJson`, `toKeyValueDocument` | Nested JSON ↔ dotted keys, and the `2s.key-values.v1` document of export and import |
| `detectKeyValueFormat` | `document`, `flat-json`, `json`, `dotenv` or `unknown` for pasted text |
| `isSecretReference`, `parseSecretReference`, `formatSecretReference` | References to secrets in the customer's Key Vault (`kv://vault/name`, the vault URI, App Configuration's `{ "uri": … }`) |

```ts
import { getKeyValues, importKeyValues, parseDotEnv, toKeyValueDocument } from '@42for.net/2splatform.sdk'

const document = toKeyValueDocument(parseDotEnv(text))              // every item Public
await importKeyValues('acme', 'billing', 'default', document, { mode: 'Merge', dryRun: true })
const page = await getKeyValues('acme', 'billing', 'default', { keyPrefix: 'db.', includeValues: true })
```

### Client-side encryption (`./hyok`)

Values of the `Hyok` level are encrypted before they reach the platform, for the RSA public keys registered as the project's recipients. `@42for.net/2splatform.sdk/hyok` does it on WebCrypto, in browsers and in Node 22 or later, with no runtime dependencies: JWE General JSON Serialization, `A256GCM` content, `RSA-OAEP-256` per recipient, and the place `{organization}/{project}/{view}/{key}` in the protected header. The C# library `KeyValues.ClientEncryption` and the CLI read and write the same documents; the tests check both directions against `jose`.

```ts
import { getRecipients, setKeyValue } from '@42for.net/2splatform.sdk'
import { decryptClientSecret, encryptForRecipients, generateRecipientKeyPair, getHyokPlace } from '@42for.net/2splatform.sdk/hyok'

const recipients = await getRecipients('acme', 'billing')                 // the API's ClientEncryptionRecipient[]
const place = getHyokPlace('acme', 'billing', 'default', 'db.password')
const value = await encryptForRecipients('s3cret', recipients, place)
await setKeyValue('acme', 'billing', 'default', 'db.password', { Protection: 'Hyok', Value: value })

const plain = await decryptClientSecret(value, privateKeyPem, 'api')       // the holder of a recipient's private key
const { publicJwk, privateJwk } = await generateRecipientKeyPair()         // a new recipient: register publicJwk
```

## Export and import of a view

The `transfers` tag runs the jobs that export the documents of a view into a zip and import a zip into a view: `startViewExport`, `getViewExport`, `getViewExportArchive`, `startViewImport` and `getViewImport` (`docs/Platform/Storyteller/export-import.md`). `Include` and the import's `include` list the kinds (`ViewArchiveContent`: `Annotations`, `Schemas`, `Templates`, `Configurations`), all four when empty; the query sends them comma-separated. `existing` is `Overwrite` (the default) or `Skip`. The archive comes back as a `Blob`. Their Vue Query composables are under `./vue-query`, Zod schemas under `./zod`, and MSW handlers under `./msw` (`getTransfersMock()`, part of `getStorytellerMock()`, and `getStartViewExportMockHandler(…)` and the rest).

```ts
import { getViewExport, getViewExportArchive, getViewImport, startViewExport, startViewImport } from '@42for.net/2splatform.sdk'

const started = await startViewExport('acme', 'billing', 'default', { Format: 'Folder', Include: ['Annotations', 'Templates'] })
const exported = await getViewExport('acme', 'billing', 'default', started.Id!)          // poll until Status is Succeeded
const zip = await getViewExportArchive('acme', 'billing', 'default', exported.Id!)       // a Blob

const check = await startViewImport('acme', 'billing', 'staging', zip, { include: ['Templates'], existing: 'Skip', dryRun: true })
const result = await getViewImport('acme', 'billing', 'staging', check.Id!)              // Summaries per kind, Items with their Warnings
```

## Workload identity federation

A `Federated` machine has no secret. The workload exchanges a token of its platform (GitHub Actions, Kubernetes, Vercel, Azure managed identity, AWS, Google Cloud) at the project's token endpoint, `POST /v1/{organization}/{project}/access/token` ([RFC 8693](https://www.rfc-editor.org/rfc/rfc8693)), for a short-lived Storyteller token. Trusted issuers, federation rules and the setup per platform are in "Machine access with workload identity federation" of `docs/Platform/Storyteller/authentication.md`.

`createFederatedTokenProvider` is a `getAccessToken` for `configureStoryteller`. It asks `getSubjectToken` for a current platform token, exchanges it, and reuses the Storyteller token until 60 s before it expires. Concurrent requests share one exchange, and a failed exchange is not cached. If an exchange in those last 60 s fails, the request still gets the cached token, which is valid until it expires, and the next request tries the exchange again. The fetcher's retry after a `401` drops the cached token and exchanges again, so a failure there fails the request.

```ts
import { getVercelOidcToken } from '@vercel/oidc'
import { configureStoryteller, createFederatedTokenProvider, getAnnotations } from '@42for.net/2splatform.sdk'

const baseUrl = 'https://api.2s.42for.net/api'
const tokenEndpoint = `${baseUrl}/v1/acme/billing/access/token` // the machine's TokenEndpoint, and the rule's audience

configureStoryteller({
  baseUrl,
  getAccessToken: createFederatedTokenProvider({
    baseUrl,
    organization: 'acme',
    project: 'billing',
    machineId: '3f1c2a9e-5b7d-4c11-9e0a-2d4f6b8c1a07',                  // client_id
    getSubjectToken: () => getVercelOidcToken({ audience: tokenEndpoint }), // never the default audience
    scope: 'Annotation.Read',                                             // optional: a subset of the machine's scopes; all of them when omitted
  }),
})

const page = await getAnnotations('acme', 'billing', 'default')
```

`getVercelOidcToken({ audience })` needs `@vercel/oidc` 3.7.0 or later. A token with a custom audience always carries the team issuer `https://oidc.vercel.com/<team-slug>`, whatever issuer mode the project uses, so that is the trusted issuer, never the global `https://oidc.vercel.com`.

`getSubjectToken` on other platforms:

| Platform | `getSubjectToken` | `subjectTokenType` |
| --- | --- | --- |
| GitHub Actions (`permissions: id-token: write`) | `() => core.getIDToken(tokenEndpoint)` (`@actions/core`) | default (`…:jwt`) |
| Kubernetes (a projected `serviceAccountToken` with the rule's audience) | `async () => (await readFile('/var/run/secrets/storyteller/token', 'utf8')).trim()`; read the file for every exchange, the kubelet rotates it | default |
| Azure managed identity | a token for `resource=api://<appId>` from IMDS or `IDENTITY_ENDPOINT` | `FederatedSubjectTokenType.AccessToken` |
| AWS (outbound identity federation enabled) | `async () => (await sts.send(new GetWebIdentityTokenCommand({ Audience: [tokenEndpoint], SigningAlgorithm: 'ES384' }))).WebIdentityToken!` with `const sts = new STSClient({ region: 'eu-central-1' })` (`@aws-sdk/client-sts`); a regional client, the global STS endpoint does not offer the operation | default |
| Google Cloud | the metadata server's `…/identity?audience=…&format=full` | `FederatedSubjectTokenType.IdToken` |

`exchangeFederatedToken` does a single exchange and returns `{ accessToken, expiresAt, scope }` (`expiresAt` in milliseconds, like `Date.now()`), for example to pass the token to another process:

```ts
import { exchangeFederatedToken, hasErrorCode, isStorytellerError } from '@42for.net/2splatform.sdk'

try {
  const { accessToken, expiresAt } = await exchangeFederatedToken({ baseUrl, organization: 'acme', project: 'billing', machineId, subjectToken })
} catch (error) {
  if (hasErrorCode(error, 'invalid_request')) {
    // a malformed request, or a subject token that matches no rule of the machine (the reason is only logged by the API)
  } else if (isStorytellerError(error) && error.status === 503) {
    // temporarily_unavailable: try again in a few seconds with the same platform token
  }
}
```

Both helpers post the form with plain `fetch` (or the `fetch` option), without `Authorization` and without following redirects. The generated `exchangeMachineToken` posts the same form, but through the configured fetcher: it adds `Authorization` whenever `getAccessToken` returns a token, which the endpoint refuses with `invalid_request`, and as `getAccessToken` it would call itself. The trusted issuers and rules are managed with the generated `getFederatedIssuers`, `getFederatedIssuer`, `setFederatedIssuer`, `deleteFederatedIssuer` and `setMachineFederationRules` (and their composables, Zod schemas and MSW handlers), with a user token.

## User token exchange

The generated `exchangeUserToken` posts the RFC 8693 exchange of an actor, such as the MCP server, to `POST /v1/access/token`: the person's token for the actor (`subject_token`), the actor's id (`client_id`) and its proof (`actor_token`, `client_assertion`, or `client_secret` in Development) give a short-lived Storyteller user token that names the person and the actor, with the actor's `restrictions`. Like `exchangeMachineToken`, it goes through the configured fetcher, which adds `Authorization` whenever `getAccessToken` returns a token, and the endpoint refuses that with `invalid_request`. Call it only while `getAccessToken` returns nothing, with `{ redirect: 'error' }` as its options (the subject token is in the body), or post the form with plain `fetch`. `getAuthorizationServerMetadata` (RFC 8414) and `getJsonWebKeySet` read the issuer's metadata and signing keys anonymously.
