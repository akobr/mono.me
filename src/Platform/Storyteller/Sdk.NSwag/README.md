# How to generate

This SDK is generated by [NSwag](https://devblogs.microsoft.com/ise/maintain-api-client-with-nswag-model-gen/).

## Guide

- https://github.com/RicoSuter/NSwag
- https://github.com/RicoSuter/NSwag/wiki/CommandLine

### Install

```powershell
dotnet tool install --global NSwag.ConsoleCore --version 14.6.3
```

Use the version that generated `src/ApiSdk.g.cs` (its header names it); another version rewrites the whole file.

### Generate

```powershell
cd src/Platform/Storyteller/Sdk.NSwag/
nswag openapi2csclient /input:open.api.v0.10.0.json /className:"{controller}ApiClient" /output:src/ApiSdk.g.cs /namespace:_42.Platform.Storyteller.Sdk /OperationGenerationMode:MultipleClientsFromFirstTagAndOperationId /GenerateClientInterfaces:true
```

The OpenAPI document comes from the API test `OpenApiExportTests`: it renders the document with the same engine the Functions host uses, so no running host is needed.

```powershell
$env:STORYTELLER_OPENAPI_EXPORT = "$PWD/open.api.v<version>.json"
dotnet test ../Api.Functions/test --filter "FullyQualifiedName~OpenApiExportTests"
```

Copy the same file into `../sdk.typescript/` and regenerate the TypeScript SDK (`npm run generate`), then add the new `{controller}ApiClient` to `src/ApiSdk.partial.cs` and `src/ServicesCollectionExtensions.cs`.

`src/ApiSdk.Conditional.cs` is hand-written: it copies the route, the hooks and the exceptions of `GetConfigurationAsync` and `GetResolvedConfigurationAsync`. After a regeneration, compare it with the two generated methods, and keep the members it uses: `ConvertToString`, `ReadObjectResponseAsync`, `ReadAsStringAsync`, the `PrepareRequest` and `ProcessResponse` hooks, and the messages of the exceptions.

## Conditional reads

`IConfigurationsApiClient` has a conditional twin of each configuration read:

```csharp
var response = await configurations.GetResolvedConfigurationConditionalAsync("acme", "billing", "default", "sbt.northwind", etag);

if (!response.IsNotModified)
{
    document = response.Result;   // the Configuration of a 200
}

etag = response.ETag;             // W/"r.…", sent back as it is
```

* `ifNoneMatch` is sent unchanged as `If-None-Match`; `null` or an empty string sends none.
* A `304` returns with `IsNotModified` and no `Result`; it does not throw. Every other status throws what `GetConfigurationAsync` and `GetResolvedConfigurationAsync` throw for it, with the same messages: `ApiException<ErrorResponse>` for a `400`, `403`, `404` with a body, `422` (resolved only) or `500`, and a plain `ApiException` for a `401`, a `404` without a body (a missing configuration) and anything else.
* `ConditionalResponse<T>` keeps the headers of a `200` and a `304`: `ETag` (raw, weak prefix included), `CacheControl` (raw), `IsNoStore`, `SecretsWithheld` (`X-2S-Secrets-Withheld`: `mtls-required` for a machine with `Secrets.Read` but no certificate), and all `Headers`, with case-insensitive names. `Cache-Control` and `X-2S-Secrets-Withheld` depend on the caller's rights, not on the document: a caller that may read secrets gets `no-store` on every resolved read.
* Date-like strings of `Content` stay strings, as in the other reads of the client.
* The client keeps no state of a read; one instance serves concurrent calls.

The generated `GetConfigurationAsync`, `GetResolvedConfigurationAsync` and `GetConfigurationCompositionAsync` take `if_None_Match` after `key`, since the document declares the header (pass `null` for none), but they still throw an `ApiException` with status `304` when they get one, and they return the body without the response headers. That is why the twins are hand-written: NSwag throws on every documented status that is not a success and has no body, and `/WrapResponses` would expose the headers of a `200` but not turn a `304` into a result.

## Credentials

`ISdkConfiguration` carries what every request needs:

* `AccessTokenFactory` is called before each request. A value that starts with `ApiKey ` is sent as `Authorization: ApiKey <key>`; any other value as `Authorization: Bearer <token>`; an empty value sends no header.
* `ClientCertificate` is added to the `HttpClientHandler` of every client for mutual TLS. It needs a private key, and it must be set before the first client is resolved, because the handler is built then.
* `ClientCertificateHeaderName` is for development only. When it is set together with `ClientCertificate`, every request also carries the certificate (base64 DER) in that header, for a host without TLS. `sform` sets `X-ARR-ClientCert` for an `http` API on `localhost`, which the local Functions host accepts with `MachineAuth:IsCertificateHeaderFromClientAllowed`.

`AddStorytellerSdk(configurationFactory, configureHttpClient)` calls `configureHttpClient` with the `IHttpClientBuilder` of each of the seven typed clients, after their primary handler (the one that carries `ClientCertificate`) is set, for example to add a `DelegatingHandler`. `sform` adds one that sends a request once more after a `401`, with a new token of a machine whose credential can renew it (client credentials or federation):

```csharp
services.AddStorytellerSdk(null, builder => builder.AddHttpMessageHandler(
    provider => new MachineTokenRenewalHandler(provider.GetRequiredService<IMachineSignIn>())));
```

A `DelegatingHandler` wraps the primary handler, which follows redirects: a handler that sends a request again has to check that `RequestUri` and `Authorization` are still the ones it sent, as a redirect changes both on the same message. The overload with one parameter adds no handler.

### Machine credentials

`StorytellerCredential` (namespace `_42.Platform.Storyteller.Sdk.Credentials`) signs a machine in without `sform`:

| Factory | Sends |
|---|---|
| `FromApiKey(apiKey)` | `Authorization: ApiKey <key>`; a leading `ApiKey ` and whitespace are removed. `.WithClientCertificate(certificate)` adds the machine's certificate, the only combination with a certificate. |
| `FromCertificate(certificate)` | no `Authorization`; the certificate only. `StorytellerClientCertificate.Load(path, password)` loads a `.pfx` and refuses one without a private key. |
| `FromClientCredentials(new ClientCredentialsOptions { … })` | `Bearer` from a `client_credentials` token request. Without `TokenUrl`, only an AuthKit client id (`client_…`) works: it reads the AuthKit domain from the endpoint's `v1/auth/configuration` and posts to `{domain}/oauth2/token`. |
| `FromTokenFile(path)` | `Bearer` with the content of the file, read again before every request. It cannot renew, so a `401` is not retried: the rotated file is read by the next request. |
| `FromFederatedTokenFile(new FederatedTokenOptions { … })` | `Bearer` from an RFC 8693 exchange at `{endpoint}/v1/{organization}/{project}/access/token`, with the platform token of the file, read again before every exchange. |
| `FromEnvironment()` | the credential of the `STORYTELLER_*` variables below, or `null` when they describe none. A federated machine of a GitHub Actions job gets its platform token from the runner, see [GitHub Actions](#github-actions). |

* **Token cache.** Client credentials and federation keep their token in memory. Concurrent callers share one token request, and its failure. The token is renewed 60 seconds before it expires, or halfway through a token that lives less than two minutes: `expires_in` capped at a day, else the JWT `exp`, else five minutes. A renewal that fails before the token expires keeps the token until then.
* **Renewal.** `GetAuthorizationAsync(rejected, cancellationToken)` takes the value the API refused. The cached token is dropped only when it is that value, so a burst of `401`s makes one token request.
* **Token requests** use their own `HttpClient`: no redirects, no `Authorization` header, and the [resilience pipeline](#resilience) with retries of the `POST`. The one exception is the ID token request to the GitHub Actions runner, which carries the runner's request token, on that request only. `ConfigureHandler` of the options (or of the binding) configures its `SocketsHttpHandler`, for a proxy; redirects stay off.
* **Binding.** `credential.Bind(new StorytellerCredentialBinding(endpoint) { Organization = …, Project = … })` returns a copy that knows its endpoint and target project. Federation needs both; AuthKit discovery needs the endpoint. A value set in the options wins over the binding. An unbound credential falls back to `STORYTELLER_ENDPOINT` (or the deprecated `STORYTELLER_API_URL`) and to the organization and project of `STORYTELLER_KEY` (`@{organization}.{project}.…`). Bind once and reuse the result, as a singleton: every copy of a client-credentials or federated credential has its own token cache and its own connection pool for token requests, so a `Bind` per request or per scope makes a token request each time. `StorytellerCredential` is `IDisposable`: disposing a copy closes the connections of its token requests (not the client certificate, which stays yours), so an application that binds one copy per tenant disposes the copies it no longer uses.
* **URLs** must be `https`, or `http` to `localhost` or a loopback address literal (`127.0.0.1`, `[::1]`), and carry no user info. An endpoint, which paths are appended to, has no query or fragment either.
* **Failures** throw `StorytellerAuthenticationException` with a `Reason`: `Configuration` (variables, files, a missing binding, a URL), `Rejected` (a redirect or a `4xx` other than `408` and `429` from a token, discovery or GitHub Actions request, an answer without a token, or a platform that does not sign in with AuthKit) or `Unavailable` (a network error, a timeout, an open circuit, or `408`, `429` or `5xx`; all but `501` and `505` after retries). Messages include the `error` and `error_description` of an OAuth answer; neither they nor `ToString()` contain a secret.

#### Variables

`FromEnvironment` reads the names of the shared integration contract. The older `sform` names are deprecated, but still read when the canonical name is unset; a canonical name and its deprecated name set to different values are an error that names both. Values are trimmed; an empty value is unset. Messages name the variables as they were set, and never print a secret: they print file paths, and URLs without user info, query or fragment.

| Canonical | Deprecated | Meaning |
|---|---|---|
| `STORYTELLER_ENDPOINT` | `STORYTELLER_API_URL` | The API base, `/api` included; read only by an unbound credential |
| `STORYTELLER_KEY` | – | The full key `@{organization}.{project}.{view}.{annotation key}`; an unbound federated credential takes its organization and project |
| `STORYTELLER_API_KEY` | – | The structured API key; a leading `ApiKey` scheme is removed |
| `STORYTELLER_CLIENT_CERTIFICATE` | `STORYTELLER_CERTIFICATE_FILE` | The machine's PKCS#12 file (`.pfx`) |
| `STORYTELLER_CLIENT_CERTIFICATE_PASSWORD` | `STORYTELLER_CERTIFICATE_PASSWORD` | Its password |
| `STORYTELLER_CLIENT_ID` | – | The client id of client credentials, or the federated machine id |
| `STORYTELLER_CLIENT_SECRET`, `STORYTELLER_TOKEN_URL`, `STORYTELLER_TOKEN_SCOPE` | – | Client credentials; the scope also for federation |
| `STORYTELLER_TOKEN_FILE` | `STORYTELLER_SUBJECT_TOKEN_FILE`, federation only | With `STORYTELLER_CLIENT_ID` and no client-credentials variable: the platform token a federated machine exchanges. Alone: a bearer token the API accepts |
| `STORYTELLER_SUBJECT_TOKEN_TYPE` | – | `jwt` (the default), `id_token`, `access_token` or the full URN, in any case |
| `ACTIONS_ID_TOKEN_REQUEST_URL`, `ACTIONS_ID_TOKEN_REQUEST_TOKEN` | – | Set by GitHub Actions in a job with `id-token: write`: the platform token source of a federated machine without a token file |

| Kind | Variables |
|---|---|
| API key | `STORYTELLER_API_KEY` |
| Certificate | `STORYTELLER_CLIENT_CERTIFICATE` and, when the file has one, its password; alone or with an API key |
| Client credentials | `STORYTELLER_CLIENT_ID`, `STORYTELLER_CLIENT_SECRET`, `STORYTELLER_TOKEN_URL` (recommended; `sform account machine create` prints it), `STORYTELLER_TOKEN_SCOPE` |
| Federation | `STORYTELLER_CLIENT_ID` (the machine id) with `STORYTELLER_TOKEN_FILE` and no client-credentials variable, or in a GitHub Actions job; optional `STORYTELLER_SUBJECT_TOKEN_TYPE` and `STORYTELLER_TOKEN_SCOPE` |
| Token file | `STORYTELLER_TOKEN_FILE` without `STORYTELLER_CLIENT_ID` |

* **One kind.** Variables of two kinds at once are an error that names them.
* **`STORYTELLER_SUBJECT_TOKEN_FILE` is no plain alias.** Set, it always makes a federated machine, never a bearer token file, so it needs `STORYTELLER_CLIENT_ID`; with `STORYTELLER_TOKEN_FILE` and no client id it is two kinds. With a client id, it and `STORYTELLER_TOKEN_FILE` must agree.
* **`STORYTELLER_TOKEN_FILE` with `STORYTELLER_SUBJECT_TOKEN_TYPE`** and no client id is two kinds.
* **`STORYTELLER_CLIENT_ID` alone**, or with `STORYTELLER_TOKEN_SCOPE`, federates through GitHub Actions when the id is a GUID and both GitHub variables are set; otherwise it is an error that names both ways (a client secret, or a token file or a GitHub Actions job). `STORYTELLER_TOKEN_SCOPE` without a client id is an error.
* **`STORYTELLER_SUBJECT_TOKEN_TYPE` without a file** needs `STORYTELLER_CLIENT_ID` (any id), then takes the platform token from GitHub Actions when both GitHub variables are set; otherwise it is an error that names `STORYTELLER_TOKEN_FILE` and GitHub Actions.
* **The GitHub variables alone** describe no credential: `FromEnvironment` returns `null` in a job with `id-token: write` that sets no `STORYTELLER_*` credential variable.
* **Client credentials** need `STORYTELLER_CLIENT_ID` and `STORYTELLER_CLIENT_SECRET`. Without `STORYTELLER_TOKEN_URL`, only an AuthKit client id (`client_…`) works, through discovery. **A certificate password** without a file is an error.

#### GitHub Actions

A federated machine in a GitHub Actions job with `permissions: id-token: write` needs no token file: the credential asks the runner for a new ID token before every exchange.

* **The request.** `GET {ACTIONS_ID_TOKEN_REQUEST_URL}&audience={audience, escaped}` (`?audience=` when the URL has no query), with `Authorization: Bearer {ACTIONS_ID_TOKEN_REQUEST_TOKEN}` on that request only, on the client of the token requests: no redirects and the same resilience. The token is the `value` of the answer. `ACTIONS_ID_TOKEN_REQUEST_URL` follows the URL rule; it may have a query.
* **The audience** is the token endpoint built from the endpoint as written, without its trailing `/`, plus `/v1/{organization}/{project}/access/token` with escaped segments: byte for byte what `sform` requests and what `sform account machine create` prints, which is what a federation rule's audience must name. The exchange itself posts to the normalised URI.
* **Failures.** A network error, a timeout, `408`, `429` and `5xx` of the runner are `Unavailable` (after retries); a redirect, another `4xx`, or an answer without a token are `Rejected`. Messages name the runner's URL without its query, never the request token.
* **A refused exchange.** When the exchange of a GitHub token is `Rejected`, its message ends with "; the GitHub Actions token of this job was requested for the audience {audience}, which a rule of the machine must name exactly. For client credentials, set STORYTELLER_CLIENT_SECRET instead."
* `ToString()` is `StorytellerCredential { Kind = Federated, ClientId = {id}, SubjectTokenSource = GitHubActions }`.

#### The shared contract

The rules above are public, so that `sform` and other tools read the same variables in the same way:

* `StorytellerVariables`: the names as constants, `Credentials` (every name that makes a credential, deprecated ones included; not the endpoint, the key or the GitHub names) and `Deprecated` (a deprecated name and its canonical name).
* `StorytellerVariableReader`: trimmed values, an empty value as unset, `ReadWithFallback` with the conflict error, and `SetNames`.
* `StorytellerUrlRule`: `IsAllowed`, `IsLocalHttp`, `Require`, `RequireEndpoint` and `Describe` (a URL without user info, query or fragment, for messages).
* `StorytellerCredentialVariables.Read(getVariable)`: `null` when no credential variable is set, otherwise the checked variables with their `Kind` (`StorytellerCredentialKind`), `SubjectTokenSource` (`StorytellerSubjectTokenSource`, federated only), `Names`, `DeprecatedNames`, `ApiKeyMachine` (the machine segment of a structured key, without the secret), `ClientId` and `TokenFile`. The secrets are not exposed, the API key included, and `ToString()` prints only the kind and the names. `CreateCredential(fileSystem, timeProvider)` builds the unbound credential and loads the certificate; `FromEnvironment` is `Read(getVariable)?.CreateCredential(fileSystem, timeProvider)`.

#### The credential handler

`IHttpClientBuilder.AddStorytellerCredential(credential)` adds a `StorytellerCredentialHandler`. It sets `Authorization` on every request. After a `401` it asks the credential once more and sends the request again, when the credential `CanRenew`, the body is empty or a `ByteArrayContent`, and no redirect changed the request. On that path:

* leave `AccessTokenFactory` null, otherwise `PrepareRequest` sets `Authorization` too;
* the certificate still goes to `SdkConfiguration.ClientCertificate`, which puts it on the primary handler.

```csharp
var credential = StorytellerCredential.FromEnvironment()!
    .Bind(new StorytellerCredentialBinding(new Uri(apiUrl)) { Organization = "acme", Project = "billing" });

services.AddStorytellerSdk(
    () => new SdkConfiguration { BaseUrl = apiUrl, ClientCertificate = credential.ClientCertificate },
    builder => builder.AddStorytellerCredential(credential).AddStorytellerResilience());
```

## Resilience

`IHttpClientBuilder.AddStorytellerResilience(configure)` (namespace `_42.Platform.Storyteller.Sdk.Resilience`) adds a `ResilienceHandler` with retries, a circuit breaker and an attempt timeout. It is opt-in: `AddStorytellerSdk` adds none. `StorytellerResilience.CreatePipeline(options)` builds the same pipeline for a hand-built `HttpClient`; the pipeline keeps the state of its breaker, so use one per client. `options.Clone()` copies the options, for a client that must not see later changes.

| `StorytellerResilienceOptions` | Default |
|---|---|
| `MaxRetryAttempts` | 3; `0` adds no retry, a negative value throws `ArgumentOutOfRangeException` |
| `BaseDelay` | 500 ms, exponential backoff with jitter |
| `AttemptTimeout` | 5 s; zero or `Timeout.InfiniteTimeSpan` adds none, another negative value throws `ArgumentOutOfRangeException` |
| `RetryUnsafeMethods` | `false`: `GET` is retried; `POST`, `PUT`, `PATCH` and `DELETE` are not |
| `FailureRatio`, `MinimumThroughput`, `SamplingDuration`, `BreakDuration` | 0.5, 3, 60 s, 30 s |

The circuit breaker sits outside the retries, so it counts calls, not attempts: the retries of one failing call do not open it, three failing calls in a minute do. While it is open, calls throw `BrokenCircuitException` without reaching the server. `408`, `429`, `5xx` except `501` and `505`, network errors and attempt timeouts are retried and counted; `501` and `505` are definitive. `Retry-After` is always honoured. An application that gets `AddStandardResilienceHandler` from Aspire's service defaults (`ConfigureHttpClientDefaults`) should not add this one as well: the two pipelines would retry each other's retries.

## Workload identity federation

`AccessApiClient` manages trusted issuers and federation rules (`GetFederatedIssuersAsync`, `GetFederatedIssuerAsync`, `SetFederatedIssuerAsync`, `DeleteFederatedIssuerAsync`, `SetMachineFederationRulesAsync`) with a user token. The claim pins (`FederatedIssuer.RequiredClaims`, `FederationRule.Claims`) are dictionaries of `IReadOnlyList_String`, a `Collection<string>`: `Claims = new Dictionary<string, IReadOnlyList_String> { ["repository_id"] = new() { "74" } }`.

`ExchangeMachineTokenAsync` posts the RFC 8693 token exchange as `application/x-www-form-urlencoded` and throws `ApiException<OAuthErrorResponse>` for `400` and `503`. The endpoint refuses any `Authorization` header, and the clients of `AddStorytellerSdk` add one whenever `AccessTokenFactory` returns a token, so call it through a client without `ISdkConfiguration`, on an `HttpClient` that does not follow redirects (the subject token is in the body):

```csharp
using var http = new HttpClient(new HttpClientHandler { AllowAutoRedirect = false });
var access = new AccessApiClient(http) { BaseUrl = "https://api.2s.42for.net/api" };

var token = await access.ExchangeMachineTokenAsync("acme", "billing", new MachineTokenRequest
{
    Grant_type = "urn:ietf:params:oauth:grant-type:token-exchange",
    Client_id = machineId,
    Subject_token_type = "urn:ietf:params:oauth:token-type:jwt",
    Subject_token = platformToken,
});
// token.Access_token for Authorization: Bearer, valid for token.Expires_in seconds
```

`StorytellerCredential.FromFederatedTokenFile` (see [Machine credentials](#machine-credentials)) makes the exchange and caches its token, like `createFederatedTokenProvider` of the TypeScript SDK.

## User token exchange

`ExchangeUserTokenAsync` posts the RFC 8693 exchange of an actor, such as the MCP server, to `POST v1/access/token`: the person's token for the actor (`Subject_token`), the actor's id (`Client_id`) and its proof (`Actor_token`, `Client_assertion`, or `Client_secret` in Development) give a short-lived Storyteller user token that names the person and the actor, with the actor's `Restrictions`. Like `ExchangeMachineTokenAsync`, it throws `ApiException<OAuthErrorResponse>` for `400` and `503`, and the endpoint refuses any `Authorization` header: call it through a client without `ISdkConfiguration`, on an `HttpClient` that does not follow redirects, never through the clients of `AddStorytellerSdk`. `GetAuthorizationServerMetadataAsync` (RFC 8414) and `GetJsonWebKeySetAsync` read the issuer's metadata and signing keys anonymously.

## Client-side encryption

`src/ClientSideEncryption/KeyValueClientEncryption.cs` encrypts a key/value secret for the recipients of a project (`GET …/key-values/recipients`) and decrypts a returned document with a recipient's private key, on top of the `KeyValues.ClientEncryption` library (JWE General JSON Serialization, A256GCM, RSA-OAEP-256). The TypeScript SDK (`./hyok`) and the CLI produce and read the same format.

```csharp
var recipients = await keyValues.GetRecipientsAsync("acme", "billing");
var write = KeyValueClientEncryption.CreateWrite("s3cret", recipients, "acme", "billing", "default", "db.password");
await keyValues.SetKeyValueAsync("acme", "billing", "default", "db.password", write);

var revealed = await keyValues.GetKeyValueAsync("acme", "billing", "default", "db.password", reveal: true, includeDeleted: null);
var plain = KeyValueClientEncryption.Decrypt(revealed.Value, "api", privateKey);
```
