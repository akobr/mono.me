# CLI automation tests

Tests of the real `sform` CLI (the build of `src/Platform/Cli/src`, started out of process) against a real Storyteller deployment: pool users signed in through the AuthKit device code (approved by Playwright on the AuthKit page) and machines signed in from the `STORYTELLER_*` variables, under **TUnit**, on the reusable libraries `42.Testing.UI.Automation.*` (`src/Libraries/Testing/UI.Automation.*`) as tests without a browser, and the shared Platform pieces of [`42.Platform.Automation.Shared`](../Automation.Shared/README.md).

**Documentation:** [CLI Automation Tests](../../../docs/Platform/Cli.AutomationTests/automation-tests.md) (running, settings and profiles, users and machines, the sign-in, running sform, the target check, writing a test, the fake editor, the self tests, the command coverage and the catalogue check, Testiny, troubleshooting) and, for every setting of the framework, [UI Automation](../../../docs/Libraries/Testing/UI.Automation/readme.md). Spec: [CLI Automation Testing Project](../../../docs/Platform/Cli.AutomationTests/specs/2026-11-08%20CLI%20Automation%20Testing%20Project.md). Every case and its test: [test-cases.md](../../../docs/Platform/Cli.AutomationTests/test-cases.md).

```bash
dotnet build src/Platform/Cli.AutomationTests/src                                                           # builds sform too
pwsh src/Platform/Cli.AutomationTests/src/bin/Debug/net10.0/playwright.ps1 install chromium                 # once: the device page's browser

dotnet test --project src/Platform/Cli.AutomationTests/src                                                  # without Target:BaseUrl: self tests and coverage checks run, CLI tests skipped
UITESTS_PROFILE=dev dotnet run --project src/Platform/Cli.AutomationTests/src                               # against the local API (:7071)
dotnet run --project src/Platform/Cli.AutomationTests/src -- --treenode-filter "/**[Category=Elementary]"   # the PR gate set
dotnet run --project src/Platform/Cli.AutomationTests/src -- --treenode-filter "/**[Category=Coverage]"     # command coverage and catalogue check (no target)
```

Run it with `dotnet run` (options after `--`) or `dotnet test --project src/Platform/Cli.AutomationTests/src` (options without `--`); `dotnet test --solution 42.mono.slnx` runs it with the rest of the repository's tests on Microsoft.Testing.Platform. Without `Target:BaseUrl` (the committed default) every CLI test is skipped, while the self tests (category `SelfTest`) and the coverage checks (category `Coverage`) run and pass. Each of the 257 cases of the catalogue has its test, so `EveryCommandOptionArgumentAndValue_IsCovered` (every item of sform covered by a `[Covers]`) and `EveryCase_IsAutomated` (every row of the catalogue with its test) pass; they fail only for a new command, option or value of sform, or a new row, without its test: see [Automating a case](../../../docs/Platform/Cli.AutomationTests/automation-tests.md#automating-a-case). CI: [`.github/workflows/Platform.Cli.AutomationTests.yml`](../../../.github/workflows/Platform.Cli.AutomationTests.yml), by hand or called, against the target of the `cli-automation` environment ([CI](../../../docs/Platform/Cli.AutomationTests/automation-tests.md#ci)).

| Path | Contents |
|---|---|
| `src/CliAutomationSetup.cs` | The setup (`[assembly: UiAutomationSetup<…>]` and the other assembly attributes): no runtime sign-in flow (`Target:SignIn None`), the Testiny reporter, the settings' checks, the target check without a page |
| `src/CliTargetCheck.cs` | The check of the target before the first test, through sform: it starts, a pool user who stands for no feature signs in, the project is readable, each configured machine reads |
| `src/CliTarget.cs`, `src/CliSettings.cs`, `src/KeyValueSettings.cs`, `src/CliFeatures.cs`, `src/testsettings*.json` | The CLI's `Target` keys (over the shared `PlatformTargetSettings`), the `Cli` section, the `KeyValues` section (the customer key of the BYOK cases), the feature names (and the features that are pool users), the committed defaults and the profiles (`dev`, `ci`, `reporting-testiny`) |
| `src/CliTest*.cs` | The tests' base class: running sform (`Sform`, `StartSform`, `StartSformInTerminal`, `InProject`, `EventuallyAsync`), the roles, the feature users and the skips (`CliTest.Roles.cs`: `AsRoleUserAsync`, `RoleProjectOf`, `FeatureUser`), the sign-in and other users (`CliTest.SignIn.cs`: `AsAnotherUserAsync`, `ArrangeAsAsync`), machines (`CliTest.Machines.cs`: `CreateMachineAsync`, `RunCreatingMachineAsync`, `DeleteMachineAtCleanup`), a disposable project (`CliTest.Projects.cs`) |
| `src/Running/` | `SformRunner`, `SformRunOptions`, `SformResult`, `SformProcess`, `CliExit`, the environment built from scratch, the locator of the built sform, escape sequences, JSON (`WrappedJson`: the 80-column folds of an older sform's WriteJson joined, a safety net), the versions tables (`SformResult.VersionRows`), the secrets sform prints; `Processes/` (redirected with the console encodings and the process job, Windows ConPTY, Linux `script`), `Terminal/` (the keys) |
| `src/Access/` | The homes (`SFORM_HOME`) and working directories (outside the artifacts), the device code sign-in and the AuthKit device page, the machines (`Machines` settings, `MachineCredentials`, `MachineCreation`, `CreatedMachine`), another pool user (`SformActor`, `AccountOutput`) |
| `src/Attributes/` | `[Area]`, `[MachineOnly]`, `[FreshSignIn]`, `[Terminal]`, `[DisposableProject]`, `[RequiresFeature]`, `[RequiresMachine]`, `[Covers]`; `Role` and `[UserRole]` come from the shared library (imported globally) |
| `src/Data/` | `CliData`, the seeded names (`rst.cli-<runId>-…`, `cli_<runId>.…`) |
| `src/Editing/` | Mode E: `FakeEditor` (the fake editor as the custom command of the `editor` section of `sform.settings.json`, its variables for a run), `EditorChange` (`Replace`, `Merge`, `None`, `Invalid`, `Exit`, `Sequence`), `EditorLog` and `EditorInvocation` (what sform gave the editor) |
| `src/Coverage/` | `CommandCoverageTests` (every command, alias, option form, argument and fixed value of sform covered by a `[Covers]`; the command tree read from `42.Platform.Cli.dll` with `MetadataLoadContext`) and `CatalogueTests` (every row of the catalogue against its test, the `[Covers]` by `CatalogueCovers`), category `Coverage`, no target |
| `src/coverage-values.json`, `src/coverage-exceptions.json` | The options with a fixed set of values (and where the CLI keeps each set), and the items only feature-gated tests cover |
| `src/SelfTests/` | Plain TUnit tests of the machinery that need no target (category `SelfTest`): the fake editor's, mode E through sform against a stub of the API, the coverage and catalogue rules on a hand-built command tree, and the settings' and the feature users' rules among them |
| `src/Tests/<Section>/` | The tests of the 257 cases: one folder per section of the catalogue, one class per sub-folder, and the section's helpers (`Tests/Machines/MachineAccessTest`, the base class of the Machines and Shared Certificates classes; `SignInOutput`, `ConfigOutput`, `SchemaChecks`, `KeyValuesSupportA`/`B`, …) |
| `editor/` | The fake editor (`42.Platform.Cli.AutomationTests.Editor`), a console app built with the tests: replaces, merges (RFC 7396), leaves, breaks the file sform gives it or exits with a code, per `CLI_EDITOR_*` variables, and logs each invocation |
